# Ante facts

What Nushi depends on, as seen when it was built against the versions named below. Read it before changing the code that talks to it.

## Agent facts (Ante 0.2.14, through the bridge)

What the bridge (`internal/ante`) depends on, seen with `ante serve --stdio`; the protocol is Ante's open `crates/protocol-shape/src/msg.rs` at v0.2.14.
- Ops go in as `{"op": …, "id": "op_<ULID>"}` (a bad id is an `Error`); events come out with `parent`, the op they answer. An input's op id is its turn's id. No greeting.
- `StartSession{cwd}` answers `SessionStart` (session id, cwd, permission mode, model with `effort` and maybe `supported_efforts`, provider); unset fields come from `~/.ante/settings.json` (the user's default model, Kimi K3 here). `ResumeSession` answers `SessionEnd` (of any running one), `SessionStart`, `ExtensionRefreshed`, then the saved event log, with no end marker: the bridge sends `ContextReport` right behind it and takes its answer as the end (the host answers ops in order). Permission mode always comes from the current settings on a resume; the model is the session's.
- Live, the host echoes every input as `UserInput` (steers too, which the docs say it doesn't); streams `MessageDelta`/`ThinkingDelta`, then repeats the whole text (dropped once deltas came; replays have only the whole texts). A turn can hold several `AgentMessage`s; the bridge names them `<turn id>.<n>`.
- An approval (`TurnPause.Approval`) comes before the call's `ToolStart`; a denied call ends with a `ToolEnd{Denied}` and no start. `AcceptAlways` would write an allow rule into `settings.json`, so the bridge never offers it. Questions are `TurnPause.Question` (AskUser), answered with `QuestionResponse`.
- `UpdateSession` (model, effort, permission mode) answers `SessionUpdated` and doesn't write `settings.json` (checked). `ForkSession{at: <input id>}` needs an idle session and saves the fork without starting it (`SessionForked`); the bridge resumes it on a host of its own.
- `ToolEnd.result_json` shapes: Bash `{"Completed":{exit_code, stdout, stderr}}` (status `Failed` when the code isn't 0), Read `{file_type:{Text:{lines}}}`, Edit `{patch, summary}`, Write `{lines_written, message}`, AskUser `{message}`, a denial a string.
- Sessions are `~/.ante/sessions/<id>/{meta.json, events.jsonl, dialog.json}` (`ANTE_HOME` moves `~/.ante`, logs included); there's no op to list or delete them, so the bridge reads `meta.json` and removes the folder. A resume rewrites `meta.json` with zero usage.
- A project's `.ante/settings.json` can't widen what Ante may do: mode, allow rules, MCP servers, system prompt, model and provider are ignored with an `Info` notice (checked).
- `ante catalog` prints every provider's models (no keys: a provider's key is named by `env_key`).

- Listing and two writers (milestone X): a headless or TUI session's `meta.json` has `message_count`, `model`, `provider` and `first_user_message`, which Ante's front end ends with a `<folder-structure>` listing of the folder (the bridge drops it in titles and replays). Ante takes no lock: its TUI keeps `events.jsonl` open for writing while it has the session (lsof finds it in about 0.07 s). With the TUI and Nushi on one session both appended to `events.jsonl`, and a later `ante -r` knew only Nushi's turn: the resume reads `dialog.json`, which the last to save rewrites.

**Skills (Ante 0.2.14, step 303; run: `ante serve --stdio` with a throwaway `HOME` and `ANTE_HOME`, `StartSession` only, no key and no model call; the paths also in its bundled `ante-guide` skill)**
- Where: yours in `$ANTE_HOME/skills` (`~/.ante/skills`), `~/.agents/skills` and `~/.claude/skills` (all listed as scope `user`; on a name, `.ante` wins over `.agents` over `.claude`); the project's in `.ante/skills`, `.agents/skills` and `.claude/skills` **of the session's cwd only**: no walk-up (a repository subfolder's session didn't get the repository top's, nor the folder above it); the same order on a name, and a project skill wins over yours. Bundled ones (scope `system`: `add-provider`, `resume-claude`, `resume-codex`) sit in `$ANTE_HOME/.system/skills`, rewritten on each version change. No trust: a folder's skills load at once.
- Format: `<root>/<folder>/SKILL.md`, one level (a nested `deep/inner/SKILL.md` wasn't read; a `.hidden` folder neither). The name is the front matter's `name` (folder `folder-x` with `name: fm-name` listed as `fm-name`); without front matter the description is the body's text, lines joined.
- Links: followed everywhere: a skill folder that is a link (outside the folder too), a `SKILL.md` that is a link, and linked roots (`.agents` → elsewhere, `.claude/skills` → elsewhere, `.ante/skills` → elsewhere all loaded).
- Off: settings keys `skills` (bool, all of them, bundled included; default on), `exclude_skills` and `include_skills` (names, exact; exclude wins), and the flags `--skills`, `--no-skills`, `--include-skills`, `--exclude-skills`. Read from `$ANTE_HOME/settings.json` and the nearest `.ante/settings.json` (a project's may set them: its `exclude_skills` added to yours, both left out; its `skills: true` turned on what yours had `false`). An excluded skill is simply absent from the list.
- Listing: `SessionStart` and `ExtensionRefreshed` carry `skills: [{name, description, scope: system|user|project, argument_hint}]` (no path), `subagents` and (the latter) `mcp_servers`. Excluded skills aren't in it, so a manager has to read the folders to show them off. Starting a session reads the folder's `.ante/settings.json` and `AGENTS.md`, so it's a run in that folder.

**Slash commands (Ante 0.2.14, step 373; run: `ante serve --stdio` with a throwaway `HOME` and `ANTE_HOME`, a custom catalog provider pointing at a local fake OpenAI-compatible server that logged each request, no key)**
- The protocol has no op listing the TUI's commands. The skills `SessionStart` and `ExtensionRefreshed` list are the user-invocable ones (`user-invocable: false`, e.g. the bundled `ante-guide`, `skill-creator`, `tmux`, aren't in it); `argument_hint` and `description` can be `null`. `SessionUpdated` repeats them; they're fixed for the session.
- `UserInput("/greet Bob")` runs no skill: the model gets the text as typed (the skills are only listed to it).
- `SlashCommand{name, args}` runs a skill: a turn whose id is the op's (`TurnStart`… `TurnEnd`), **no `UserInput` echo and none saved**, the model getting `<skill>\n<name>greet</name>\n<path>…/SKILL.md</path>\n\n<body, $ARGUMENTS replaced>\n</skill>` as the user's message. A name that isn't a skill (`compact`, `model`, `nosuch` all tried) falls back to `UserInput("/name args")`: echoed and sent to the model. So a replay shows a skill's turn without the user's message, and `meta.json`'s `first_user_message` is the `<skill>` block (the bridge's list titles it `/name`).
- `Compact{instructions?}` (no turn): `InfoBlockStart{id: "compact-<op id>"}`, then `CompactStart`, `CompactEnd{summary}` (`null` when it failed), a `UsageUpdate` with the smaller context, and `InfoBlockAppend{id, detail}` last ("Compaction complete · …", "Compaction failed: …"); with nothing to compact only the two info block events ("Context is already within budget; nothing to compact."). All of them are saved, so a resume replays them.
- `UpdateSession{model: {id}}` takes any id, one the catalog doesn't list too (as the TUI's `/models <id>`), at the catalog's effort, and answers `SessionUpdated` with the whole info: a model without effort has none in it. An effort outside Ante's ladder (`min`…`max`) is an `Error` ("Invalid OpMsg JSON: unknown variant…") **with no parent**, so the bridge checks one before sending it.
- `ContextReport` answers are saved to `events.jsonl` too.
- The bridge's commands: the skills (run with `SlashCommand`), and its own `/model [id]`, `/effort [level]` (each through `UpdateSession`; with no argument it says the current value) and `/compact [what to keep]` (`Compact`, shown as a "Compact conversation" tool call holding the summary, as Ante's own compactions now are). An own command's name wins over a skill's.
