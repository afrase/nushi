# Jira facts

What Nushi depends on, as seen when it was built against the versions named below. Read it before changing the code that talks to it.

## Jira facts (Jira Cloud, October 2026; the test site)

- An API token is classic or scoped. Classic works on the site (`https://<name>.atlassian.net`) and through the gateway (`https://api.atlassian.com/ex/jira/<cloud id>`); a scoped one only through the gateway. `/_edge/tenant_info` (no auth) gives the cloud id. A refused token is `401` with `X-Seraph-LoginReason: AUTHENTICATED_FAILED` and a plain-text body; nothing in any answer says when a token expires.
- Rate limits: answers carry `RateLimit-Policy: "jira-burst-based";q=100;w=1` (150 for an issue's GET) and `X-RateLimit-Remaining`; API-token traffic isn't in the points pool. `429` and `503` carry `Retry-After`.
- `/rest/api/3/search/jql` (POST): `jql` must be bounded ("order by key desc" alone is 400 "Unbounded JQL queries are not allowed here"); `fields` defaults to the id only; `nextPageToken` and `isLast`; no total. An unknown field name searched nothing rather than failing.
- A team-managed Scrum project's board is `type: simple`; `/rest/agile/1.0/board/<id>/sprint?state=active` gives the sprint; `sprint = <id>` lists its issues.
- Transitions: `?expand=transitions.fields` gives each move's screen fields (`required`, `schema {type, items, custom}`, `allowedValues`); the test site's workflow (To Do, In Progress, In Review, Done) has none. A textarea custom field takes ADF.
- ADF as Jira makes it: wiki markup posted to `/rest/api/2` comes back in v3 as ADF (headings, marks including `subsup` and `textColor`, `hardBreak`, nested lists, `codeBlock` with `language`, `blockquote`, a titled `panel` as a panel with a bold first paragraph, tables, `mention` with `@Name`, `emoji` with unicode or Atlassian short names, `rule`, `mediaSingle`); `{info}` and the other wiki panels stayed text. ADF posted to v3 keeps editor nodes (`taskList`, `decisionList`, `expand`, `status`, `date`, `inlineCard`, `blockCard`, panel types). A `media` node names Atlassian's media file (a UUID), not the attachment; the rendered HTML's `<img>` has `data-media-services-id` and the attachment's `/attachment/thumbnail/<id>` side by side, which is how Nushi maps them.
- `internal/adf`, ADF to Markdown: paragraphs, headings, bullet and ordered lists (nested, a start number), task lists (`- [x]`), decision lists (`- ✔`), code blocks with a language, quotes, panels (a quote with **Info:** and the like), rules, tables (the first row as the header; cells on one line, lists as •), media (an attachment's image, else its name in brackets), expands (a bold title), cards (links), and inline: marks (strong, em, code, strike, link; underline, colour and sub/superscript as plain text), hard breaks, mentions, emoji (Atlassian's own as their emoji), status (code), dates (YYYY-MM-DD). Anything else: its content, its text, or its type in brackets. Text is escaped so it can't read as Markdown; links only to http, https and mailto; images only from media nodes; consecutive lists alternate markers so they stay apart.
- Finding an issue (the follow-up; from Atlassian's docs, tried only against a scripted fake, no token for the test site): `/search/jql` with `text ~ "word*"` matches word starts in the summary, description and comments; `key = ABC-1` for a key that doesn't exist is a 400 with Jira's words ("An issue with key … does not exist for field 'key'"); `issue in issueHistory() ORDER BY lastViewed DESC` is bounded and lists the issues the token's user looked at last. `/rest/api/3/issue/picker` gives key and summary (plain and HTML-marked) in "History Search" and "Current Search" sections, no status. Issue links: `/browse/KEY`; the new issue navigator and boards: `…/issues/KEY` and `?selectedIssue=KEY`.
- Markdown to ADF (goldmark, GitHub's tables, task lists, strikethrough, bare links): paragraphs, headings, lists, task lists (when every item has a box), code (fenced or indented), quotes (a quote in a quote joins it, a heading becomes bold: ADF allows neither in a quote), rules, tables, and inline marks, links and line breaks (each a `hardBreak`, as in a comment box); an image becomes its alt text linked, HTML its text. Jira accepted all of it (the live test posts and reads back a comment of each kind, unchanged).
- Latency (step 263): the test site answers an unauthenticated `serverInfo` in 220–430 ms (TLS included), so each call Nushi makes in series costs about that much more. `TestTiming` in `internal/jiracloud` stands in for a site (no token for the test site then): what Nushi asks for an issue (fields after the field list, comments, remote links) goes at once. `maxResults` above Jira's page cap is clamped, not refused, by Atlassian's account of the older search (100 with fields); the new `/search/jql` wasn't tried past 100.
- People (step 333, from the test site's recorded answers in `internal/jiracloud/testdata`): a user object has `accountId` (`712020:<uuid>` or 24 hex digits), `displayName` and `avatarUrls` (16, 24, 32, 48), and those URLs are `https://secure.gravatar.com/avatar/<hash>?d=<Atlassian's avatar-management host on atl-paas.net>/initials/XY-n.png`: never the site's own host, so Nushi draws initials rather than fetch them. An unassigned issue's `assignee` is `null` (or absent when not asked for). `/search/jql` with `fields: [summary, status, priority, assignee]` gives only those (lists ask for no more).
