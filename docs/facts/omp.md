# oh-my-pi facts

What Nushi depends on, as seen when it was built against the versions named below. Read it before changing the code that talks to it.

## Agent facts (oh-my-pi 18.12.6)

What the code depends on (`internal/omp*`), from driving `omp --mode acp` and its source.
- `initialize`: `agentInfo` `omp`, `loadSession`, `sessionCapabilities` list, fork, resume, close (no delete: `session/delete` fails "Unknown ACP ext method"), `promptCapabilities.image`, `_meta.steering.supported`; extensions `_omp/usage`, `_omp/extensions` and more.
- `session/new` returns legacy modes and config options `mode` (default, plan; not permissions), `model` (`<provider>/<id>`, the models of providers with a key: with `FIREWORKS_API_KEY`, 35 Fireworks ones; Kimi K3 by default) and `thinking` (category `thought_level`: off, auto, then the model's levels). A model picked stays with the session.
- Permissions: only bash, delete and move ask (Allow once, Always allow, Reject, Always reject); writes and edits never do. The request comes before the call's `tool_call`. A command's title starts with `$ ` (the dialect drops it).
- Questions: its ask tool exists only for a client with form elicitation; each question is `qN` with `oneOf`, then `qN__other`, "Other (type your own)". An empty answer ends the turn as cancelled.
- `usage_update` carries used, size and cost; the prompt result carries usage. A prompt during a turn cancels the turn; `_session/steering` injects ("injected").
- `session/load` replays user messages, tool calls and agent messages (fresh message ids each time); `session/fork` copies the whole session.
- Sessions are `~/.omp/agent/sessions/<folder name>/<time>_<id>.jsonl`; all of omp's state is under `~/.omp` (`PI_CODING_AGENT_DIR` moves only `agent/`), so a test points `HOME` at a temp folder.
- It runs only under Bun (≥ 1.3.14). Since milestone Z Nushi runs your `omp`, whose `#!/usr/bin/env bun` finds your Bun on PATH; with no `omp` it isn't offered, with no `bun` it says "Needs Bun".

- Listing (milestone X): `session/list` gives `{sessionId, cwd, title, updatedAt, _meta: {messageCount, size}}`, 50 a page (cursor an offset), the cwd matched either way (`/tmp` or `/private/tmp`); a `-p` run has an empty title. Session files start with a title record, then `{"type":"session", id, cwd, parentSession?}` (a fork names its parent). One process owns a session: a flock on `~/.omp/run/session-owners/<id>.lock`; another that writes to it saves to a new session instead, with `parentSession` ("Session … is open for writing in another omp process, so this session now saves to …").

**Skills (oh-my-pi 18.12.6, 2026-10-27; `omp skill list --json` and ACP `available_commands_update` in a throwaway `HOME`, Bun 1.4.4, and its source `src/discovery/*.ts`, `src/extensibility/skills.ts`)**
- Where (providers by priority; the first of a name keeps it): `.omp/skills` in the cwd and each folder above it, then `~/.omp/agent/skills` (`PI_CODING_AGENT_DIR` moves `agent/`; no description: not loaded); skillshare installs (`omp skill install`, `skills.lock.json`); `.claude/skills` from the cwd up (on by default, `skills.enableClaudeProject`), `~/.claude/skills` only with `skills.enableClaudeUser: true`; Claude plugins' and omp plugins'; **`.agents/skills` and `.agent/skills` from the cwd up**, then `~/.agents/skills` and `~/.agent/skills` (`skills.enableAgentsProject`/`enableAgentsUser`, both on); `.codex/skills` (the nearest `.codex`; `~/.codex/skills` only with `skills.enableCodexUser`); `.github/skills` in the cwd only. Every walk goes up to the repository's root (seen: not above it), outside git to your home folder (or `/`), and skips the home folder itself. No built-in skills.
- Collisions: a same-name skill with different text isn't dropped but renamed `<namespace>/<name>` with a warning (seen: `~/.agents/skills/dup` beside the repository's `dup` became `agents/dup`); an identical one is dropped.
- **No trust**: a project's skills (any of the folders above) load without asking (seen).
- Format: `<root>/<name>/SKILL.md`, one level only (`skills/group/x/SKILL.md` isn't found, seen); dot-folders skipped. Name: front matter `name`, else the folder's; `/` or `\` in it skips the skill. `.agents`, `.claude` and `.codex` skills need no description (a SKILL.md of plain text loads, seen); `.omp` and `.github` ones do. Front matter `enabled: false` hides it; `hide: true` or `disable-model-invocation: true` keeps it but out of the prompt's list. Symlinks followed: a linked root, skill folder and `SKILL.md` all load (seen); one real file reached twice loads once.
- **Off, by name, not by path**: `disabledExtensions: ["skill:<name>"]` or `skills.ignoredSkills: ["<glob>"]` (`skills.includeSkills` the opposite) in `~/.omp/agent/config.yml` (YAML) turns that name off for every source and folder (seen); the nearest `.omp/config.yml` between the cwd and the repository's root does it for the project (seen: the cwd's works; one in the repository's root doesn't once a nearer `.omp` exists). The project layer also merges `.omp/settings.json` and the cwd's `.claude/settings.json`. `skills.enabled: false` turns all off. A skill off is left out of the list.
- Listing: `omp skill list [dir] --json` resolves what a session in `dir` would (it can run elsewhere: run from the home folder with the folder as argument, seen the same): `{skills: [{name, description, filePath, baseDir, source: "<provider>:<level>" (native, agents, claude, codex, github, skillshare…; user | project), hide}], warnings: [{skillPath, message}]}`. In ACP each skill is an available command `skill:<name>` (input hint "arguments"), after `session/new` (no key needed); `/skillful` toggles the prompt's listing.

**Background commands (2026-10-29; read in oh-my-pi 18.12.6's source, not run)**
- Bash with `async: true`, or any after 60 s, runs on as a job; omp stops one through `proc://<id>/kill`. Its shell is built into the omp process, so the programs are omp's direct children with no shell between, and their process group isn't known: a group kill could be omp's own. The call stays `in_progress` until the job ends. Nushi has no background row or Stop for omp.
