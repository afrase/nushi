# Security notes

What Nushi reads, writes, runs and sends on your behalf, and what limits it. A security-sensitive change gets its entry here in the same commit ([AGENTS.md](../AGENTS.md)).

- A reply card's lead line names GitHub logins outside the quote ("Review comments from @octo"), so the agent knows whose they are: only what matches a login's shape (letters, digits, dashes, 39 at most, a bot's `[bot]`), else "someone"; the daemon's messages keep logins inside the data.

- **Mermaid** (ADR 0057): an agent's diagram text runs through mermaid.js at its strict level (labels as text, no clicks or links) in a web view that loads only Nushi's page and the pinned script (every other navigation refused); on the Mac one hidden WKWebView draws every transcript block, on the phone the sandboxed frame of the page previews (its script from the relay, `Cross-Origin-Resource-Policy: cross-origin` for that one file). A parse error's message (mermaid's, about the text) is shown as text.
- **The token** (0600, remade if empty or short) sits beside the socket in a 0700 folder; anything running as you, the agent included, can read it (ADR 0024). Any client with it can: list any absolute folder (`ListFiles`, 20,000 names at most) and read a regular file inside one (`GetFile`, 1 MB at most, no link followed out of the folder), read and watch a file in a chat's folder or worktree (`WatchChatFile`, 5 MB at most, through `os.Root`: no `..` or link out; polled each second while open; a paired phone too), read the memory of any process tree it names (`GetMemory`, sizes only), open a shell as you anywhere (terminals must stay off remote access, [ADR 0022](adr/0022-the-daemon-owns-terminals.md); closing kills what has the terminal as its controlling terminal), and add log lines (`Log`: 2 KB a message, 16 KB a stack, 16 attributes, escaped so one can't pose as another). Mentioned files go to the agent as `file://` links.
- **Agents run as you** (ADRs 0037, 0048): your CLIs from the login shell's `PATH`, with its environment, secrets included, read by the daemon running your shell (`-l -i -c`, its config runs; 5 s, then killed with what it started); the values stay in the daemon's memory and the agents' processes (names only in the log, at DEBUG; the API carries the shell, when, and why it failed); `NUSHI_*`/`NUSHID_*` (a chat's tools key among them) never reach an agent; a chat's folder reaches the agent only as `cwd`. Adapters install with `npm ci` from lockfiles pinning version and sha512 (no install scripts or optional packages; npm under `sandbox-exec` writing only in `agents/`; your registry applies, checked against the hashes) and run as `node <program>` from the data folder (a project's `node_modules` or `.npmrc` can't swap them; the first `node` on `PATH`). Finding agents runs `--version` (and `claude auth status`) with writes and the network denied.
- **Codex**: codex-acp tells Codex to trust every session's cwd, so a folder's `.codex/config.toml` (MCP servers, commands' environment, sandbox, plugins) and rules load without asking; Nushi's card is the only warning (ADR 0029), keyed by a hash of every file shown and checked again on "Start anyway"; links aren't followed; Codex's trust record is only read. Codex snapshots each thread's shell environment, secrets included, into `$CODEX_HOME/shell_snapshots/<thread>.sh` (0644).
- **Ante** (`ante serve --stdio` under `nushid ante-acp`): the bridge reads only `ante catalog` and sessions' `meta.json`, and removes a session's folder only for an id of Ante's form; prompt images go to a private temp folder removed when it ends. **omp** loads a project's extensions, hooks, tools, command modules and LSP servers without asking; the card shows each whole (ADR 0031); its bash asks, its writes don't. **PiG** (ADR 0039) **runs every tool call without asking**; a folder's `.pig` loads only once trusted in PiG, `AGENTS.md`/`CLAUDE.md` regardless; the bridge trashes a session's file only for an id whose header it found. Both bridges read a write's old text from a regular file of at most 1 MB, no links (`internal/toolcall`).
- **Trust** reads `~/.claude.json`, never writes it ("Start anyway" goes to `trusted.json`); trust of the home folder or `/` covers that folder only, and `~/.claude` is never the home folder's own. It fails closed: it lists any string setting named like Claude's credential helpers (`…Helper`, `…AuthRefresh`, `…CredentialExport`), a skill's raw front matter when it has hooks, a `.mcp.json` it can't read.
- **Git** runs as you in a client's folder with `core.fsmonitor` off, `--no-ext-diff`/`--no-textconv`, `core.hooksPath=/dev/null`, signature checks off, `GIT_NO_LAZY_FETCH=1`, `--ignore-submodules=dirty`, and the panel's status without filter drivers (Changes and new worktrees still run them: git-crypt, lfs). Nushi writes into a repository only `.worktrees/` and `info/exclude`, never through a link, switches a folder's branch when the user picks one (`git switch --no-guess`, a local branch, the name checked by git's rules first; its smudge filters run, as for a new worktree), and renames a worktree's branch it made (`git branch -m`, the name checked by its rules and `git check-ref-format --branch`, never one on a remote); reads only regular files, 1 MB at most (64 MiB for Claude's settings and `.mcp.json`); refuses bases and commits starting with `-`; forces a worktree removal or `branch -D` only when asked after the app showed what's lost (the daemon checks again). Moving a chat writes a transcript copy (0600) into Claude's projects folder for the fork, removed after, never replacing one.
- **MCP**: Claude's config holds secrets in clear; the daemon masks them before they leave it. It runs `claude mcp add-json/remove/login/logout` (names checked, `--`), so a client can add a server Claude runs as you, as a prompt could. The switch writes only the two MCP lists of the project's `.claude/settings.local.json` (atomically, keeping its mode) and may add it to `.git/info/exclude`. A user or local server's switch runs `claude -p --bare` in the folder with two control requests on stdin (the name as JSON), which writes `~/.claude.json` itself; `--bare` runs none of the folder's hooks, helpers or servers. Ante's (ADR 0058): its settings hold secrets in clear too, masked the same way; Nushi writes only `mcp_servers` of `$ANTE_HOME/settings.json` (under Ante's flock, atomically, keeping its mode; a file that isn't JSON refused), so a client can add a server Ante runs as you; Check runs `ante serve` in an empty temp folder, which starts every server in your settings.
- **Skills** (ADR 0051): skills' and plugins' text is its authors' (a plugin's a third party's): shown as plain text (control and bidi characters dropped), never Markdown or links, never sent to an agent. `claude plugin` runs only in Claude's config folder (ids checked, after `--`). Writes are one key each (`skillOverrides`, `disableBundledSkills`, `enabledPlugins`) in your `settings.json` (a link followed) or the project's local settings (links refused), replaced at once. Delete moves a folder to the Trash (`/usr/bin/trash`) only when it sits right in your skills folder or a project's `.claude/skills` that isn't a link (nor its `.claude`) and holds a `SKILL.md`; Open uses `open -t` (as text, whatever the file is). Other agents (ADR 0052): their settings are written only on a switch, one list each (Codex's `[[skills.config]]` path entries in `config.toml`, as text, the decoded result checked to be the original with only that change; PiG's `skills` list in yours or the folder's `.pig/settings.json` (there relative, `-skills/<folder>`, every other byte kept, else refused; a linked `.pig` refused); Ante's `exclude_skills`; omp's `disabledExtensions`, only in a file yaml.v3 writes back unchanged), links in a project refused, yours followed; a file of yours Nushi makes (Claude's, Ante's or PiG's `settings.json`, Codex's `config.toml`, omp's `config.yml`) is 0600 in a 0700 folder if that's new too (`atomicfile.Rewrite`), and one that exists keeps its mode (a project's local settings stay 0644, as git would make them). Link for Claude makes a relative symlink in `.claude/skills` (never through a linked `.claude`, nothing replaced) only to a shared skill some agent lists. A path the app sends (Delete, Link) must be a skill Nushi listed, right in a listed root; a project's linked roots are never listed; a skill folder that is a link is listed as one and Delete moves the link. No agent runs to list skills. A project's skill is trashed, linked and its settings written through an `os.Root` of its repository, so a folder an agent swaps for a link between Nushi's check and its act can't lead outside; skill folders whose names have control or invisible characters are skipped. Claude's skills and MCP servers run no git in the folder since 2026-10-29: the repository's top and the project are read from its files (`skillfile.Top`, `git.TrustRoot`, whose one `git config --file` only reads the main checkout's config file), as the trust card does.
- **Words Nushi puts in a prompt** (ADR 0016's second amendment): the note of a branch renamed, fixed words around two branch names that git accepts (`check-ref-format --branch`, after Nushi's own rules: no spaces, control characters or `..`); its own text block, never merged into the user's. A user's message the agent replays loses a leading text of exactly that shape.
- **Files someone else chose** (a repository's settings, a skill, a file a model names, a background shell's output) are read through `internal/regularfile`: only a regular file, checked before the open and on the open file (a fifo isn't waited on, a device isn't opened), a link followed only where the agent follows one, and at most so much (64 MiB for agents' settings, 4 MiB for a `SKILL.md`, 1 MB for a write's old text, 5 MB for a preview); one that grows past that while read is refused, not cut (Codex's `config.toml` was cut at 64 MiB and decoded, until 2026-10-29).
- **Stopping a background command** (ADR 0065): the daemon reads the command lines of the processes below a chat's agent (`kern.procargs2`, the user's own processes only; never logged) and sends SIGTERM, then SIGKILL, to one process group: the one whose leader is below the agent's process, is still the process found (its start time) and runs exactly the call's command, checked again just before the signal; the SIGKILL only while every process in the group started before the SIGTERM. An agent could start a process whose command line mimics another call's command: it then gets that group stopped, as it could stop it itself. The next prompt carries a fixed `[Nushi]` note naming the task's id.
- **Claude's transcripts in Go** (`claudeagent/sessions`, a port of the Python Agent SDK's helpers; `claudeacp` calls it to load, list, fork, delete and title sessions, and to tell a resume claude quit on from a session that is gone): reads Claude's transcripts in its config folder's `projects/`, every name from a session id that must be a UUID (no path in it) or an `agent-<id>.jsonl` found there; to find a session started in another worktree it runs `git -c core.fsmonitor=false worktree list --porcelain` in the session's folder (5 s at most), as the SDK does. `Fork` writes a new transcript (0600, its folder 0700 if new; `O_EXCL`, so never over another) beside the source or in a given folder's project folder; `Delete` removes `<id>.jsonl` and the `<id>/` folder beside it (subagents' transcripts), a link there removed, not followed.
- **Claude's requests in Go** (`claudeagent`'s control protocol; only `claudeacp` calls it): requests for credentials (`oauth_token_refresh`, `host_auth_token_refresh`, `remote_control_work_secret`) are always answered "unsupported", never passed to the caller's callback, and the environment that would invite them is never set. A permission request with no `CanUseTool` gets an error, never an allow; a user dialog gets no answer (none is declared); a request claude withdraws gets none either, whatever its callback returns. A hook callback runs only a function the caller registered in `initialize` (an unknown id gets an error); an MCP elicitation with no `OnElicitation` is declined, and an answer that isn't accept, decline or cancel is an error, never an accept.
- **Claude's ACP agent in Go** (`claudeacp`, ADR 0066; off by default): the daemon runs it only when Settings › Agents' "Use Nushi's Go agent" is on (`claudeGoAgent` in `settings.json`, which any client of the API can turn on, a paired phone included, as it can any setting; read each time a Claude chat's agent starts, so a running chat keeps the agent it started with until it next starts) or when `NUSHI_CLAUDE_ADAPTER=go` is in its own environment (a dev override that forces it whatever the setting says), as itself (`nushid claude-acp`, `os.Executable`), in the data folder, with the chat's environment (the login shell's, ADR 0048) and `CLAUDE_CODE_EXECUTABLE` naming the `claude` found on `PATH`, as for the adapter; its stderr goes to the log through the agents' redaction, claude's included (at INFO, a session's at most 20 lines at once then 2 a second, each cut at 1 KiB, the rest counted). It runs the user's `claude` once per session, in the session's folder (absolute and a folder, else refused), with the agent's environment plus `_meta.claudeCode.options.env`, the client's MCP servers (stdio ones are commands claude runs as you, as with claude-agent-acp) and settings, in the agent's own process group, so the daemon's kill of that group (an agent that overstays `stopGrace`) ends every claude, its stdio MCP servers and its hooks, as with the adapter (SIGTERM closes the sessions as stdin's end does), but not its Bash commands, background ones included: each leads a group of its own (docs/facts/claude.md) and outlives the kill, as under the adapter; it passes `--allow-dangerously-skip-permissions` (not as root without `IS_SANDBOX`) so the client may switch to bypass later, which claude's own settings can still forbid. It changes claude's mode, model and settings (effort, fast mode, main agent) only as the client sets them, an effort with `ultracode: true` when the session's settings turned ultracode on (else claude would turn it off). Every permission claude asks for goes to the client, and the agent never allows anything itself: no answer (withdrawn, the turn cancelled, an option it didn't offer) is a deny that stops the turn, and a request from work a cancel stopped is denied at once; "don't ask again" (claudeacp/always.go, worded per tool as claude-agent-acp words it) sends back the rules claude itself suggested, offered only where its words say no less than they allow (a file rule for any file only for a call in the session's folder, folder rules only when they reach one folder, named), or, as the adapter, a rule of its own kept in the project's local settings: a fetch's domain, a skill (or its prefix), or any use of a tool with no rules of its own (WebSearch, Agent…); none when an ask rule of the user's matched or claude said not to, and never one that would change the session's mode; leaving plan mode (ExitPlanMode) switches claude, for the session, to the mode the user picked from Auto (on a model that has it), Accept edits and Manual. AskUserQuestion's answers go back as the tool's input. An MCP server's form or page goes to the client only if it declares that kind, else it is declined; a page only when it is https, or http on a loopback host (localhost, 127.0.0.0/8, ::1), with a host and no user name in it (else declined and logged with the server's name), and both carry the server's name in `_meta.mcpServer`. It reads no settings or credentials itself. Of claude's transcripts (in `$CLAUDE_CONFIG_DIR`, else `~/.claude`) it reads a session's own, and its subagents', to replay a load to the client; the start and end of the folder's sessions (of every folder's, when the client names none) to list them; and the session's own for its title. It writes only a fork (the session's copy, into the request's folder's history) and deletes only on `session/delete`: that session's transcript and folder, after its claude has exited, wherever claude keeps them. A session id must be a UUID to name a file, so a request can't name a path. For the title, it reads the one claude keeps; when there is none it asks claude once a session to make one (`generate_session_title`, a model call of claude's, kept in the transcript) from the last 1,000 characters of the prompts and answers. It logs no prompt or text.
- **Recording claude for the parity tests** (`make claude-record`, a developer's tool; nothing in the daemon): it runs the `claude` named by `CLAUDE_TEE_REAL` (never one found by itself) under the pinned Node adapter, with none of the caller's environment but `PATH`: a throwaway `HOME`, `CLAUDE_CONFIG_DIR` and `TMPDIR`, a dummy `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL` at `fakeapi` and the CLI's nonessential traffic, telemetry, error reports and updates off, so no login, settings or account of the caller's takes part. `fakeapi` listens on loopback only, refuses a key shaped like a real one (`sk-ant-…`, never logged), and logs each call's path, model and answer, not its content. `claude-tee` writes the environment's names, never values, into a cassette, nor the values of any `env` or `headers` object in claude's arguments or frames (MCP servers' tokens, the settings' env), only their names (0600; the recorder copies the good ones into testdata); what claude and the adapter say is recorded as is, so a scenario's scripts must hold nothing secret. The adapter is set up in a cache folder with `internal/npm` as on Set up; the agent's process group is stopped at the end of each run, so no `claude` outlives it. A failed run's throwaway folder is kept in the temp folder for a look. A scenario's `kill` step stops a process group only below the agent the run started (`proctree`, as Nushi stops a background command), never one found elsewhere. The recordings keep claude's transcripts of the run (`history/`, from the throwaway config folder; never its `memory/`), which hold only what the scripts and the fake API said, and the run's throwaway paths.
- **What agents send**: a panic on it becomes a JSON-RPC error; a malformed form is refused. A line over 256 MB ends the agent (`agentproc.MaxRead`; the bridges likewise end a CLI that sends one), and a request to the API over 32 MB unzipped is refused before it is decoded (`api.MaxRequest`). Their Markdown's local images come only from regular files of 20 MB at most, remote ones after a click (a preview's Markdown: only the chat's files through `WatchChatFile`, remote ones as text); links open http(s) only. Background shells: the daemon reads only a regular `<task id>.output` in a `tasks` folder, no link, its last 64 KB. Finding a chat's session gone (ADR 0015) only reads Claude's project folder for the chat's folder (opens it, `lstat`s `<id>.jsonl`; ids with `/` or a leading `.` refused) and removes only Nushi's own record and an empty scratch folder of the chat's (`os.Remove`, which fails on a folder that has files). Listing sessions started elsewhere (ADR 0035) only reads (Claude's `sessions/*.json` and transcripts' first records, Codex's rollouts and lock files, omp's headers and locks via F_GETLK, Ante's `meta.json` and `lsof` on its `events.jsonl`).
- **The log** (ADR 0038): agents' stderr goes through a redaction pass for known secret shapes (`internal/secrets`, the ones tool calls' input loses) and values named like a secret (`NAME=value`, `"key": "value"`); a private key's lines after its BEGIN line are left out, to its END line (200 at most); a prompt or a key of another shape echoed there lands in `nushid.log` (0644 when the launcher's `>>` made it, 0600 when the daemon did; the folder is 0700). The client token is masked by value.
- **The helper** (ADR 0036): `start-daemon`, the launch agent's program, is a script sealed as a resource of the app's signature (launchd doesn't pin it to a hash) that only `open`s the helper. Start at login adds an item under Login Items.
- **The show tool** (ADR 0068): an agent can now open a file in the preview with no click, so on the Mac a page runs on the harness's ask alone. Nushi adds no allow rule and lists no annotations; Bypass permissions or "don't ask again" means pages open unasked. It takes only what a tool row's Preview could open (`filewatch.Allowed`, `filewatch.Artifact`, `filewatch.Check`: a regular file, links followed but not out of the folder), its path bounded (4096 bytes, no NUL), refused with fixed text because `tools.Service` logs a tool's error, and its answer carries nothing of the file. A show call never counts in `Wrote`. `Wrote` still counts any tool call's locations, reads and refused calls too. The path reaches the app in the `show` event and the row's input; both only ask `WatchChatFile`, which checks again, and the card and row mark control and bidi characters in it.
- **Previews of pages** (the owner: "we can trust what the agent writes and it's the user's responsibility", so no ADR, hardening later): on the Mac an agent's HTML, SVG or PDF runs in a WKWebView with its scripts and the network on, as a page opened in a browser would; only WebKit's free defaults hold: no script message handlers (nothing from the page reaches Nushi), file reads only inside the chat's folder or worktree holding it (else its own folder), and any navigation of the main frame away from the file opened in the default browser instead (http, https and file only, through the app that opens https, so a linked `.command` isn't run by Terminal; mailto by Mail). The daemon's watch still decides which files may show (the folders through `os.Root`, or `Wrote`), a preview tab's too: its path, kept in `app.json` across restarts, is only asked of `WatchChatFile` again, and only when the tab is clicked, so a restart runs no page. The web view then reads from disk itself, so a link inside the folder pointing out is WebKit's to refuse (its sandbox follows the resolved path). On the phone a page is written into a frame of `frame.html`, which the relay serves sandboxed (`sandbox allow-scripts`, as the iframe also is, so an origin of its own: no IndexedDB, no device key, no reach into the app) with a CSP of its own that lets scripts and the network run, framed only by the app (`frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`); the app's CSP gained `frame-src 'self'`. A `srcdoc` or `blob:` frame was tried first: WebKit gives it the app's CSP, so no inline script runs. The page can post messages to the app, which listens for none.
- **Transcripts' copies** (ADR 0047): each chat's transcript as shown (prompts, the agent's text, tool calls' output and diffs, images; since 2026-10-28 tool calls' raw input, an MCP tool's arguments too, and a raw output the content didn't show, 8 KB each at most; the input with what looks secret masked: every value under a key named like a secret (however deep; numbers and bools too, so `max_tokens` shows masked), and known token shapes anywhere, keys included (`internal/secrets`, as the log), as the row shows it; copies written before keep what they had; a tool call's title, the agent's own words and often its command, isn't masked) in `transcripts/<chat id>/` in the data folder (folders 0700, files 0600), readable by anything running as you, as Claude's own transcripts are. Never logged (counts, sizes and chat ids only; `TestNothingPrivateLogged` checks a copy written, merged and cleared), never sent to an agent; clients get it as they get transcripts (a paired phone too). Every path goes through an `os.Root` of the folder, named from a checked chat id or an image's SHA-256; a link planted there leads nowhere. Clearing removes the chat's folder; a crash's temporary files go at the next start. A rewind's fork may name an agent message id that came from the copy.
- **Drafts** (ADR 0062): what you're writing in a chat (text, mentioned files, reply cards with their quotes, images) sits in clear in `drafts.json` and `drafts/` (0600 in the 0700 data folder) until sent, or the chat is deleted or archived; the phone keeps text and cards in IndexedDB beside its key, readable by script on the app's origin.
- **The app's files**: `app.json`, `reviews.json` (review comments with the lines they quote), `context.json`, `drafts.json` and its images, and `pulls/` (pull requests as read) are each written whole through `writeWhole` (`file_mode_ffi.dart`), 0600, their folders 0700 (`privateDir`); the first three were 0644 before, in the 0700 data folder.
- **Remote access** (ADRs 0033, 0034; reviewed in milestone V): the Noise key is in `remote-key.json` (0600), readable by any process of yours. A paired phone is a full client (chats, permissions, terminals, MCP, adapters) but not the Mac's calls (SetRemote, StartPairing, ConfirmPairing, RevokeDevice); the remote API has no token check (the handshake authenticated the device). The Mac asks Allow or Deny for any pairing; the six-digit code is all that stops someone who saw the QR code within its 5 minutes. The PAC file is fetched directly and run by CFNetwork in osascript, asked only scheme://host:port/.
- **Jira** (ADRs 0042, 0043): the token is in the login keychain ("Nushi Jira"), readable by the build that stored it and by a later one after your OK (`security find-generic-password -w` gets the prompt too); any program of yours can delete it. It goes over HTTPS through the system proxy as Basic auth, to the site or Atlassian's gateway. An issue's text is rendered as escaped Markdown (fuzzed), people's names as plain text (control and bidi characters dropped; no avatar image fetched), links http/https/mailto, images only its attachments through the daemon. A chat's tools key (in its MCP server's environment and on Claude Code's command line, so in `ps`) grants that issue's four tools while the daemon runs; the agent's writes are its harness's to allow. What lists and issues showed last (issue text included) sits in `cache/jira/<site>.json` in the data folder (0600, its folder 0700), readable by anything running as you; dropped with the site, never logged.
- **GitHub** (ADRs 0045, 0046): a host's token is gh's (go-gh in the daemon, gh's config read again when a host isn't in it or has no token; else `gh auth token`, the token on its stdout, 10 s at most, in a process group of its own; gh having no token is believed for 30 s) or a pasted one in the keychain ("Nushi GitHub"); sent only in the `Authorization` header to its own host (never to a job log's link). A host must be github.com, gh's, or given a token before any token is read for it (go-gh gives `GH_ENTERPRISE_TOKEN` for any host). A `GH_TOKEN` in your shell reaches agents as it would a terminal; Nushi adds none. GitHub's text is rendered as GitHub renders it, parsed as a browser does, written back from what its sanitizer keeps; tested against GitHub's renderer and fuzzed. Addresses from GitHub leave the daemon only when http(s) (`webLink` checks again). Names that go into the inbox's searches (repositories, owners, hidden or picked, the folders' remotes') are checked against GitHub's characters first and a bad one refused (`InboxFilter.Check`), so none adds a qualifier of its own. In a message for an agent, GitHub's text sits between random marks, said to be data, outsiders marked. Send to agent quotes it in a reply card instead: every line of a quote goes to the agent behind `> ` (`withReplies`), so its text can't end the quote, and the card's own words say it's data. GitHub's refusals reach the app in its words, plain and bounded (1 KiB, no control or format characters); the log has only their status (`api.loggable`). The inbox GitHub gave last sits in `cache/github/<host>.json` (0600). Keychain failures are logged with the call, its OSStatus and macOS's words, never the account or the secret; a daemon that can't be asked never prompts (an OK given then would be recorded for another program).
- **The phone's web app** (ADR 0054; reviewed by subagents on 2026-10-27): the device's X25519 key sits raw in IndexedDB with the pairing: script on the app's origin can take it and act as a paired device (code execution as you on the Mac) until revoked. Limits: the relay's CSP (`default-src 'none'`; scripts, images, fonts and connections only its own; `wasm-unsafe-eval` for CanvasKit; `unsafe-inline` styles, which the engine needs; Trusted Types required, Safari 26+), no third-party code, an origin used for nothing else (another service mounted on the same host would share IndexedDB), Revoke on the Mac. Whoever serves the app (the relay's operator, whoever takes the Pi, anyone with a certificate for its name) can serve code that takes the key: use it only from a relay you run; with `-web` the relay is trusted for code, not only a pipe. `-origin` is https except on this machine. The pairing link's secret is in the fragment, taken out of the address once read; it travels through the QR code (which iOS's Camera opens as a link in Safari: the fragment stays on the phone), the clipboard (Universal Clipboard: your other Apple devices) or AirDrop, single-use for 5 minutes, and the six-digit code still stands. Scan: the camera only from a tap, its frames read in the page or `qr_worker.js` (jsQR 1.4.0, vendored unchanged from the npm registry's tarball, sha512 checked; pure computation) and dropped, the stream stopped when the screen goes; the relay's Permissions-Policy allows the camera for its own origin only. **Cloudflare** (the owner's relay since 2026-10-27): it terminates TLS for `nushi.aaronfrase.com`, so it (and anyone with the owner's Cloudflare account) can serve altered app code that takes the device key, as the relay's host can; its Rocket Loader rewrote the page's script once (the CSP's Trusted Types refused its loader). Tailscale on the phone would keep TLS on the Pi. Static files have no bandwidth cap of their own (only the per-address connection caps and a write deadline).
- **Web Push** (ADR 0054): the VAPID private key in `vapid.json` (0600), never logged; subscriptions (endpoint and keys) in `devices.json` with their device, never sent to clients (the API says only on or off), removed by Revoke or a 404/410; pushes only to https on 443 at Apple's, Google's, Mozilla's or Microsoft's push services (a plain host name: no IP literal, zone or port), through the Mac's proxy, no redirects followed; a failure is logged without the endpoint, the push service's answer by status only. A payload is the title, the kind, the agent and the chat's id: nothing of the chat's. Only a device's own channel sets its subscription or view; only the Mac sends a test.
- **Pull requests kept**: each pull request a chat's tab or widget read last (its text, comments, threads, checks' summaries) sits in clear in `pulls/` in the app's data folder (0600 in a 0700 folder), readable by anything running as you, as `cache/github/` is; the 50 newest, never logged, named from the host, repository and number when those are only GitHub's characters.
- **Clean-up after a pull request** (ADR 0063): `RemoveChatWorktree` forces (`git worktree remove --force`) only when the request says so, which the app sends only after its dialog named the uncommitted files; it removes ignored files too (said in the dialog); never mid-turn or under another chat that isn't archived. `DeleteChatBranch` runs `branch -D` only with no worktree holding the branch, and with commits its base lacks only when forced (after a merge GitHub reports). `DeleteGitHubBranch` deletes `refs/heads/<head>` on the pull request's head repository only for a merged or closed pull request, only while that ref is at the pull request's head commit, never the default branch; `RestoreGitHubBranch` makes it again at that commit. `RerunGitHubChecks` re-runs the failed jobs of the runs a pull request's failed checks belong to. All with the user's token, logged by what, never the names.
- **Merging** (ADR 0069): `MergeGitHubPull`, `EnableGitHubAutoMerge`, `DisableGitHubAutoMerge`, `EnqueueGitHubPull` and `DequeueGitHubPull` write to GitHub with the user's token. A client asks; the app asks only from the user's confirmation, and nothing in Nushi merges by itself. Before each write the daemon reads the pull request again and refuses without sending: not open, no write access, a head other than the one the client names (a commit's id, always sent to GitHub as `expectedHeadOid`), a base branch other than the one it names (a pull request retargeted since), a method the repository or its rules don't allow. A merge or an enqueue also needs nothing in `MergeBlocks`, so an admin's token isn't carried past a rule (GitHub would take it, unasked); auto-merge isn't taken for a draft, a conflict or what could merge now, which goes the direct way; there's no bypass in the API, and `jump` is never sent. What's left is a race with GitHub between that read and the write, for rules only: the head stays checked by GitHub. Any client of the API can make these calls, a paired phone too, as for a review; an agent gets no tool for them, but runs as you, so it could use `gh` or the client token (ADR 0024). The commit's title and message are the user's, 1 KiB and 64 KiB at most, never logged; GitHub's defaults come plain and bounded the same way, and are shown as text. Logins shown (who turned auto-merge on, who queued it) are only what has a login's shape, else "someone". Logged: the host and what was done (`merge squash`), never a title, branch, login or GitHub's words.
- **The update check** (ADR 0061): the daemon asks `api.github.com` for the latest release of `afrase/nushi` every 2 hours (GitHub sees the Mac's address, nothing else: no token, no header of the user's), through the system proxy; the tag must parse as a version, and the link the app opens is built from it, not taken from the answer. The app opens it only through `webLink` (http/https).
- **Releases** (ADR 0055): signed ad hoc and not notarized; the cask clears the quarantine, so the tap stands in for Gatekeeper and whoever can push to `afrase/homebrew-tap` or publish a release here decides what `brew install` runs. `HOMEBREW_TAP_TOKEN` is a fine-grained token for that one repository, used only in the cask step; only the last job (`publish`: attach and the cask) has `contents: write` on this repository, and it runs no code of the tag's but its cask template; the build and check jobs read only. A daemon stops itself when its executable is gone at two checks 30 s apart (`cmd/nushid/deleted.go`).
- **govulncheck** reports GO-2026-5932 with no fix (`golang.org/x/crypto/openpgp`, unmaintained): module-level only, since Nushi never imports `openpgp` (it needs x/crypto for autocert and Noise); `make lint` passes, and it stays until x/crypto drops the package.
