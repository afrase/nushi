# 0052. Skills for every agent, and the shared .agents/skills

## Context
The owner asked for the Skills view to cover every agent, above all the shared convention: a repository's `.agents/skills/<name>/SKILL.md`, which several agents read, hoping Claude adopts it too. Seen in step 303 (`docs/facts/*.md`): Codex 0.163.0, PiG 0.5.3, omp 18.12.6 and Ante 0.2.14 read `.agents/skills` and `~/.agents/skills`, each with its own walk (Codex, PiG and omp up to the repository's root, Ante the folder alone), PiG only once the folder is trusted; Claude Code 2.1.310 reads neither, but follows a skill folder in `.claude/skills` that is a link. Each agent turns a skill off its own way: Codex by path in `config.toml` (`[[skills.config]]`), PiG by path in the scope's `skills` list (yours, or the project's `.pig/settings.json`), Ante (`exclude_skills`) and omp (`disabledExtensions`, YAML) by name only.

## Decision
- **A reader per agent** behind `features/skills` (`claudeskills`, `codexskills`, `pigskills`, `ompskills`, `anteskills`), each reading the agent's files itself: no agent runs in the folder to list. The view picks an agent (Claude by default; a chat's menu opens its own).
- **Shared skills** (the project's `.agents/skills` as the agents walk it, and `~/.agents/skills`) are listed once, with every agent that loads each and its state for each. The switch is the picked agent's, by its own mechanism, edited as 0051 edits Claude's settings (only that key or list, the rest kept, replaced at once): Codex's `config.toml` as text, comments and order kept, the result decoded and compared, else refused ("change it in config.toml"); omp's `config.yml` only when yaml.v3 writes it back unchanged. Name-only switches say "by name, everywhere". PiG's project switch writes the project's `.pig/settings.json`, the only place PiG takes it. A folder PiG doesn't trust says "Loads once the folder is trusted", with no switch.
- **Claude** gets a shared skill only through a relative link, `.claude/skills/<name>` → `../../.agents/skills/<name>`, made on "Link for Claude…" (asked first); such a link shows on the shared row, not as a project skill. New skill… asks for `.agents/skills/<name>/SKILL.md` with `name` and `description` when the agent reads it; for Claude it offers `.claude/skills` instead, or `.agents/skills` and the link.
- **Links**: a project's linked roots stay out for every agent (step 300's rule), though the agents follow them; a linked skill folder is listed as linked, and Delete moves the link, not its target. Delete of a shared skill names every agent that loses it and takes the agents' links to it too. Delete only of the agent's own folders.

## Consequences
- What Nushi lists can differ from an agent's own list: linked roots, PiG's nested skills and skills named in settings or packages, omp's plugins and skillshare's, Codex's plugins' skills; a name in two places shows twice (omp renames one, Codex lists both).
- A PiG project switch changes a file the repository may commit.
- When Claude reads `.agents/skills`, `claudeskills.Shared` adds those roots, `reads_shared` turns true and the link offer goes (`docs/facts/claude.md` says what was seen).
- Amends 0051: the page is every agent's.
