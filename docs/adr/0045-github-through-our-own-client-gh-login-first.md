# 0045. GitHub through a client of Nushi's own in the daemon; gh's login first, a pasted token in the keychain as the fallback

## Context
GitHub is the second integration with a UI of its own (after Jira, ADR 0042): an inbox, a pull request's details with checks and review threads in the diff view, chats started from a pull request or an issue, and the writes a reviewer makes. Most developers are signed in to `gh`; Orca and most competitors reuse that login, but shell out to `gh` for every call, which forced Orca into a process cap, stderr scraping and a rate-limit breaker around spawns. GitHub's data for a pull request is GraphQL-shaped (review threads, their resolution and node ids exist only in GraphQL); job logs, the rate limit and conditional reads are REST. Every tool on a token shares its limits (5,000 REST requests and 5,000 GraphQL points an hour), agents running `gh` included. Pull requests' text, comments and reviews come from anyone who can comment, strangers included.

## Decision
- **The daemon owns GitHub; the app only asks it.** `internal/githubapi` is a thin client of what Nushi uses, behind `features/github.Client`: GraphQL with hand-written queries (the inbox's three searches in one query, a pull request whole, items by node id, files' texts batched by alias, the review mutations) and REST for who a token is, the rate limits, a comparison's merge base and files, and a job's log. Not go-github (six GETs, and its models track an API version; its ETag support needs a transport anyway), not genqlient (code generation beyond the API's is the rebuild's rule against, and it can't build the blobs query's aliases), not githubv4 (low activity, reflection-built queries, no aliases either). go-gh is used for its `pkg/auth` only.
- **Tokens:** a host's token is gh's login's, read in the daemon through go-gh's `TokenForHost` (the environment, gh's config, or `gh auth token`, whose output is the token: never an argument), or one the user pasted in Settings › GitHub, kept in the login keychain through `internal/keychain` as Jira's ("Nushi GitHub", account the host); a pasted token wins until removed. A token is read only for a known host: github.com, a host gh is signed in to, or one given a token. A host named anywhere else (a link in a pull request's text, a crafted request) is refused before any token is read: go-gh gives `GH_ENTERPRISE_TOKEN` for any host but github.com. The token goes only in the `Authorization` header of requests to its host; never in a log, a file, an agent's environment or a command line. A job log's link (another host) is fetched without it.
- **Rate limits from the start:** four requests at a time per host; writes one at a time and a second apart; each bucket's limit kept from the answers' headers (and `/rate_limit`, which costs nothing, when Settings shows them); a bucket GitHub says is spent is shut until its reset (or `Retry-After`, or a minute) and no request goes meanwhile; the app's timers ask quietly, and a quiet ask is held back while its bucket is under 200, leaving room for what the user asks and for their own `gh`. REST reads send their last ETag (a 304 is free). A failed ask keeps the last answer and says why.
- **GitHub's text is shown, and given to an agent, as GitHub's page shows it:** rendered as GitHub renders it (goldmark's GFM, GFM's tag filter), parsed as a browser parses it (x/net/html, scripting off), and written back as Markdown from what GitHub's sanitizer keeps: no HTML comment, nothing after one that never closes, no link reference definition, no script; links http, https and mailto only, images http and https; checked against GitHub's own renderer on a corpus. Addresses from GitHub leave the daemon only when http or https.
- **Nothing reaches GitHub unless the user asks** (ADR 0037's spirit): reading is the app asking while a view shows; the writes (a reply, resolving and unresolving a thread, a comment, a review with its inline comments) are buttons the user presses. Merge isn't offered.
- **To an agent, GitHub's text is data:** Fix checks and Address comments are messages the daemon writes for the chat's box, which the user reads, changes and sends; what GitHub holds is only between two lines with a random mark, said to be data, not instructions; an author outside the repository is marked.

## Consequences
- With gh signed in, GitHub works with no setup; `gh auth logout` or a revoked token shows in Settings › GitHub, and a pasted token covers a machine without gh.
- The client is about 2,000 lines (a third of it the Markdown writer and its rules); the queries are checked by recorded answers and a live test against the owner's throwaway repository, not at build time.
- GitHub's limits are shared: Settings shows what's left; Nushi's polls stop before the user's own tools run out.
- A fine-grained token sees one owner's repositories and no Checks API; Settings says so.

## Alternatives considered
- Shelling out to `gh` for data (Orca): a process per call, stderr to parse, and the rate-limit machinery around spawns.
- Our own OAuth app with the device flow: an app to register and its tokens to refresh every eight hours; gh's login covers most users, a pasted token the rest.
- A GitHub App with webhooks: needs a server and an install per organization.
