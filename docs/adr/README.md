# Decisions

- [0001](0001-chat-wrangler-and-diff-viewer.md) Nushi is a chat wrangler and a very good diff viewer
- [0002](0002-separate-daemon.md) A separate Go daemon runs the agents; Flutter is the window
- [0003](0003-acp-v1-own-client.md) Agents speak ACP v1 through our own small client (it became a library: 0041)
- [0004](0004-connect-over-unix-socket.md) Connect RPC over a Unix socket, additive changes only (a rename in place keeps the number and type); a newer app asks for a daemon restart
- [0005](0005-clients-authenticate.md) Clients authenticate with a token from the start
- [0006](0006-remote-through-relay.md) Remote access later, through an end-to-end encrypted relay (replaced by 0033 and 0034)
- [0007](0007-harness-owns-permissions.md) The harness owns permissions; its mode is the only control
- [0008](0008-chats-belong-to-the-agent.md) Chats belong to the agent
- [0009](0009-agent-questions-are-cards.md) Agent questions are real, answerable cards
- [0010](0010-json-files-for-sessions.md) A JSON file per session until that stops being enough
- [0011](0011-nushi-next-identity.md) The rebuild runs as "Nushi Next" beside the first build
- [0012](0012-diff-view-package.md) The diff viewer uses the published diff_view package
- [0013](0013-app-starts-its-daemon.md) The packaged app starts its own daemon, never stops one on its own (how it starts it: 0036)
- [0014](0014-moving-a-chat-forks-it.md) Moving a chat forks its Claude session
- [0015](0015-delete-takes-the-agents-history.md) Deleting a chat deletes the agent's history of it, through ACP; a chat whose session the agent deleted is forgotten (amended)
- [0016](0016-a-worktree-per-chat.md) A chat can have a git worktree of its own (amended: its branch is named after the chat, the agent is told of a rename, and the choice is per chat, not remembered)
- [0017](0017-context-breakdown-from-claude.md) The context card reads Claude's /context output
- [0018](0018-the-app-is-nushi.md) The app is Nushi
- [0019](0019-changes-read-only-toward-git.md) The Changes view is read-only toward git
- [0020](0020-rewind-through-a-vendor-fork.md) Rewinding forks the session at a message through a vendor extension
- [0021](0021-claude-config-is-the-mcp-source.md) Claude's own config is the source of truth for MCP servers; Nushi changes it only through the `claude mcp` CLI
- [0022](0022-the-daemon-owns-terminals.md) The daemon owns terminals; they are local-only until remote access decides otherwise
- [0023](0023-warn-before-a-folder-runs-code.md) Warn before a folder's own code runs (hooks, helpers, `.mcp.json` servers) unless Claude or Nushi trusts it; never refuse
- [0024](0024-the-agent-can-read-the-token.md) The agent can read Nushi's token file; no same-user protection is worth its cost (amends 0005)
- [0025](0025-claude-rules-in-one-place.md) Claude's rules live in `internal/claude*`; the chats feature takes a `Dialect` that `main` fills (since 0077 a harness type per agent)
- [0026](0026-the-transcript-lays-out-every-item.md) The transcript lays out every item it has, not a lazy list; a long chat's recent part, pages above it
- [0027](0027-what-lives-only-in-memory.md) What lives only in memory, in the daemon and the app
- [0028](0028-agents-get-the-login-shells-environment.md) Agents get the login shell's environment, through the daemon's; Nushi doesn't read or filter it (superseded by 0048)
- [0029](0029-warn-before-a-folder-runs-code-for-codex.md) Warn before a folder's own code runs, for Codex too; "Start anyway" is kept per agent
- [0030](0030-our-own-bridge-for-ante.md) Ante runs through an ACP bridge of Nushi's own (`nushid ante-acp`), not `ante-acp`
- [0031](0031-warn-before-a-folder-runs-code-for-ante-and-omp.md) Warn before a folder's own code runs, for Ante and omp (and opencode, amended: every folder up to `/`); the files are read by `internal/folderfiles`
- [0032](0032-idle-chats-sleep.md) Idle chats sleep: their agent stops, a message wakes them through `session/load`; a chat that couldn't reopen isn't asleep, and showing it tries again
- [0033](0033-the-relay-is-a-dumb-pipe.md) The relay is a dumb pipe that keeps nothing; what it can still see (replaces 0006)
- [0034](0034-noise-between-phone-and-daemon.md) Noise (IKpsk1 to pair, IK after) between the phone and the daemon; pairing by QR code; a paired device is a full client; the threat model (replaces 0006, amends 0022)
- [0035](0035-open-sessions-started-elsewhere.md) Sessions started elsewhere (a terminal) open as chats through `session/load`, not copies; forks left out; open elsewhere: warn where both can write, not offered where the agent allows one writer (amended: a title filter, and a search of what was said in Claude's and Codex's transcripts, read each time, no index)
- [0036](0036-the-daemon-is-a-background-helper-app.md) The daemon is a background-only helper app (`Contents/Helpers/Nushi Daemon.app`) the app opens through Launch Services; Start at login is a launch agent that opens it too; no KeepAlive (amends 0013)
- [0037](0037-agents-you-set-up.md) Agents are found on PATH, read-only; an adapter is set up only when asked, from our own lockfile, into the data folder; agents run the user's own CLIs; no npx (supersedes part of 0003; its Claude part superseded by 0066)
- [0038](0038-logs-you-can-debug-from.md) Logs you can debug from: slog's text format, a line per thing that happened with the chat's attributes, rotated by the daemon, the app's errors in it; never what the user wrote
- [0039](0039-our-own-bridge-for-pig.md) PiG runs through an ACP bridge of Nushi's own (`nushid pig-acp`) on its RPC mode, not `pig-acp`; no trust card (PiG's own trust gates what a folder loads)
- [0040](0040-strict-linting.md) Strict linting: every golangci-lint linter on unless listed off with why, and govulncheck, pinned in `tools/lint/go.mod`; very_good_analysis under strict Dart analysis; `make lint`, `make check` and CI (amended: CI's parts as parallel jobs, the app's tests in shards, goldens on macOS)
- [0041](0041-acp-through-acp-go.md) Agents speak ACP through `github.com/afrase/acp-go`, Nushi's client grown into a library of its own; Nushi uses its unstable package at a tagged version; what is Nushi's (logging, the fake agent) stays in Nushi
- [0042](0042-jira-cloud-through-our-own-client-tokens-in-the-keychain.md) Jira Cloud through a thin client of Nushi's own in the daemon (classic or scoped API tokens, Markdown both ways through ADF); tokens in the login keychain through the Security framework, never prompting unless the user asks; nothing reaches Jira unless asked
- [0043](0043-an-mcp-server-of-nushis-own-for-a-chats-tools.md) A chat's agent gets Nushi's tools through `nushid tools-mcp`, an MCP server over stdio with a key per chat that grants that chat's tools only (Jira's for its issue); the harness asks before they run
- [0044](0044-a-turn-ends-with-its-own-work.md) A Claude turn ends with its own work, not when the adapter answers its held prompt; Stop spares background subagents (`perTaskStopAffordance`); what stops Claude asks first; amended: subagents as sessions of their own (their ends, a Stop each)
- [0045](0045-github-through-our-own-client-gh-login-first.md) GitHub through a thin client of Nushi's own in the daemon (GraphQL for pull requests, REST for logs and limits; go-gh for auth only); gh's login first, a pasted token in the keychain; a token only for a known host; rate limits gated from the start; GitHub's text as its page shows it; nothing reaches GitHub unless asked
- [0046](0046-the-github-inbox-and-polling.md) The GitHub view is an inbox polled while it shows (a minute), a pull request's details every 30 s, a chat's status chip each minute; answers kept briefly, last known on failure; files read once a head
- [0047](0047-nushis-copy-of-transcripts.md) Nushi keeps its own read-only copy of each chat's transcript as it was shown (on by default): a reopened chat shows the copy and the agent's replay once each ("Compacted here" where Claude's replay starts; the agent's from where they differ); a chat whose session is gone stays read-only with it; never sent to an agent
- [0048](0048-agents-start-with-the-login-shells-environment.md) Agents start with the login shell's environment, which the daemon reads itself (`<shell> -l -i -c`, between marks, 5 s at most) at start and from Settings › Agents (a minute old, or Reload), over its own, without Nushi's own variables; a failure falls back and says so; values never logged or sent (supersedes 0028)
- [0049](0049-controls-look-like-controls.md) Controls look like controls: one set on `Pressable` (Button secondary, primary, destructive; MenuField, compact or boxed; MenuButton; MenuIcon; LinkText for going somewhere; IconTap only where the icon is clear; DragGrip on draggable cards), named tokens for both themes; plain text never clickable, `Menu` opens only from a control; ⌘1–⌘9, ⌘[, ⌘] switch chats, a terminal's tabs and Jira's lists take ⌥⌘1–9
- [0050](0050-mcp-servers-off-through-claudes-own-toggle.md) A user or local MCP server goes off for the project through Claude's own toggle (`mcp_toggle` to a `claude -p --bare` run, which writes `disabledMcpServers` as `/mcp` does); project servers keep their settings switch; plugins' servers and connectors say only `/mcp` can (amends 0021)
- [0051](0051-the-skills-manager.md) The skills manager reads Claude's skill folders and settings itself and `claude plugin list --json` outside the folder; writes only `skillOverrides`, `disableBundledSkills` and `enabledPlugins` (your settings or the project's local ones) and `claude plugin` for your plugins; deletes to the Trash (widens 0021's exception)
- [0052](0052-skills-for-every-agent-and-the-shared-folder.md) Skills for every agent: a reader per agent (its own files, never run in the folder); `.agents/skills` and `~/.agents/skills` as Shared, with the agents that load each and the picked agent's own switch (Codex's `config.toml` as text, comments kept or refused; PiG's `skills` list; Ante's and omp's by name); Claude through a relative link in `.claude/skills` made on request; linked roots left out (amends 0051)
- [0053](0053-settings-is-a-view.md) Settings is a view in the chat's place (⌘,; Esc and Close go back; superseded in that by 0087): a nav of ten sections, MCP servers and Skills among them, every way in through `openSettings(section:)`; pages of grouped rows with controls at the group's edge, 720 px at most, left-aligned beside the nav; Chat history a lazy table
- [0054](0054-the-phone-is-a-web-app-with-web-push.md) The phone is the Flutter app on the web, on the Home Screen, served by your own relay (`-web`, a strict CSP, WebSockets from its own origin only); pairing by a link with the parameters in the fragment; the device key raw in IndexedDB (as safe as the origin serving it); Web Push straight from the daemon to an allowlist of push services, RFC 8291 and VAPID on the standard library, saying only what happened (amends 0034 and the push decision); amended: Scan with the camera and the QR code as an https link, long chats' recent part first and gzip, the relay behind a Cloudflare tunnel (trusted for code), the engine's fallback fonts mirrored at build time (sha256-locked) and served by the relay, IBM Plex cut; a turn's end judged once by the daemon (done, failed, stopped; a crash fails) for push and the Mac alike
- [0055](0055-releases-and-the-homebrew-cask.md) Releases from a published GitHub release (`release.yml` builds each part of `tools/release.sh` in a job of its own beside the check, a passing CI run or CI called: the app's zip, the relay for Linux arm64/amd64 and macOS, the web app, checksums); no GoReleaser; a cask in `afrase/homebrew-tap` that clears the quarantine, updated for the latest release only; versions from the tag into the app and the daemon (Ping's `version`); macOS 13 and arm64; upgrades leave the daemon running, which stops itself once its app is deleted (after Sextant's ADR 0058)
- [0056](0056-the-daemon-restarts-itself-when-idle.md) An older daemon restarts itself into the bundled one once nothing runs: the app's pings ask (an ask lapses in 15 s), idle is sleep's rule across every chat plus no terminal running a command, prompts refused as Unavailable from the check on and sent again by the app; the app stays usable while it waits (amends 0004, 0013, 0055)
- [0057](0057-mermaid-diagrams.md) Mermaid diagrams: one pinned `mermaid.min.js` (sha256-locked, fetched at build time, among the app's assets for the Mac and the phone; strict level); `.mmd` previews in a web view (the phone's sandboxed frame); transcript and Markdown blocks drawn once by a hidden WKWebView into PNGs at the block's width (the phone: Show diagram); a block still streaming or that doesn't parse shows its source
- [0058](0058-antes-mcp-servers-in-its-settings.md) Ante's MCP servers (yours, its only scope) written by Nushi in `$ANTE_HOME/settings.json`, `mcp_servers` alone, under Ante's own `settings.json.lock` (flock) and atomically; no off switch or sign-in (Ante has none); checked by a throwaway `ante serve` session's warm-up notice (amends 0021)
- [0059](0059-a-chats-pull-request.md) A chat's pull request found by its branch's head (REST `pulls?head=` with ETags, the remote pushed to first, forks' parents too) and linked on the chat; a hand link wins, Unlink is remembered; asked only while the chat (each minute, whatever its panel), the sidebar or the phone shows it; the tab is the GitHub view's own pane; Send to agent fills reply cards, never sends (amends 0046)
- [0060](0060-a-chat-keeps-its-picks.md) A chat keeps the options the user picked (model, effort, ...), following the agent's own changes, and puts them back on every open of its session, model first; each agent's last picks start new chats (amends 0007, 0032); amended 2026-11-05: a side chat starts on its chat's mode and picks, and its own changes are its session's alone, never remembered
- [0061](0061-the-daemon-checks-for-a-newer-release.md) The daemon asks GitHub for Nushi's latest release at start and every 2 hours (no token, ETag, a setting on by default), compares it by semantic versioning with its own; the app shows a toast in the bottom right corner: Copy (Homebrew's upgrade, when the cask installed it) or Download, Release notes, × until a newer one
- [0062](0062-drafts-kept-on-disk.md) Each chat's draft kept on disk: the Mac's `drafts.json` (0600, atomic; images in `drafts/`), saved 500 ms after it stops changing, at once when sent or cleared and when the app goes to the back or quits, gone with its chat (deleted or archived); the phone's text and reply cards in IndexedDB
- [0063](0063-clean-up-after-a-pull-request.md) Clean up after a pull request: the PR widget's Clean up… names each part (worktree, local branch, the branch on GitHub, archive) with what it costs; the daemon refuses again (mid-turn, another chat there, uncommitted changes or unmerged commits without force, a worktree holding the branch); the GitHub branch only while it points at the pull request's head, never the default branch; Restore branch and Unarchive undo (amends 0016, 0059)
- [0064](0064-the-daemon-keeps-pinned-chats.md) Pinned chats are the daemon's (`Session.Pin`, `PinChats` sets the whole order, API 90; archiving unpins), so the phone shows them; a project's chat order stays the Mac's `app.json`
- [0065](0065-nushi-stops-background-commands-itself.md) Stop on a Claude background command signals its shell's process group (SIGTERM, SIGKILL after 2 s) when exactly one group leader below the agent runs that command, no turn; else, and for subagents, a short TaskStop prompt (the id only); the row ends "stopped" by Claude's own record, and the next prompt tells Claude why it "failed"
- [0066](0066-claude-through-nushis-go-agent.md) Claude through Nushi's Go agent: `claudeagent` (claude's stream-JSON protocol) and `claudeacp` (an ACP agent with the adapter's wire shape), run as `nushid claude-acp` on the user's `claude`; no Node, no versions pinned; since 2026-11-04 (amendment) Claude's only agent, the Node adapter and its setting gone (supersedes 0037's Claude part); since 2026-11-05 (amendment) its own module, `github.com/afrase/claude-acp-go`
- [0067](0067-forking-a-chat-makes-a-new-chat.md) Fork chat and Fork from here make a new chat (same agent, folder and worktree, picks, title marked "(fork)") on a fork of the session made by its own agent process, cut at the agent's message or before a running turn; its transcript and copy are the original's to there; Keep as chat makes a side chat such a chat, reopened on its own agent (API 94)
- [0068](0068-an-agent-opens-a-preview.md) An agent opens a preview: a `show` tool on Nushi's MCP server for every Claude and Codex chat, the harness's ask the gate before a page runs (no annotations, no allow rule; the card names the file); only what a tool row's Preview could open (`filewatch.Allowed`, the artifact types); the `show` event (API 95) opens it beside the chat that's showing, else the latest waits for that chat's transcript; the phone only offers Preview (amends 0043)
- [0069](0069-merging-a-pull-request.md) Merging a pull request: the Merge control (the repository's methods as a split button, ready or exactly why not), every merge from one confirmation with the commit's text editable, always at the head shown (`expectedHeadOid`, a moved head refused and re-read), the daemon refusing anything past a rule of the base's so an admin's token can't bypass; auto-merge, the merge queue (no direct merge there), a phone as for a review, no MCP tool (amends 0045)
- [0070](0070-preview-tabs-are-the-panes-own.md) Preview tabs are the pane's own: with two or more files open, the names take the file name's place in the pane's title row, so nothing else moves; every open adds or shows a tab (`show` under 0068's rules), in memory, one view at a time, ⌘W closes the showing tab; the one file's name has no menu (amended 2026-11-05: a click shows it in the Files pane); a browser tab's + (amended by 0094); the chat header's closable file segments and a permanent side column were rejected by the owner
- [0071](0071-one-look-for-tabs.md) One look for tabs: views of the same thing (the chat header's, Preview and Source, Changes' scopes, History's filters, a pull request's sections, a diagram's) are `PlainTabs`, labels with a line, drawn from the same pieces as 0070's file tabs and measuring what the pill measured; a form's values stay `Segmented`, and so does the phone
- [0072](0072-the-chat-areas-spacing.md) The chat area's spacing: a scale in the theme (gutters 24, 12 between a bar's controls, 24 between groups, 2 between icon buttons), the header and pane headers 44, the composer's box 48, the transcript 14 on 22, 16 apart, 32 before a chapter, capped at 860 at the left; a tool row has no box until it fails; gaps only come out of room over, so nothing folds sooner, and the phone keeps its values
- [0073](0073-comment-drafts-kept-on-disk.md) GitHub's and Jira's drafts kept on disk: the comment boxes' text and a review's inline comments in `comment_drafts.json` (0600), saved 500 ms after they stop changing and when the app goes to the back or quits

- [0077](0077-each-harness-is-a-type.md) Each harness is a concrete type (`claude.Harness`…) behind small interfaces in `features/chats/harness.go`, asked once by the service; what reads the Mac is a `Local` type around it, which tests never run (replaces 0025's `Dialect`)

- [0079](0079-stage-and-commit-from-changes.md) Stage and commit from Changes (amends 0019): whole files on Uncommitted, only from a click, the Mac's calls; a commit refused if what's staged moved since it was shown or reaches outside the folder; mid-turn a warning, not a block; it's `git commit`, hooks and signing run; the chat's agent can write the message in a throwaway read-only fork; no push
- [0080](0080-no-title-bar.md) No title bar: the content runs to the window's top, under the traffic lights; a header moves the window, and a double click in its empty space zooms it

- [0084](0084-a-code-block-runs-in-your-terminal.md) A code block runs in your terminal: ▷ types an agent's shell block into the chat's own shell session (a new tab when it's busy); OSC 133 marks tell where its output starts and ends; the output joins your next message only when the run ended on its own
- [0085](0085-pinned-messages-kept-by-the-daemon.md) Pinned messages are the daemon's (`PinMessage`, `Chat.pinned_messages`), one call per message; a pin keeps its item's id and a hash of its message's opening, by which a reopen without Nushi's copy finds a message Nushi named; a rewind's cut, Delete and a message gone from the agent's history drop it; a fork keeps those of what it keeps; amended: the agent's messages alone, a rail at the transcript's top left with its menu, and a title for each pin (the message's, then the agent's own)
- [0086](0086-color-themes.md) A color theme is a name and a dark and a light set of the tokens, which stay the one source of color (the terminal's and a diff's colors became tokens); built in Nushi, Vivid, Solarized, Nord, Catppuccin, Tokyo Night (a named third-party theme's known colors as published, exempt from the contrast tests in code, diffs and the terminal); the user's are JSON files in the data folder's `themes`, read strictly, a token each, watched; a custom theme under AA gets a warning, not a refusal; the phone picks a built-in

- [0088](0088-claudes-plan-runs-in-the-daemon.md) Claude's `/plan`, which claude refuses outside its terminal, is run by the daemon: a harness names terminal commands that set a chat option (`TerminalCommands`), offered with the agent's commands; `/plan` sets the mode as the menu does, leaves a notice, then sends the text after it; in plan mode already `/plan` alone says so and `/plan <text>` just sends the text (the terminal drops it); `SendPromptResponse.ran_command` tells the app
