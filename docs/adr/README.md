# Decisions

- [0001](0001-chat-wrangler-and-diff-viewer.md) Nushi is a chat wrangler and a very good diff viewer
- [0002](0002-separate-daemon.md) A separate Go daemon runs the agents; Flutter is the window
- [0003](0003-acp-v1-own-client.md) Agents speak ACP v1 through our own small client (it became a library: 0041)
- [0004](0004-connect-over-unix-socket.md) Connect RPC over a Unix socket, additive changes only; a newer app asks for a daemon restart
- [0005](0005-clients-authenticate.md) Clients authenticate with a token from the start
- [0006](0006-remote-through-relay.md) Remote access later, through an end-to-end encrypted relay (replaced by 0033 and 0034)
- [0007](0007-harness-owns-permissions.md) The harness owns permissions; its mode is the only control
- [0008](0008-chats-belong-to-the-agent.md) Chats belong to the agent
- [0009](0009-agent-questions-are-cards.md) Agent questions are real, answerable cards
- [0010](0010-json-files-for-sessions.md) A JSON file per session until that stops being enough
- [0011](0011-nushi-next-identity.md) The rebuild runs as "Nushi Next" beside the first build
- [0012](0012-diff-view-package.md) The diff viewer uses the published diff_view package
- [0013](0013-app-starts-its-daemon.md) The packaged app starts its own daemon, never stops one on its own (how it starts it: 0036)
- [0014](0014-moving-a-chat-forks-it.md) Moving a chat forks its Claude session through a copy of Claude's history
- [0015](0015-delete-takes-the-agents-history.md) Deleting a chat deletes the agent's history of it, through ACP
- [0016](0016-a-worktree-per-chat.md) A chat can have a git worktree of its own
- [0017](0017-context-breakdown-from-claude.md) The context card reads Claude's /context output
- [0018](0018-the-app-is-nushi.md) The app is Nushi
- [0019](0019-changes-read-only-toward-git.md) The Changes view is read-only toward git
- [0020](0020-rewind-through-a-vendor-fork.md) Rewinding forks the session at a message through a vendor extension
- [0021](0021-claude-config-is-the-mcp-source.md) Claude's own config is the source of truth for MCP servers; Nushi changes it only through the `claude mcp` CLI
- [0022](0022-the-daemon-owns-terminals.md) The daemon owns terminals; they are local-only until remote access decides otherwise
- [0023](0023-warn-before-a-folder-runs-code.md) Warn before a folder's own code runs (hooks, helpers, `.mcp.json` servers) unless Claude or Nushi trusts it; never refuse
- [0024](0024-the-agent-can-read-the-token.md) The agent can read Nushi's token file; no same-user protection is worth its cost (amends 0005)
- [0025](0025-claude-rules-in-one-place.md) Claude's rules live in `internal/claude*`; the chats feature takes a `Dialect` that `main` fills
- [0026](0026-the-transcript-lays-out-every-item.md) The transcript lays out every item, not a lazy list
- [0027](0027-what-lives-only-in-memory.md) What lives only in memory, in the daemon and the app
- [0028](0028-agents-get-the-login-shells-environment.md) Agents get the login shell's environment, through the daemon's; Nushi doesn't read or filter it
- [0029](0029-warn-before-a-folder-runs-code-for-codex.md) Warn before a folder's own code runs, for Codex too; "Start anyway" is kept per agent
- [0030](0030-our-own-bridge-for-ante.md) Ante runs through an ACP bridge of Nushi's own (`nushid ante-acp`), not `ante-acp`
- [0031](0031-warn-before-a-folder-runs-code-for-ante-and-omp.md) Warn before a folder's own code runs, for Ante and omp; the files are read by `internal/folderfiles`
- [0032](0032-idle-chats-sleep.md) Idle chats sleep: their agent stops, a message wakes them through `session/load`; a chat that couldn't reopen isn't asleep, and showing it tries again
- [0033](0033-the-relay-is-a-dumb-pipe.md) The relay is a dumb pipe that keeps nothing; what it can still see (replaces 0006)
- [0034](0034-noise-between-phone-and-daemon.md) Noise (IKpsk1 to pair, IK after) between the phone and the daemon; pairing by QR code; a paired device is a full client; the threat model (replaces 0006, amends 0022)
- [0035](0035-open-sessions-started-elsewhere.md) Sessions started elsewhere (a terminal) open as chats through `session/load`, not copies; forks left out; open elsewhere: warn where both can write, not offered where the agent allows one writer
- [0036](0036-the-daemon-is-a-background-helper-app.md) The daemon is a background-only helper app (`Contents/Helpers/Nushi Daemon.app`) the app opens through Launch Services; Start at login is a launch agent that opens it too; no KeepAlive (amends 0013)
- [0037](0037-agents-you-set-up.md) Agents are found on PATH, read-only; an adapter is set up only when asked, from our own lockfile, into the data folder; agents run the user's own CLIs; no npx (supersedes part of 0003)
- [0038](0038-logs-you-can-debug-from.md) Logs you can debug from: slog's text format, a line per thing that happened with the chat's attributes, rotated by the daemon, the app's errors in it; never what the user wrote
- [0039](0039-our-own-bridge-for-pig.md) PiG runs through an ACP bridge of Nushi's own (`nushid pig-acp`) on its RPC mode, not `pig-acp`; no trust card (PiG's own trust gates what a folder loads)
- [0040](0040-strict-linting.md) Strict linting: every golangci-lint linter on unless listed off with why, and govulncheck, pinned in `tools/lint/go.mod`; very_good_analysis under strict Dart analysis; `make lint`, `make check` and CI
- [0041](0041-acp-through-acp-go.md) Agents speak ACP through `github.com/afrase/acp-go`, Nushi's client grown into a library of its own; Nushi uses its unstable package at a tagged version; what is Nushi's (logging, the fake agent) stays in Nushi
- [0042](0042-jira-cloud-through-our-own-client-tokens-in-the-keychain.md) Jira Cloud through a thin client of Nushi's own in the daemon (classic or scoped API tokens, Markdown both ways through ADF); tokens in the login keychain through the Security framework, never prompting unless the user asks; nothing reaches Jira unless asked
- [0043](0043-an-mcp-server-of-nushis-own-for-a-chats-tools.md) A chat's agent gets Nushi's tools through `nushid tools-mcp`, an MCP server over stdio with a key per chat that grants that chat's tools only (Jira's for its issue); the harness asks before they run
