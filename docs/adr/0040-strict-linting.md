# 0040. Strict linting: every golangci-lint linter on unless listed off with why, and govulncheck, pinned in their own module; very_good_analysis and strict Dart analysis; CI runs both

## Context
Nushi had no Go linter: `go test`'s few `go vet` checks were all, and the Dart side had only `flutter_lints`, with `flutter analyze` run nowhere. A broad golangci-lint run found about 800 reports (errcheck 405, gosec 102, revive 65, contextcheck 37…). The owner runs Go strictly: many linters on, each exclusion there for a stated reason, and normally govulncheck and, for Dart, very_good_analysis too (added after the first pass, steps 180–186).

## Decision
- **golangci-lint 2.15.0, pinned in `tools/lint/go.mod`** with a `tool` directive, run as `go tool -modfile=tools/lint/go.mod golangci-lint` (since [0041](0041-acp-through-acp-go.md) built from it into `bin/`, as `-modfile` can't run beside a `go.work`): nothing on PATH or installed globally, and the daemon's `go.mod` doesn't take its dependencies (about 200 modules). In `tools/lint`, not `tools/`: a `go.mod` in `tools/` would cut `tools/icongen` out of the main module.
- **`.golangci.yml`: `default: all`**, and every linter off is listed with its reason (style that fights the code, rules that don't fit it, linters that need configuration this repository has no use for). gofmt and goimports format; gofumpt doesn't (it rewrites the compact composite literals in 60 files and checks nothing that matters).
- **A wrong report is marked where it is**: `//nolint:<linter> // why`, which nolintlint enforces; in Dart `// ignore: <rule>` under a comment saying why (nine: seven `close_sinks` on sinks handed to their owner, a switch on a protobuf enum that keeps its `default`, and the marks' path data in adjacent strings, for the file). A path exclusion only where a whole package is about what the linter reports (tests' temp files for gosec, the API's proto conversions, internal/git running git), each with its reason in the config.
- **gosec's G204 and G304 aren't excluded wholesale**: starting processes and reading files at paths is what the daemon does, so each is checked and marked.
- **govulncheck 1.9.0, pinned beside golangci-lint** in `tools/lint/go.mod` and built into `bin/`. `make lint` runs it over the main module (the daemon, the relay, the tools) and over the lint tools themselves; it fails on a vulnerability our code calls. A standard-library one is fixed by the `go` line's patch version (`go 1.27.3`: the go command fetches that toolchain, setup-go reads it on CI), a module's by `go get`; an advisory with no fix goes in NOTES.md with its id.
- **Dart: very_good_analysis as the base**, in place of `flutter_lints` and `lints`, in the app and every package; then `analysis_options.yaml` at the root, which wins where they differ: very_good_analysis has the strict casts, inference and raw types and 48 of the first 54 rules; the root keeps five of the other six, and close_sinks reported (very_good_analysis ignores it). Off, each with its reason in the file: `prefer_int_literals` (its fix broke a double), `unnecessary_await_in_return` (very_good_analysis's `async_return_with_no_await` asks for the opposite), and in the app only `public_member_api_docs` (it isn't a library). The rules step 166 had left out as style (one declaration a line, cascades, named booleans, sorted dependencies, no reassigned parameters…) are on with the rest: `dart fix` did most of it, and `lines_longer_than_80_chars` doesn't fight `dart format` (only long strings were over, and they split).
- **`make lint`** runs golangci-lint, govulncheck, `buf lint` and `buf format`, `flutter analyze` (infos fatal) and `dart format`; `make test` stays tests only; `make check` runs both. CI (`.github/workflows/ci.yml`, actions pinned by commit) runs `make lint` and `make test` on macOS, and the portable packages' tests on Linux.

## Consequences
- A new linter report fails `make lint` and CI: fix it, or mark it with the reason.
- About 125 `//nolint` directives, most of them gosec's on process starts and file reads (each says why that one is fine), errcheck's on read-only closes, and contextcheck's on functions that rightly start their own context.
- `make lint` needs the network: govulncheck asks vuln.go.dev. A new advisory can fail it, and CI, with no change here: bump what it names, or note it.
- Upgrading golangci-lint is a change of `tools/lint/go.mod` (`go get -tool …@vX` there); new linters arrive on with `default: all`, so an upgrade may need fixes or new reasons.
- A very_good_analysis major brings new rules (`^11.0.0` holds it until then); 11.0.0 brought the `new` constructor form (`unnecessary_type_name_in_constructor`) and package imports.
- Rejected: a global or Homebrew golangci-lint or govulncheck (not pinned, and on PATH); their dependencies in the main `go.mod`; excluding tests wholesale from errcheck; very_good_analysis's own list copied into ours (it would drift from the version pinned).

## Amendments
- 2026-10-27 (step 344, the owner: "I don't think CI should take that long"): **CI runs the parts in parallel.** `make lint` is `lint-go` and `lint-dart`, `make test` is `test-go`, `test-packages`, `test-app` and `test-web`; `make check` still runs them all. CI runs them as jobs, about 3 minutes in all instead of 12: Go's lint and tests, the web app's end-to-end test and the app's tests (two shards of test files, `SHARD=i/2`) on macOS, the rest on Linux (`ci.yml` says why each runs where). The app's goldens stay on macOS: on Linux 173 of 471 tests differ by 1–4% (text rendering), past the 1% CI allows. Caches: the lint tools as built, golangci-lint's results, the Go module and build caches per job, pub's, and Flutter's SDK without the engines tests never use (0.9 GB, not 2.1). Measurements: `docs/history/perf-2026-10.md`.
