# 0094. The preview pane has browser tabs, for local web servers and then any site

Status: accepted, 2026-11-06.

## Context
The owner wants Claude desktop's browser beside the chat: look at the dev server the agent started while the chat goes on. The preview pane already shows an agent's pages, but only files, and a link out of one opens the default browser (ADR 0068). A dev server is a page at an address, which keeps its own history and moves as it's used, so it isn't a file.

## Decision
- **A browser tab is a preview tab** (ADR 0070): the pane's tabs hold files and browser tabs in the order opened (`PreviewEntry`: `PreviewFile` or `BrowserTab`). One pane, its width, Close (every tab) and ⌘W stay as they are. A browser tab is never matched to another: each open is its own.
- **It looks like Claude desktop's** where Nushi's rules allow: a + at the end of the tab row opens a new browser tab, shown only while a browser tab shows (a file's tabs keep plain names and nothing else); under the title row a bar of Back, Forward, Reload and the address field; the tab named for the page's title. A new tab is its address field and "Enter a local address, like localhost:3000". The chat header's globe (a drawn line icon, ADR 0072) shows the last browser tab or a new one, and pressed while one shows hides the browser: its tabs are put away at their addresses (a file's tab left shows, else the preview closes) and come back as it's pressed again, as the Files button shows and hides its pane; it folds into ⋯ first when the header is tight. The palette and File have New browser tab.
- **Local pages only, at first** (amended below: any site). The main frame loads http or https to this Mac (`localhost`, 127.0.0.0/8, `::1`) and `about:blank`. Another site, or a mail address, opens in the default browser only on a press: a typed address (Return is the press), or a link within a second of a pointer's press in a web view (ADR 0068's rule less its keys: people type into a local page's forms, and a Space or Return there reaches the page's script first), so a page can't open the browser on its own. `file:` goes nowhere, frames included: files belong in a file's tab. In the main frame every other scheme goes nowhere too; a frame inside a local page loads what it likes but a file, as in a browser. Any site follows, the owner having said yes (2026-11-06; docs/roadmap.md).
- **The web view is WebKit's defaults, less windows**: no script message handlers or JavaScript channels, so nothing from a page reaches Nushi; `javaScriptCanOpenWindowsAutomatically` off, and a link with a target loads in the tab (the plugin's way). It shares WebKit's default data store with file previews and diagrams, the only one the plugin reaches (docs/security.md).
- **⌘L and ⌘R are menu items** (File › Open Location…, View › Reload Page) as well as the app's keys, so they work while WebKit has the keys: AppKit gives a key the web view doesn't take to the menu bar. They apply only with a browser tab in sight and no dialog up. Jira's and GitHub's ⌘R stay theirs: their views bind it below the app's keys, and the acts don't apply there. ⌘[ and ⌘] stay chat switching; Back and Forward are buttons.
- **One view at a time**, as ADR 0070 has it: a browser tab's page loads again from its address when its tab shows, its history gone.

## Consequences
- Switching tabs or chats reloads a page and loses its state and history; an app-wide keep-alive of a few views is the next step (docs/roadmap.md).
- Until the pane draws its own, a page's dialogs get the plugin's answers (an `alert` shows nothing, `confirm` is no, `prompt` is empty), and a self-signed certificate or basic auth gets WebKit's default handling, which fails; the swipe back is the app's, not the page's.
- A page's camera and microphone requests are refused (the plugin's default would ask macOS, and the app declares neither); a location request gets WebKit's default, untested.
- A page's title is read when its address changes and when it finishes loading; a single-page app that only changes its title isn't seen (the plugin has no title observer).
- Nothing opens a browser tab for the agent yet: `show {url}` and the dev servers are later work.
- Amended 2026-11-06 (the owner: a tab may browse any website, and was surprised it couldn't): the main frame loads http or https to any host, typed or followed (a link, a redirect, a script's `location`), and `about:blank`. `file:` still goes nowhere, and so does every other scheme in the main frame but mail, which opens its app only on a pointer's press. The field keeps a typed http or https, makes `example.com` https, and makes this Mac, an IP address, a `.local` or `.localhost` name and a single name with a port (`devbox:8080`) http, as servers there seldom have a certificate; it searches nothing, so other text gets a note. A new tab says "Enter an address, like example.com or localhost:3000". Plain http loads: App Transport Security exempts web content (`NSAllowsArbitraryLoadsInWebContent`), which reaches every web view of the app, and file previews keep their main frame on their file. File previews share WebKit's store with the tabs, and WebKit takes a `file:` page's frames as first party, so a preview now sends and keeps no cookies: a page the agent wrote can't act on what a tab signed in to (docs/security.md). A page over http from another machine has "Not secure" in the bar (this Mac's own pages don't leave it). A certificate WebKit refuses fails the page with no way past it, the pane saying the certificate of the address that failed isn't valid, over WebKit's reason; a self-signed one on this Mac too, until the pane can ask. The bar shows the page on screen, not where a navigation is headed: WebKit's URL (the plugin's only report) is a navigation's from its start, so a page could start one to a site that never answers and keep its own form up under that site's name. The address moves when a load commits (the Swift side stands in front of the plugin's navigation delegate for `didCommit`; a tab that can't have it loads nothing) and, between commits, only within the page's origin (its history, a fragment). An address with a user name (`https://bank.example@evil.example`) loads nothing, typed or followed, and the bar never shows one. Out of the field's focus the bar shows the host apart from the rest, without the scheme, and a host too long for the field loses its start, not its end. There is still no other store, no private window and no Clear browsing data.
- Amended 2026-11-06, as Claude desktop's browser does it (the owner's screenshots): out of the field's focus the bar shows the host alone, centred (its port too, its start cut when too long); in the focus, the whole address. At the field's right end a box-with-arrow button opens the tab's page in the default browser, its tooltip naming that browser ("Open in Google Chrome", the app macOS opens https with; "Open in your browser" when it can't say); a new tab and a blank page have none. A typed `file:` address of this Mac (`file:///…`, `file://localhost/…`) or a path from `/` opens that file's preview, a file's tab beside the browser tab, under the preview's own rules (the daemon decides what shows); a page's `file:` link still goes nowhere. A web link clicked in a chat (its messages, its tool calls' output) opens in a new browser tab beside it, with Settings › General's Open links in built-in browser on, as it is at first (Claude's default); off, or in a window too narrow for the pane beside the transcript (it would lie over the box), or with a user name in it, the default browser has it, as do links outside a chat (Jira, GitHub, the phone). `openWebLink` is the one place: `AgentMarkdown`'s links go through it, after its check that a link's text names the address it goes to. A site can't reach this Mac or the local network through a tab (loopback, `*.localhost`, 0.0.0.0/8 and `::`, 10/8, 172.16/12, 192.168/16, 169.254/16, fc00::/7, fe80::/10, IPv4 in IPv6, `*.local`), as Chrome's Private Network Access would have it and WebKit has nothing for: a content rule list on the tab's web view blocks every load of such an address, frames, scripts, images, fetch, XHR and WebSockets, `unless-top-url` the page on top is at one itself (a dev server keeps the whole network) or at a site let through; it goes on before the tab's first load, and a tab that can't have it loads nothing. A main frame's load counts as its own top page to WebKit (a probe app, 2026-11-06: a site's script sent the main frame to localhost past the rules), so the tab's navigation rule drops a site's page going to a local address unless the user asked for that load, and the pane says so; a click on a page's link there counts as the page's. An ask is bound to the load it names, within a second: the address typed, or the history item Back, Forward or Reload goes to, of WebKit's kind for it (`NavigationSource`), so a page's script navigating meanwhile can't take it. A navigation comes from the page last committed, not an address typed and still loading, and a server's redirect from the address that redirected; WebKit says which navigations are redirects only privately (`_isRedirect`, which `CommitWatch` reads where it's there; without it a navigation while a load is let go is judged by the stricter of the page on screen and that load, as it may be either's). A list of sites let through that changes twice quickly puts on only the last: an older list compiled after it is dropped. The sites let through are a list of hosts in `app.json`, each an `unless-top-url` exception; the ⋯ menu that changes it follows (docs/roadmap.md).

- Amended 2026-11-06, after the owner tried v0.14.0 ("I see no options like Claude desktop. Just make it look more like that"; their screenshots of its browser, measured for proportions, drawn in Nushi's theme). The title row's tabs are chips, as Claude's: a rounded fill on the one showing (a tint under the pointer on the others), a globe, the title and a ✕, the + after them; a file's tab beside a browser tab is a chip too (its kind's icon, its name in the code face), so the row reads as one, while files alone keep ADR 0071's plain tabs. One browser tab is a chip as well, where its title was. At the row's right end ⋯, Expand and Close. The bar is the header's height, with larger drawn Back, Forward and Reload, and the address field a rounded, filled box with a fine border, the host centred in a larger size and Open in inside its right end with its own tint. The ⋯ menu is Claude's, in its order and words where they apply: Save screenshot (WebKit's snapshot of the part in sight, a PNG saved where the save panel says); Open links in built-in browser, checked as the setting is; Manage allowed sites…, the sites let through the local-network block, each removable (Claude's list is also of sites its agent may drive; Nushi's agents drive no pages, so it's this one); Local network access with the site's state beside it and, under the site's name (the page may move while the menu is open, and the rows follow it), Blocked or Allowed for this site, fixed at Allowed for a page on this Mac or the network (it always reaches it) and at Blocked for a host a rule can't hold, absent on a new or blank tab; under Cookies, Clear browsing data in red, which asks first, then removes every site's data from WebKit's default store and reloads the page. Claude's Import cookies is left out: it would mean decrypting another browser's stored logins. The ⋯ stays tinted while its menu is open and is reached from the keyboard as the app's other menus are. Expand gives the pane the whole chat area under the chat header (`Beside.cover`): the transcript, the box and the other panes stay laid out but aren't drawn or reached, so the page isn't made again; Collapse, Esc while Flutter has the keys in the pane, a file's tab, the browser hidden, another chat or the Changes tab put it back.

## Alternatives considered
- A browser as its own place, beside Chat and Changes: the owner rejected file tabs in the header (ADR 0070), and the page is wanted beside the chat.
- Any http(s) site in the tab now: logins would share WebKit's store with file previews, and a local page could send the tab anywhere; the owner wants it, and it follows as its own change.
- Back and Forward on ⌘← and ⌘→: in a field inside the page they move the caret, and the menu can't tell.
