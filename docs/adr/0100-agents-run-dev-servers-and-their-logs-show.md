# 0100. Agents run a folder's dev servers by name, and a server's output shows in a drawer

Status: accepted, 2026-11-08. Amends [0098](0098-the-daemon-runs-a-folders-dev-servers.md) (agents start servers) and [0068](0068-an-agent-opens-a-preview.md) (`show` takes a url).

## Context
ADR 0098 ran a folder's dev servers on the user's ▶ only and left for later what Claude desktop also has: its agent's `preview_*` tools, `show` of a page rather than a file, and a server's output to read. A failed server showed its last lines in a tooltip; a running one showed nothing, and the agent ran its own servers through Bash, unseen by the Servers menu. The owner wants Claude desktop's behaviour (docs/facts/claude.md has what's known of it), the resolved command on the agent's permission card only ("card only", 2026-11-06), and nothing of it on the phone (no use case, 2026-11-08).

## Decision
- **The daemon keeps a server's output.** While it runs, its terminal's scrollback (`internal/terminal`, 1 MB) holds it; once it ends, the last 256 KB of it as written stay with the server, as its 200-line tail for the row's tooltip does, for the five ended servers a folder keeps (`servers/log.go`). Nothing of it is logged or written to disk.
- **`WatchServerLog {chat_id, server_id}`** (API 111) streams it: the last 256 KB, raw (escapes and colours kept, a character or an escape possibly cut in two), then what the server writes as it comes, then `ended`. A server that ended sends what it kept and `ended`. `DevServer.log_id` names the server whose output it is: the running one's once its program started, else the last one's that ran, failed or stopped; empty when none (one that never started has none). It is macOnly and checks the Mac's socket, as the other server calls.
- **The logs drawer** (the app's): each row of the Servers menu with a `log_id` has Logs, which opens a drawer docked at the bottom of the browser tab's pane, with the server's name, port and state, Stop (solid red, as the menu's) while it runs, and a close. It draws the bytes with the terminal view's renderer, read-only: ANSI colours, no input, no link opening on its own, and no OSC sequence acting on the app (title, clipboard, hyperlinks). It keeps to the bottom unless the user scrolls up. A failure's tooltip ends by pointing to Logs. The browser pane, not the chat's terminal area: the Servers button is on its bar, the page the output explains is beside it, and a server is its folder's, while the terminal area holds the chat's own shells, which take input.
- **The agent's tools**, a `tools.Set` beside `show` on Nushi's MCP server (so Claude and Codex, the harnesses with `ClientMCP`), with Claude desktop's names: `preview_list` (the chat's folder's entries as JSON: name, state, port, url, source, problem, error), `preview_start {name}`, `preview_stop {name}` and `preview_logs {name, lines?}` (plain text, the escapes stripped, the last `lines`, 100 unless given, 500 at most, 32 KB at most). The folder is the chat's folder or worktree, as for the Servers menu; a side chat's is its chat's. A name is an entry's written name, matched without case, and must be fit for the agent's text (ADR 0095's pattern: 64 bytes, no NUL); an entry whose name isn't is only counted in the list. No tool takes a command (ADR 0098's rule). Refusals are fixed text, Claude desktop's codes leading where it has one (`launch_config_missing`, `launch_config_name_not_found`); a failure that quotes the launch file or the server's output goes to the agent whole and to the log as its kind alone (`tools.Logged`).
- **`preview_start` waits** up to 30 s for the server to answer or fail and says which, with a failure's reason and last lines. A server it started, once it answers, asks the Mac to show its page beside that chat (`show_url`, below), at once if it already answers; the user's ▶ shows nothing this way (the app opens what it asked for, ADR 0098).
- **The harness asks; the card says what runs.** The tools list no annotations (ADR 0068's reason). When the ask to run `preview_start` comes, the daemon resolves the named entry as the start would run it (its `env`, the program on the login shell's `PATH`, its arguments, each quoted so a control or bidi character shows) into the ask's `Item.server_command`, and keeps that entry's hash: the start that follows runs only that entry as shown, and is refused, once, if the file changed it since. With no ask (the user allowed the tool), it runs the entry as the file says.
- **`show` takes `path` or `url`**, exactly one. A url must be http or https to this Mac's loopback (localhost, a `*.localhost` name, 127.0.0.0/8 or `[::1]`), any port and path, no user name, no space, control character or backslash, its host read as a browser reads it (`launchfile.LoopbackURL`: IDNA's mapping, IPv4's number forms, a trailing dot and IPv4-mapped addresses refused). The daemon sends the url as it read it in the `show_url` event (no seq; only the Mac acts), and the app opens a browser tab (ADR 0094) under ADR 0068's showAsked rules: only while that chat's Chat tab shows, never moving the user. The row reads "Showed <url>" with Open. Anything else is refused with fixed text.
- **The phone gets none of it**: the calls are macOnly, and its app ignores `show_url` as it does `show`.

## Consequences
- An agent allowed `preview_start` for good runs any entry of the launch files unasked, and it can write those files itself: the card and its hash bind only a run that was asked about. That's the reach Bash already has under the same allow.
- The drawer shows a server's output since the daemon started it; a daemon restart loses the output with the servers (ADR 0098 starts nothing again).
- An ended server lets go of its terminal and keeps its log alone: 256 KB at most each, five a folder, dropped with the folder (its last chat archived or deleted, its worktree removed).
- Claude desktop's parameter shapes beyond the names aren't in docs/facts (only its error codes are); the tools take `name`, and are to follow its shapes once they're seen.
- Ante, oh-my-pi, Pi and PiG take no client MCP servers and still run servers through Bash, unseen by the menu (docs/roadmap.md: spotting them).

## Alternatives considered
- Attaching the terminal view to the server's pty through `AttachTerminal`: servers aren't the chat's terminals (`Terms`), and that call's siblings write and resize; a stream of its own is read-only by construction and still feeds the same renderer.
- Output as events on `Events`: every client, the phone too, would get every server's output.
- `preview_start` answering at once: the agent would poll `preview_list` to learn what the start already knows.
- `show {url}` for any site: browser tabs load any site since ADR 0094's amendment, but the agent's page beside the chat is meant for what it built here; a site is a link in its message, opened by a press.
- The phone's list with Run and Stop (ADR 0098's later): the owner sees no use for it now.
