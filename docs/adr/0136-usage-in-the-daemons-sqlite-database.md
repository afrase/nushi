# 0136. Usage in the daemon's SQLite database

Status: accepted, 2026-11-20.

## Context
The owner wants a Usage page: what the agents spent and the tokens they used, by day, agent, model and project, mostly as API pricing sees it, and an account's limits where an agent says them. Nushi kept none of it: a chat showed its session's cost and last turn's tokens, and forgot them. Every agent that reports a cost (Claude, Pi and PiG, omp, OpenCode) reports the session's total so far, not the turn's; Claude's isn't reliable across processes and starts again near zero after a fork (`docs/facts/claude.md`). Codex and Ante report tokens and no cost. Sums over ranges and groupings are a query's work, not a JSON file read whole.

## Decision
- **The daemon's first database** is SQLite through `modernc.org/sqlite`: SQLite translated to Go, so the Linux and Windows builds stay without cgo; queries do the sums; later features add their tables to it. DuckDB was rejected: cgo, and a far larger binary. One file, `nushi.db` in the data folder (0600), WAL with a busy timeout; `PRAGMA user_version` and a list of steps (`internal/database`) migrate it. Settings and chats' records stay JSON (`internal/store`). A database that won't open or write is logged, and chats go on without usage.
- **A row per turn** (`turns`): when it ended, the stored chat's id (a side chat's turns count toward its chat, marked side), the agent, the model (what Claude's usage names, `_claude/model`, else the chat's model option; may be empty), the project folder (a worktree chat's repository's, as the sidebar groups chats), the prompt's four token counts, the turn's cost and currency, whether the agent reports a cost at all, and the session total it was measured against. A turn ends in four places, each recorded: the prompt's answer (`turn`); a held turn's work ending while the agent keeps its prompt for background subagents (`released`: its cost) and that prompt's late answer (`held`: its tokens, not counted as a turn of its own); and the agent's own turn after a background task (`own`: its result's cost, no tokens, kept only if something moved).
- **Cost per turn** is the session's total now less the last total measured for the same session, kept per chat in memory and read back from the chat's last row after a restart. A lower total (a new process, a fork that started again) counts whole, never negative. A fork's first figure (a side chat, a fork made a chat, a kept side chat) is measured against the total of the chat it came from: one that carries that total counts only what's past it, and Claude's, which starts again near zero, is lower and counts whole. A chat older than the database, with no row yet, takes its first figure as the start, not as spent. Rows are written by the usage feature's own goroutine, batched; a turn never waits for the disk (a full queue drops, said once).
- **Not counted**: throwaway forks (the Context widget's `/context`, a commit message's) and workflows' agents, which never reach a chat's turn; their cost shows in the session's next total only where the agent folds it in. A total that drops but then passes the last figure within one turn undercounts that turn (the drop is unseen); a rewind of an agent whose forks carry the earlier part's cost counts that part again.
- **Limits** are only what an agent reports of itself: Claude's `rate_limit_event`, passed on as `_meta._claude/rateLimit`, read leniently through the harness's `UsageReader`, so another agent's (omp's `_omp/usage`, Codex's) plugs in beside it. The latest of each agent's limit of each kind is kept (`limits`), with when it was seen. Nushi holds no login or token for it and asks no service.
- **The API** is one call, `GetUsage(from)`: totals, days in the daemon's zone (the Mac's, the only caller), agents, models, folders, the 20 costliest chats with their titles, the agents that reported no cost, the first turn kept and the limits. The Mac's only: the page names folders and titles, and the phone has none.
- **The page** is Settings › Usage (the Mac's): a span of days ending today (7, 30, 90 or all), its tokens being input and output only, the cache's read and written shown apart (cache reads are most of Claude's tokens and cheap); with no cost reported in the span it leads with tokens and shows no $0.
- **History**: every row is kept, deleting a chat keeps its rows (shown without a title), and nothing is pruned. No backfill: Claude's transcripts hold each assistant message's API usage and model with its time, but no cost; Codex's rollouts hold cumulative `token_count` events. A later backfill could read those and price tokens itself.

## Consequences
Usage starts at the upgrade; older chats count from their next turn. Turns while the daemon was down, or run in a terminal, aren't seen. The binary grows by SQLite's Go translation.

**Amendment (2026-11-23):** GetUsage takes only `from`; its `to` and `time_zone`, which no client sent, are reserved, and days are the daemon's zone, the Mac's. The costliest chats rank, after cost, by input and output tokens, as the page counts them.
