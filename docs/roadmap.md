# Roadmap

What isn't built yet and the decisions still open, each checked against the code on 2026-10-31. An entry goes when its work ships, in the same commit, and a gap is checked against the code before it's written down ([AGENTS.md](../AGENTS.md)). What's built is in the user docs, why in [`docs/adr/`](adr/README.md), October's small decisions in [`history/decisions-2026-10.md`](history/decisions-2026-10.md).

## Plans

### The app

- **A to-do list shared by you and the agents** (the owner, 2026-11-09: "I often come to the office on Monday and forget what I was working on"): one list in the app that people and agents both add to, check off and read, so the work in flight survives a weekend. Agents would reach it through tools on Nushi's MCP server, which every Claude and Codex chat already has (ADR 0068's `show`), and an item could link to the chat, folder or pull request it's about. Today an agent's plan (its own to-dos) lives only in its chat and ends with it. Mocked three ways on 2026-11-09 (https://claude.ai/artifact/E6gN5wv15nA3xGrZw5Dyz4): A, a list at the top of the sidebar; B, a page beside Jira and GitHub; C, "Where you left off", which isn't a list at all but is built from what Nushi already knows (agents' unfinished plans, uncommitted changes, branches not pushed, pull requests waiting on you, chats that need you), plus one note per folder. The owner likes C but left it for later as harder than it looks. The hard part is deciding what's still in flight: a plan abandoned weeks ago, an idle chat with old changes. The facts themselves are mostly there already, except an asleep chat's plan, git across every folder at launch, and GitHub per folder. Mac only, not the phone.
- **The empty state as a visualisation** (the owner, 2026-10-26): a gravity toy (an orrery in the empty pane) didn't look good enough and was reverted. Revisit with a fresh agent and stronger visual references (the owner has seen better ones); a prototype in an HTML artifact first, before any Flutter.
- **The jump button as Nushi's mark** (the owner, 2026-11-01, from Claude Code): while you're scrolled up and the agent works, the round mark animates in place of `JumpChip`; under the pointer it turns into the jump-to-latest arrow. Nushi's icon is already circular.
- **Icons for chats** (the owner, 2026-11-02): an icon of the user's choice on a chat's row, beside its color, to tell chats apart when the names blend together.
- **The phone's list, arranged** (after the Mac's sidebar got its Arrange menu, 2026-11-04, ADR 0089): Group by and Sort by on the phone's chat list. The grouping and sort are shared code (`arrangement.dart`'s `groupChats`, `sortChats`); missing are a control in the phone's header, the choice kept in the phone's own storage (`platform_web.dart`, as its theme is), and how its Needs you group fits beside a Status grouping.
- **Opt-in metrics and crash logs** (the owner, 2026-11-01): off unless you turn them on, with nothing sent before that. Stack traces and counts only, never prompts, paths or tokens; what's collected is written down.
- **A redesign** (the owner, 2026-10-26): a fresh look at the whole app, not piecemeal fixes. Scope it with the owner first: what feels wrong, and which apps' look to learn from. Pass one, the shapes, is done (2026-11-11, [ADR 0110](adr/0110-corners-come-from-the-theme.md)): every corner is one of the theme's radius tokens and their values are rounder. Pass two, the frame, is done (2026-11-11, [ADR 0111](adr/0111-surfaces-and-floating-panes.md)): the surfaces as tokens in every theme, the main area a floating pane, the sidebar on the window's background with the status card at its foot, and the chat's header. Pass three is done (the same day, the same ADR): the transcript's rows and cards and the composer, and the details back inside the pane, flat, after the owner saw them as cards beside it. Left, each restyled from ADR 0111's rules (its Still owed list): the details' widgets' contents, Changes, then Settings (its theme preview still draws the old tool rows), Jira, GitHub and Chat history, then dialogs, menus, popovers and the secondary button, the side panes' own parts, and the phone's details. Open with the owner: moving the Mac's traffic lights to the mock's place (native work, to be looked at on a real window), and the sidebar's projects as tiles with a rail. The fonts stay.
- **What the Linux app still lacks** (the owner, 2026-10-27; the app runs there since ADR 0104, checked end to end only under Xvfb in a VM):
  - web views: WebKitGTK behind `PageHost`, `BrowserHost` and `DiagramHost`, a custom URI scheme for a page's root and WebKit's decide-policy signal for what a press opens, as WKWebView does on the Mac; until then a page's preview and a browser tab are placeholders that open the default browser (the owner's direction), and a diagram shows its source;
  - diagrams without a web view: Mermaid run in the default browser (a page of the diagram with the pinned mermaid.js beside it), which means shipping mermaid.js in the package (5 MB, left out for now);
  - the window's chrome drawn in the app as on the Mac, with the rounder redesign (above): for now GTK's header bar on GNOME sits over Nushi's own headers;
  - the window's size and place: it opens at 1280×800 every time, where the window manager puts it, and remembers neither (the Mac's does); at that size, with the details panel showing, what the agent `show`s stays closed (ADR 0068's narrow window) until its row's Preview;
  - packages: an AUR package (`nushi-bin`), which needs the owner's AUR account and an `AUR_SSH_KEY` secret; Flatpak (its sandbox fights a daemon that runs the user's own CLIs, and would need the desktop portals for files and links); the update card's Download opens the release's page, where a package manager's install should get a command to copy, as Homebrew's does;
  - notifications through GNotification, so a click on one opens Nushi when it isn't running (a D-Bus-activatable `.desktop` file);
  - snap browsers (Ubuntu's Firefox and Chromium) can't read hidden folders in the home, so a page in the data folder (a scratch chat's) doesn't open in them; no workaround yet (a copy where they can read it, or the page served on localhost);
  - checks on real hardware, which Xvfb can't do: GNOME's header bar on Wayland and its activation token (a notification's click raising the window), the touchpad's two-finger back swipe (its direction and how far it must go), the Ctrl keys in a real GNOME and KDE session (IBus and the desktop's own shortcuts may take some), and what the Super key does there.
- **Windows** (the owner, 2026-10-27): WebView2, ConPTY for terminals, AF_UNIX sockets (supported), Credential Manager for the keychain, nothing equal to npm's sandbox, paths and shells, which agents' CLIs run there; the daemon doesn't build for Windows yet (`filelock`, `procgroup`, `logs`, `proctree`, `agentproc` and claude-acp-go's `sessions` use Unix-only calls).
- **A modular window** (the owner, 2026-11-04): panes you can drag anywhere and arrange as you like — the transcript, side chat, subagent, preview, details, terminal — docked or split, the layout remembered. "Maybe that's a future task." Today each pane has its place beside the transcript and only its width is dragged (`beside.dart`). Claude Code's desktop app tiles them (the owner's screenshots, 2026-11-04, in the research folder's `claude-layout-*.webp`): each tool opens to the right, the next stacks below it, closing one lets its neighbour fill the space, and with all open they make a grid. The owner isn't sure they like it (not every tool should open to the right): look at it again in the window's rewrite, not before.
- **Undo after a fork** (the owner, 2026-11-05, after forking by accident from the action row): a toast "Forked into a new chat · Undo" whose Undo deletes the fork and goes back; preferred over a confirm on every fork. Left for now.
- **Panes at narrow widths**: at ~720 wide with the sidebar showing and the Files pane open, the chat column narrows to ~260 and the composer runs under the pane (seen in the Files button's renders, 2026-11-05). The panes should give way (fold the sidebar, or overlay) before the chat gets that narrow.
- **The side chat as Claude Code's** (the owner, 2026-10-29, from Claude Code's desktop app): there, Side chat is a pane of its own in the right-hand column (⌘;, from a ⋯ menu that also toggles Artifacts, Background tasks and Plan), with a tab and a short line saying what it is ("Chat about this session without touching the main thread … nothing here is added to the session"). Ours (⇧⌘B) lasts while hidden but opens apart from the details column, and says only "Ask in the side chat". Missing: a place in the details column, its empty state's line, and a look at the shortcut.
- **What's worked out from a long chat's items, past what's loaded** (ADR 0026, 2026-11-04): the Artifacts widget and the Files pane's marks of what the chat wrote know only the loaded part, so a file written early in a long chat isn't listed until its page is in. The daemon could list a chat's written files with its snapshot.
- **Find, next**: the preview has find only in its editor (ADR 0096): not in rendered Markdown (its `OutlinedMarkdown` could take ADR 0082's `TextMarks`, but needs its own marks scope, reveal and a focus to route ⌘F by), the read-only source (`SourceView`, a file that can't be edited), CSV, HTML or browser tabs. No find on the phone (the owner, 2026-11-09: the phone is for keeping an agent going while away, not reading back through chats).
- **Plain model chat** with no agent, straight to an API or gateway with a key (Nushi would own the history). Agent chats already reach a gateway through Claude's own settings (`ANTHROPIC_BASE_URL`, `apiKeyHelper`).
- **Usage limits** (session and weekly) for subscription users, if an agent exposes them; nothing shows them. claude-agent-acp 0.94.0 once put `_meta._claude/rateLimit` on a `usage_update` (`docs/facts/claude.md`), not a stable interface; the Go agent passes claude's the same way and nothing reads it.

### Previews

- **Dev servers, next** (ADR 0098 shipped the daemon's servers and the Servers menu, 2026-11-07; ADR 0100 the agent's `preview_*` tools, `show {url}` and the output's stream, 2026-11-08, with the app's logs drawer, card and tab): spotting servers an agent started in Bash or a terminal's ▷ started (`internal/listeners` is ready); Claude's quick package.json scan with Use this, and Nushi writing `.agents/launch.json` (`jsonsettings`' one-element edit); starting servers again after a daemon restart, rather than holding it; the details panel's Dev servers widget and a palette item, for when no browser tab is open; `servers_changed` when a launch file is written (the menu reads the files as it opens, and a start of an entry changed since is refused).

- **A Files view's rest** (the owner, 2026-10-27; the use case is seeing what the agent made, like Claude Code's artifacts): missing is the web view's hardening past WebKit's free defaults (the Files pane, ADR 0090, has the tree). The owner trusts what the agent writes as much as a page they'd open in a browser (2026-10-28), so the network stays on, no switch. Files are edited in the preview (ADR 0096); left for if it's used enough: backups of unsaved text, saying who changed a file, the approval card's lines, merging by hand in Compare, undo that survives a change from disk, the phone. Mocks: https://claude.ai/artifact/TP8YD5rSCSi2L28hnsdPGP (the owner liked them).

### Changes and review

- **Review comments by an agent** (from JetBrains AIR): a side chat reviews the changes and posts comments through a small MCP tool (`add_comment(file, line, text)`); they show in Changes, and those picked go to the main chat.
- **Findings, picked** (after a finding opened the chat's Changes at its line, 2026-10-26): tick a review's findings in its card and send them back to the agent ("fix these"), or show them as comments in Changes. Each finding already has a stable id (`findingIds`: its file, line and summary).
- **More git from Changes**: push, and staging by hunk ([ADR 0079](adr/0079-stage-and-commit-from-changes.md) has whole files; diff_view has no per-hunk controls yet).
- **A related worktree's pull request**: its row says "merged" only from git, so a squash merge reads "removed". A pull request could say otherwise, but finding one by branch is a GitHub call for each row, which the row's refresh shouldn't make.

### GitHub

- **A found pull request's chip** in the chat's header: the header's chip shows only the pull request or issue a chat started from; a found one gets just its tab.
- **The agent's own GitHub tools** on Nushi's MCP server ([ADR 0043](adr/0043-an-mcp-server-of-nushis-own-for-a-chats-tools.md)): a `tools.Set` scoped to the chat's pull request, as Jira's chats have for their issue.
- **GitHub, next**: stacked pull requests, notifications as a source (If-Modified-Since, X-Poll-Interval), reactions, files marked viewed, Enterprise capabilities probed, a review's inline comments kept across app restarts (quitting loses them).

### Jira

- **Jira, next**: a Data Center client (v2, wiki markup, personal tokens) behind `features/jira.Client`; review-comment tools on the same MCP server; creating issues, assigning, worklogs, remote links for a chat's PR, a "plan only" mode; `/jql/parse`; counts on the tabs; change badges from `changelog/bulkfetch`; Rovo MCP's OAuth; the token's expiry from the admin API.

### Agents

- **Agents without Node** (the owner, 2026-10-29): Claude runs through the Go agent alone since 2026-11-04 ([ADR 0066](adr/0066-claude-through-nushis-go-agent.md)), from the published `github.com/afrase/claude-acp-go` since 2026-11-05. Codex later, against `codex app-server --stdio`. omp needs no Bun as its own binary; Pi needs Node regardless. Smaller: codex-acp's `CODEX_PATH` could name the native binary past npm's 14 MB launcher (`docs/history/perf-2026-10.md`).
- **Each chat in a micro VM** (the owner, 2026-11-04, after seeing Firecracker): the agent and everything it runs sandboxed in a lightweight VM per chat. Firecracker itself needs Linux's KVM and can't run on a Mac; the Mac's counterpart is Apple's Virtualization framework, which its `container` tool and Containerization package use for one small Linux VM per container. Open: a Linux guest can't run macOS tools (Xcode, Swift for Apple platforms, Homebrew's Mac binaries), so it's a choice per chat or project, not a default; the worktree shared in (virtiofs) and what else (git config, SSH agent, the agent's login, which must reach the VM without Nushi reading it); network rules; the agent CLI installed in the image; terminals and previews reaching into the VM; start time and memory per chat. The lighter step first may be the agents' own sandboxes (Claude Code's Bash sandbox, Codex's `--sandbox`) exposed as a chat option.
- **More agents**: Gemini CLI (`gemini --acp`), goose (`goose acp`); each a `Harness` type and its own `internal/<agent>*` packages, reading its own keys.
- **Agents' folders from the login shell's environment**: the daemon finds each agent's folder from its own environment (`claude.ConfigDir`, `opencode.ConfigDir`, `CODEX_HOME`, `ANTE_HOME`, Pi's and omp's variables), while the agent starts with the login shell's ([ADR 0048](adr/0048-agents-start-with-the-login-shells-environment.md)). A variable set only in the shell then sends Nushi to another folder than the agent's: with `OPENCODE_CONFIG_DIR` or `XDG_CONFIG_HOME` there, opencode's skills switch writes an `opencode.json` opencode doesn't read. Fix it for every agent at once, reading those variables through `shellenv`.
- **Skills, next**: browsing and installing from marketplaces (`claude plugin list --available --json`, `install`), Codex's and omp's plugins' skills, Pi's and PiG's nested skills, a Reload offer after a skill change, omp's project switch (`.omp/config.yml`), New skill… linking for Claude once written (it says to use Link for Claude…), Claude's own `/skills` numbers when a chat runs (`get_skills_dialog` over the adapter, if it exposes one).
- **Per agent**: Claude's subagents' steps from session/load (their sessions replay them since 2026-10-27; dropped while the merge isn't made for them, though a chat without a copy could show them). Codex's MCP servers in the MCP view, its background terminals and subagent sessions. Ante's subagents, background jobs, `Info` notices (and its other TUI commands: `/goal` and `/rename` have ops), native `RewindSession` (upstream `ante-acp` could take the bridge's mapping). omp's `/context`, MCP servers on `session/new`, deleting its sessions. Pi's and PiG's MCP servers in the MCP view, a replayed message's images, an empty reopen (`--session-id`), `PIG_USE_PI_DIRS=1`, telling a session open in a terminal; whether Pi drops or shrinks a big image its bridge sends inline (`internal/pi/prompt.go`; unchecked, as the pi CLI wasn't installed when Ante's limit was found). opencode's (`docs/facts/opencode.md`): Nushi's tools (it calls a client's MCP tools from a script and asks nothing; below), a subagent's steps as they run (they come as `opencode/session/child_update` notifications, which acp-go drops), its background commands listed and kept through a sleep (nothing in ACP names or stops one, and only SIGTERM ends it cleanly), reading its SQLite store (a search of its sessions, a mark on one open elsewhere, subagents' and never-prompted sessions left out of Sessions →, which `session/list` doesn't tell apart), its MCP servers in the MCP view (`opencode mcp list` has no JSON form, and there's `mcp add` but no `mcp remove`), a warning when a command Nushi doesn't offer is typed by hand (it still goes out and runs unseen), that command's messages not doubled after a daemon restart (`session/load` replays its template as a second user message, then its reply, after the typed one), a mark in the chat for its compaction (nothing reads `_meta["opencode/compaction"]`, so `/compact` shows only your message), stopping it should it ever ignore SIGTERM (after the grace Nushi closes its input and kills only the agent's own process group, which its server and shell commands aren't in; never seen, and no way was found to make the real opencode do it). Opening sessions started elsewhere: Ante's forks, a search, other worktrees' sessions.

### The phone

- **Mobile, next**: an `Events` filter for cellular; tool output and diffs fetched on expanding them (the API would need an item's own call); renaming the device after pairing; a native iOS app with the Keychain and Face ID if the developer program ever works out.
- **After a revoke** (ADR 0034's 2026-11-04 amendment, the relay review's #1 and #6): the Mac shows which devices haven't moved to the new id and key yet, and the devices paired since the revoked one was last seen, with "Pair again" and "Revoke these too"; a "Revoke and reset" for a lost or stolen phone that drops the old ids at once and makes a new VAPID key (the phones subscribe again); the relay closing a replaced listener with a code of its own (4409), so the Mac warns that another holder of the id's key listens (left until the relay's listen allowlist lands, which changes the same code); a new pairing announced by a macOS notification and a push to the other devices.

## Decisions to revisit

- **Findings from review bots' Markdown** (PR redesign, 2026-10-29): opt-in, and a guess at the common shapes (the owner: "really cool but it only works for our setup"). If bots start posting structured review comments (threads, or a check's annotations), read those instead.
- **A review comment as a card while it's written**: left of the UX review's idea. Comments in Changes are kept apart (`reviews.json`) and become cards only on Send to agent; the idea was one store for both.
- **A finding's path** is taken as relative to the chat's folder, though Claude's schema says relative to the repository: a chat in a subfolder misses files outside it, and an absolute path in the worktree but outside the chat's folder isn't opened.
- **Artifact pins on the phone**: pins are in the Mac's `app.json`, which the phone can't reach. Kept by the daemon, as a chat's pins are (ADR 0064), the phone could show them.
- **Sessions the agent deleted** ([ADR 0015](adr/0015-delete-takes-the-agents-history.md)), what the check doesn't cover: another `CLAUDE_CONFIG_DIR` whose project folder for the path exists (it can't tell the configs apart), Ante and omp (their errors weren't looked at), a message typed into a chat that then goes (lost with it).
- **Tried only on some agents**: the transcript merge ([ADR 0047](adr/0047-nushis-copy-of-transcripts.md)) was tried by hand only with Claude's and the fake agent's replays; Codex, Ante, omp, Pi and PiG go through it untried, and opencode's was seen only in a reopen after a daemon restart. The real PiG, omp and Ante were run only for the facts, not against Nushi's skill switches. The real opencode was run under Nushi only on 2026-11-10 (a dev daemon, a throwaway `HOME`, a fake model), for what `docs/facts/opencode.md` says was seen through Nushi; the rest of Nushi's side was tried with the fake agent. Not reproduced there: the hang after a hand-typed command's permission, and opencode ignoring SIGTERM.
- **opencode's commands**: only `compact` is offered (`opencode.Harness.HidesCommand`), since opencode 2.2.6 answers every other command at once over ACP and then runs it unseen (`docs/facts/opencode.md`). Once opencode runs a command inside its prompt, offer them all again, the user's own included.
- **Nushi's tools for opencode** ([ADR 0068](adr/0068-an-agent-opens-a-preview.md)'s note): it gets none while it calls a client's MCP tools from its Code Mode script without asking. Hand it the server once it asks permission for an MCP tool, naming the tool and its input, and shows each call as it runs.
- **`sandbox-exec`** is deprecated but works on macOS 27; setting up an adapter (`npm ci`) relies on it.
- **Settings' Remote access** is the remote widget unchanged (its own heading under the page's) until it's redone in rows.
- **Not reproduced, so not closed**: Reload's brief duplicate message (2026-10-31: `reload_test.go` holds each item once; if it's still seen, look at what the app draws), and ? boxes for Nerd Font icons in Settings' terminal preview (how to check is under `[controls]` in the archive).
