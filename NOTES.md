# Notes

What an agent needs before working on Nushi: what it is, how to build and run it, where things are, the rules of this repository, and what's open. The history (summaries, demos, the step table) is in `docs/history/`; see "Where else to look" at the end.

## What Nushi is

A macOS app for running coding agents as chats, "a chat wrangler and a very very good diff viewer", for one user (the owner) for now. A Go daemon, `nushid`, runs the agents over the Agent Client Protocol (through the owner's library `github.com/afrase/acp-go`) and keeps them running when the app quits; a Flutter app is the window and talks to the daemon over Connect RPC on a Unix socket with a client token (API version 72). The packaged app carries the daemon in a background-only helper app and starts it when none runs; Start at login is a launch agent.

Five agents, each run as the owner's own CLI with its own login, settings and history: **Claude** (`claude` through claude-agent-acp 0.94.0, which Settings › Agents › Set up installs into the data folder with `npm ci` from a pinned lockfile), **Codex** (`codex` through codex-acp 2.2.2, the same way), **Ante** and **PiG** (through bridges of Nushi's own inside `nushid`, `nushid ante-acp` and `nushid pig-acp`) and **oh-my-pi** (`omp --mode acp` under Bun). Chats belong to the agent: its history is the source of truth, and a chat resumes in a terminal (and a terminal's session opens in Nushi); Nushi keeps a read-only copy of each transcript as shown, for what the agent no longer replays (ADR 0047). The harness owns permissions: the agent's own mode is the only control, its prompts and questions (Claude's AskUserQuestion) are answerable cards, and Nushi never answers them. Nushi is unopinionated: options and warnings, few enforced flows.

A chat has a transcript (your messages as chapter bands, tool rows, subagents, background tasks, plans), a composer with a queue (steer or send next), side questions, rewind, a chat in its own worktree, a Changes view (a diff viewer with review comments sent to the agent), terminals the daemon owns, the Context card, and sleep (an idle chat's agent stops; the next message wakes it). Before an agent starts in a folder that brings code of its own (hooks, MCP servers, extensions), a trust card shows it. Settings is a view in the chat's place (⌘,), a nav of sections, Chat history's table of transcripts' copies among them. Its MCP servers section edits Claude's MCP config through `claude mcp` and turns servers off per project; its Skills section lists each agent's skills (the shared `.agents/skills` with the agents that load each) and Claude's plugins, and turns them on and off the agent's own way. Jira (⌘J) and GitHub (⌘G) are views in the chat's place: lists, details, writes you ask for, and Start work into a worktree. Remote access connects the daemon to a relay for a phone over Noise; the phone is the Flutter app on the web, added to the Home Screen and served by the owner's relay, with Web Push from the daemon (ADR 0054). `nushid.log` is meant to be debugged from (ADR 0038).

The decisions are in `docs/adr/` (`docs/adr/README.md` is the index); the README says how to use each part.

## Build, run, test, install

- **Tools**: Go (the `go` line in `go.mod`) and Flutter on `PATH`; `make gen` needs `dart pub global activate protoc_plugin` and `connectrpc`; buf, golangci-lint and govulncheck come pinned (nothing to install). The daemon builds with cgo (Xcode's command-line tools: `internal/keychain`).
- **Dev daemon beside the installed Nushi**: `NUSHI_DATA=<folder> make run` (builds `bin/nushid`, starts it in the background on that folder unless one runs there, then `flutter run` the app), `NUSHI_DATA=<folder> make stop`. Use a short path (`/tmp/nd…`): the socket's path has a length limit. Without `NUSHI_DATA` both use `~/Library/Application Support/Nushi`, the real data. Driving the daemon's API without the app: see Working notes.
- **Checks**: `make check` (lint, then test) before every push, as CI does; `make lint` needs the network (govulncheck). `make test` is Go's tests, each Dart package's and the app's (widget tests and goldens in `app/test/goldens`, both themes; `cd app && flutter test --update-goldens <file>` rewrites them). Tests never touch the real data folder (Go tests use temp folders, app tests `FLUTTER_TEST`'s). Live tests run only with their variables set: `NUSHI_GITHUB_LIVE` (the throwaway repository `afrase/nushi-gh-test`, gh's login read in the test), `NUSHI_JIRA_TEST_SITE`/`_EMAIL`/`_TOKEN`, `NUSHI_KEYCHAIN_TEST`.
- **Install**: `make install` packages a release app (`make package`: the app, the daemon in `Contents/Helpers/Nushi Daemon.app`, signed with the first "Apple Development" identity in the keychain (or `NUSHI_SIGN`; ad hoc when there is none, and then the keychain asks again after every install), checked by `tools/check-bundle.sh`), puts it in `~/Applications`, and copies it to `COPY_TO` from `local.mk` (not committed): the owner's iCloud Downloads, so the work Mac gets it. The running installed daemon keeps the old build until it restarts: restart it only when no chat's agent runs (stop it by its PID, then `open -n -g "$HOME/Applications/Nushi.app/Contents/Helpers/Nushi Daemon.app" --args -login` as the app does, and check `nushid started … api=<n>` in `nushid.log`); otherwise say so, and the app offers "Restart daemon" when the API moved.
- **Other targets**: `make lines` (hand-written line counts), `make gen` (after editing `proto/`; the generated code is committed), `make relay`, `make web` (the phone's web app into `app/build/web`, for the relay's `-web`), `make icons`, `make adapters` (an adapter's lockfile after its version changed).
- **Debugging from the logs**: `nushid.log` in the data folder (Settings › Logs; `.1` and `.2` are older, 10 MB each), `app.log` beside it for what the app wrote while the daemon didn't answer; `NUSHI_LOG=debug` or the Settings switch for debug lines. One chat: `grep 'chat=<id>' nushid.log` (side chats name theirs); an agent's processes: `grep 'pid=<pid>'`; a recovered panic's stack: `printf '%b\n' "$(grep panicked nushid.log)"`. What each failure looks like: `docs/history/debugging-from-the-logs.md`.

## Repository map

Go, one module (`go.mod`); features declare the interfaces they need and `cmd/nushid/main.go` fills them in. Packages that do I/O are named for what they are; generic code lives outside `internal/`.

- `cmd/nushid`: the daemon's main and wiring; also the subcommands `ante-acp`, `pig-acp`, `tools-mcp` and `-login` (start through the login shell). `cmd/nushi-relay`, `relay/`, `noiseconn/`: the relay (it serves the phone's web app too, `relay/web.go`) and the Noise channel (remote access); `internal/webpush` Web Push (RFC 8291, VAPID), sent by `features/remote` (`push.go`).
- `internal/features/`: `chats` (sessions, turns, queue, rewind, move, sleep, worktrees, side chats, relays to subagents), `agents` (finding, setting up and removing agents), `trust` (the trust card), `mcp` (the MCP view), `skills` (the Skills view), `terminals`, `memory`, `remote` (pairing, devices), `jira`, `github`, `tools` (the tools a chat's agent gets through `tools-mcp`).
- `internal/api`: the Connect API (`api.Version`); `proto/nushi/v1/nushi.proto` and its generated code in `internal/gen` and `app/lib/gen`.
- Agents: `internal/claude`, `codex`, `omp` (what each adapter or CLI does; `adapter/` holds the pinned lockfiles), `internal/ante`, `internal/pig` (the bridges), `internal/*trust` (what a folder brings each agent), `claudehistory`, `claudemcp` (MCP config, its switches, `EditLocal`/`EditUser` for Claude's settings), `claudeskills` (skills and plugins), `codexskills`, `pigskills`, `ompskills`, `anteskills` (each agent's skills; `skillfile` reads a skills folder), `agentproc` (an agent's process and its ACP connection), `toolcall` (the bridges' tool calls), `acptest` (the fake agent).
- Integrations: `internal/jiracloud`, `adf` (Jira's document format to Markdown), `githubapi`, `mdwrite` (Markdown for anyone's text), `mcpserver`, `keychain`.
- Plumbing: `model` (plain shared types), `jsonsettings` and `atomicfile` (one key of a settings file, replaced at once), `store` (JSON state), `transcripts` (Nushi's copy of transcripts), `git`, `terminal`, `events`, `logs`, `npm`, `readonly` (`sandbox-exec`), `shellenv` (the login shell's environment, for agents), `folderfiles`, `filelock`, `footprint`, `sysproxy`; `internal/e2e` runs the API against the fake agent.
- `app/`: the Flutter app (`lib/`, one file per view or part: `chat_view`, `transcript`, `composer`, `changes_view`, `jira_*`, `github_*`, `mcp*`, `skills*`, `settings*` (Settings: `settings_view`, `settings_nav`, `settings_rows` for its pages' groups and rows, `settings_general`; `history_*` for Chat history)…; `lib/theme/tokens.dart` holds every color; `controls.dart` every button, menu field, link, icon button and grip, ADR 0049; `chat_keys.dart` ⌘1–⌘9, ⌘[ and ⌘]); `lib/phone_main.dart` and `lib/phone/` the phone's web app (its browser side in `platform_web.dart`), `web/` its page, manifest and service worker, finished by `tools/webbuild`. `packages/`: `markdown` (streaming Markdown, `markdown_view`), `uds_transport`, `noise`, `remote_transport`, `svg_path`. `diff_view` is a pub package of the owner's.
- `tools/`: `lint` (the pinned lint tools' module), `icongen`, `adapters.sh`, `check-bundle.sh`. `docs/`: ADRs, brand, facts, history, user notes.

## Working rules for this repo

- **Steps**: work is numbered in steps, one commit each on `main` ("Step N: …"), pushed after `make check`; never force. Number from the one after the last `Step` commit (`git log --grep '^Step' -1`). Each step adds its row to `docs/history/steps.md` (`make lines`), and a milestone adds its summary to `docs/history/summaries.md` (newest first) and its demo to `docs/history/demos.md`.
- **Size tripwires**: about 500 changed lines a step (tests included, generated code not) and about 400 lines a source file. Crossing one is allowed: say what pushed it in the step table's list and the milestone's summary, and split a file along its seams when it grows past.
- **The API** is additive only (ADR 0004): a change bumps `api.Version` in `internal/api` and `apiVersion` in `app/lib/daemon.dart`; an older daemon gets "Restart daemon".
- **Docs**: an ADR for a decision someone might undo (`docs/adr/`, a page at most, one line in its README), never restated elsewhere; an open product question goes under Decisions to revisit; a security-sensitive change under Security notes; a new dependency under Dependencies; a vendor's behaviour in `docs/facts/`.
- **Lint exclusions** (ADR 0040). A report wrong for one line: `//nolint:<linter> // <why>` on it, or on the function's line when it covers the function (contextcheck's mark on a function that rightly starts its own context stops the report spreading to callers); nolintlint refuses one without both, or one that silences nothing. Exclude by path in `.golangci.yml`'s `exclusions.rules` only where a whole package or kind of file is what the linter reports on (tests' temp files for gosec, the proto int32s), with a comment why; `disable` a linter only when it doesn't fit the code at all, the reason on its line. No comment needed for `_ = json.Unmarshal(…)` on an agent's payload (best effort; what's missing stays zero) or `defer f.Close() //nolint:errcheck // read-only`. Dart: `// ignore: <rule>` below a comment saying why, `// ignore_for_file:` when the whole file is about it; a rule that doesn't fit goes `false` in `analysis_options.yaml` with the reason. govulncheck: a standard-library finding is fixed by the `go` line's patch version (`go.mod` and `tools/lint/go.mod`), a module's by `go get` of the fix; one with no fix goes under Security notes with its id.
- **Never use the owner's credentials** in tests (fakes instead), except where a milestone's prompt allows it; never print, log or store a token; never erase or set the owner's fish variables (`env -u` keeps one out of a child). Don't drive the app with clicks or keys while the owner may be at the screen: test through the daemon's API, widget tests and goldens.
- **UI is looked at, full size** (the owner, 2026-10-27, after the GitHub bar's buttons floated mid-bar in a wide window): render every view you build or change at real sizes (Mac: ~1700 and ~720 wide; phone: 390×844, 430×932, landscape) and read the PNGs before reporting; assert key positions (a bar's trailing buttons at its edge, nothing clipped). In a `Row`, never a `Flexible` beside a `Spacer` (it takes half the free width): put the flexible part in an `Expanded` row of its own (`github_wide_test.dart`).

## Decisions to revisit

Open questions; what's settled is in `docs/adr/` or the code. Brackets name the milestone that made each.

**GitHub** (ADRs 0045, 0046)
- [AF] A view in the chat's place (⌘G), as Jira's; one host at a time, the first that works unless picked. The inbox is three searches (review requested of me by name, or of my teams too when picked [AF fix: only me by default, remembered in `app.json`], mine, assigned issues), 50 each; "my folders' repositories" is `repo:` qualifiers (six at most, then filtered in the daemon). Details replace the list.
- [AF] A pasted token beats gh's login for its host until removed; gh's login can't be removed from Nushi (`gh auth logout`).
- [cards] The inbox's three searches are cards as Jira's statuses: their order and which are collapsed are one choice for every host (`app.json`). A row's repository is on a line under its title (both layouts in `docs/history/github-rows/`); Start work shows on hover and on the selected row, and in the right-click menu. Review required (only asked for) shows nothing; comments show only where no thread is unresolved.
- [cards] The filters go into the searches: "Last 90 days" at first (30 days, a year, any time; one choice for every host), counted in UTC days; each card counts what it leaves out with three `first: 0` searches (the query's cost stays 1) and "Show" widens that card until Nushi quits, the span or the host changes. Hidden repositories and owners (`-repo:`, `-user:`; 50 in the search, the rest left out by the daemon, taking places of the 50) and "Only owners…" (`user:`, ten at most) are per host; "My folders' repositories" and "Only owners…" exclude each other. The menu lists the owners and repositories the inbox has and those hidden, so one never seen can't be hidden from it (only from a row). A repository both asked for and hidden is neither (GitHub drops `repo:` given the same `-repo:` and searches everyone's).
- [cache] The inbox GitHub gave last is kept per host and filter (`cache/github/<host>.json`) and shown while GitHub is asked; dropped when a pasted token is added or removed, not when gh's login switches account (the old account's inbox shows until GitHub answers).
- [AF] Polls are quiet and stop below 200 left in their bucket; the user's own asks go until it's spent. The daemon keeps the inbox 20 s, states 30 s.
- [AF] A review's inline comments live in the app while it runs (no pending review on GitHub until sent); a review sent while mine is pending on GitHub joins it.
- [AF] Start work on a pull request needs a clone of its repository (a remote whose URL is it); its branch is checked out tracking it (a taken name gets `-2`, pushed with `git push <remote> HEAD:<branch>`); a fork's head is `pr-<n>-<branch>`, tracking nothing.
- [AF] Fix checks carries five failed checks at most, each with its job log's last 16 KB (a short log whole). Address comments asks which unresolved threads (all picked; with one it goes at once). A chat on a pull request or issue gets no MCP tools for it (Jira's do). Images in GitHub's text are links, never fetched (camo needs its signature).

**Jira** (ADRs 0042, 0043)
- [AE] A view in the chat's place (⌘J), one site at a time (the last picked). Lists and the open issue are polled each minute while it shows, never otherwise; a failed poll keeps what shows. Details replace the list; "All sites" shows my open issues only. The Sprint list is one board's active sprint, picked once per site (two active: the first).
- [cache] Each list's and opened issue's last answer is kept per site (`cache/jira/<site>.json`, 40 answers, dropped with the site or when it's added again) and shown while Jira is asked ("Updated 5m ago · refreshing"; kept on a failure, with the error); only for another list than the one showing, so ⌘R keeps what shows. With nothing kept, rows that are coming after 150 ms. A search asks for the whole list in one page (Jira may cap it at 100 with fields: not tried, no token for the test site); the sprint list searches the sprint found last while asking which is active (`TestTiming` in `internal/jiracloud`).
- [assignees] A row's assignee is initials on a color from the account id (`Tokens.avatars`), never Jira's avatar image: Jira Cloud's `avatarUrls` are on Gravatar with a default on Atlassian's media host, never the site's own, and the daemon fetches only from the site. Mine has no assignee column or filter. The filter ("Everyone ▾": Me, Unassigned, the people the list has, each with its count) is the app's, over the list Jira gave (the 200 asked for; not added to the JQL), kept per site and list in `app.json` (a saved search by its JQL); a person no longer in the list stays in the menu with 0. A list kept from before API 72 has no account ids: Me and a person match by name there.
- [AE] A token's expiry is warned of 14 days ahead only when you gave its date (Jira doesn't say). Images only from the issue's attachments, through the daemon; others show their alt text. Links open in the browser, http(s) only (`webLink`, for all the app's Markdown).
- [AE, follow-up] A chat from an issue gets nothing in the box (its agent learns the issue from its tools' instructions); a picked issue turns the worktree on, on `KEY-summary-slug` (40 characters of summary at most, cut between words) or any branch git takes, the folder named after it with `-` for `/`.
- [follow-up] A key typed alone is looked for on the site used last; a link's site is matched by address, an unknown one not guessed. Words are `text ~` (summary, description, comments), so they don't find a key's prefix. The task list orders statuses by category, then as Jira listed them, not by the workflow (that needs its scheme), until its cards are dragged; their order and which are collapsed are kept per site in `app.json` (`*` for All sites), a status not in the order going last.
- [AE] The agent's Jira tools are one issue's four; a key per chat while the daemon runs (a deleted chat's kept until it stops); side chats share it. Agents' writes go in `jira-writes.json` (the latest 2,000). Transitions' required fields are checked by Nushi first; a field of an unknown type is sent as an option's id.

**Transcripts' copies** (ADR 0047)
- [transcripts] On by default; off, nothing new is written but a rewind still cuts an existing copy and Delete removes it; turning it off asks Keep or Delete. Items are written as they settle (a message once another follows, a tool call once ended, a prompt once answered, a plan at the turn's end), each after the item before it; a crash loses what hadn't settled, which the agent's replay brings back. Records aren't fsynced (as the caches): a power loss may lose the last seconds. A file mostly of superseded records is written anew when read (past 1 MB).
- [transcripts] The merge lines up the copy and the replay by the agent's ids (messages and tool calls keep theirs in Claude's and Codex's replays; omp gives fresh ones), then by text, as their longest common run. Where they agree the copy's items stand (they have what no replay brings: prompts, questions, notices, subagents' steps); an item only the agent has is put in by its id, one without an id is dropped between agreed items (it may be the copy's, told otherwise, such as a command); a tool call the copy has running is the agent's. Before the replay's first agreed item: the copy alone, then "Compacted here" (Claude's replay starting with its summary: `claude.Compacted`), or a divider if the copy has a conversation there the agent lacks; after the last, when both go on, the agent's from there after a divider. Commands (`/…`) and a compaction's call count as the copy's own (Claude replays neither). Only Claude's and the fake agent's replays were tried by hand; Codex, Ante, omp and PiG go through the same merge untried.
- [transcripts] The marks aren't written to the copy; it then matches what the chat shows, so a divider shows on the reopen that finds the difference, not after. Only the last compaction is marked (Claude's replay says nothing of earlier ones; their calls stay). Side chats get no copy; a moved or rewound chat keeps its own (the same chat id). A user message's id in the copy is Nushi's (`item-N`), the agent's in a replay.
- [transcripts] Settings' cleanup goes by when a copy was last written, checked at start and hourly; Clear on a row asks nothing (Clear all, a picked batch and turning off ask once); a copy whose chat is gone lists as "A deleted chat". Clearing a gone chat's copy removes the chat unless its work keeps it.
- [settings] Chat history gets every copy in one answer (no paging: 5,000 list in about 0.15 s, the walk and a stat of each file; the app builds only the rows that show). Its folder, archived and read-only come from the app's chats, not the daemon's list. Sorting by agent or folder isn't offered; the bar counts and clears only the picked rows that show (a filter or search hides the others, still picked); the batch clear asks once. The "clear older than N days" field went: sort by last used and pick a range.

**Chats, turns and subagents**
- [U] A chat not opened since the daemon started counts as asleep; opening reopens it (its transcript comes from the agent). Sleep stops the agent as Archive does (a turn stopped, manual Sleep only; side chats end; a held queue waits); not for side chats. Auto-sleep checks each minute; any event is activity, opening or reading isn't. Waking restores model, effort and fast, but not after a daemon restart.
- [expired] A chat whose session its agent deleted (Claude Code's `cleanupPeriodDays`, 30 by default) is forgotten, not kept as a dead chat (the owner's call, ADR 0015's amendment): only Nushi's record goes (and an empty scratch folder); a worktree with uncommitted changes or commits, or a scratch folder with files, keeps the chat, marked, with Delete…; so does Nushi's copy of its transcript [transcripts], read-only, with Start a new chat here (the New chat dialog on its folder). Certain only: Claude's -32002 on `session/load` plus its readable project folder lacking the transcript, Codex's "no rollout found", PiG's -32002; listing the chats checks Claude's files alone at most hourly. Not covered: another `CLAUDE_CONFIG_DIR` whose project folder for the path exists (the check can't tell the configs apart), Ante and omp (their errors weren't looked at), a message typed into a chat that then goes (lost with it). The app's notice of removed chats lives in the daemon's memory until dismissed; the "30 days" in it is the app's text, not Claude's setting.
- [reopen fix] A failed reopen is retried only when the chat is shown or on Try again (it gives up after 2 minutes); a hidden chat whose agent became ready says "asleep" until shown. A removed worktree gets Move…, like a gone folder.
- [Q, R] Stopping the daemon (and Archive, Delete, Reload, Move) cancels turns, gives each agent 5 s, closes its input, kills it 5 s later; once stopping, no agent starts. Archive keeps queued messages held until you send or the next turn ends. Side chats end when no app has followed the daemon for 2 minutes. A message over about 30 MB is refused; one sent while a chat reopens, rewinds or moves waits in the queue.
- [Q, R] Send now stops only the turn running when it came; if that ends first, the message still goes next. Reload cancels a prompt or question Claude asked on its own. ## Security notes to look at

- **The token** (0600, remade if empty or short) sits beside the socket in a 0700 folder; anything running as you, the agent included, can read it (ADR 0024). Any client with it can: list any absolute folder (`ListFiles`, 20,000 names at most) and read a regular file inside one (`GetFile`, 1 MB at most, no link followed out of the folder), read the memory of any process tree it names (`GetMemory`, sizes only), open a shell as you anywhere (terminals must stay off remote access, [ADR 0022](docs/adr/0022-the-daemon-owns-terminals.md); closing kills what has the terminal as its controlling terminal), and add log lines (`Log`: 2 KB a message, 16 KB a stack, 16 attributes, escaped so one can't pose as another). Mentioned files go to the agent as `file://` links.
- **Agents run as you** (ADRs 0037, 0048): your CLIs from the login shell's `PATH`, with its environment, secrets included, read by the daemon running your shell (`-l -i -c`, its config runs; 5 s, then killed with what it started); the values stay in the daemon's memory and the agents' processes (names only in the log, at DEBUG; the API carries the shell, when, and why it failed); `NUSHI_*`/`NUSHID_*` (a chat's tools key among them) never reach an agent; a chat's folder reaches the agent only as `cwd`. Adapters install with `npm ci` from lockfiles pinning version and sha512 (no install scripts or optional packages; npm under `sandbox-exec` writing only in `agents/`; your registry applies, checked against the hashes) and run as `node <program>` from the data folder (a project's `node_modules` or `.npmrc` can't swap them; the first `node` on `PATH`). Finding agents runs `--version` (and `claude auth status`) with writes and the network denied.
- **Codex**: codex-acp tells Codex to trust every session's cwd, so a folder's `.codex/config.toml` (MCP servers, commands' environment, sandbox, plugins) and rules load without asking; Nushi's card is the only warning (ADR 0029), keyed by a hash of every file shown and checked again on "Start anyway"; links aren't followed; Codex's trust record is only read. Codex snapshots each thread's shell environment, secrets included, into `$CODEX_HOME/shell_snapshots/<thread>.sh` (0644).
- **Ante** (`ante serve --stdio` under `nushid ante-acp`): the bridge reads only `ante catalog` and sessions' `meta.json`, and removes a session's folder only for an id of Ante's form; prompt images go to a private temp folder removed when it ends. **omp** loads a project's extensions, hooks, tools, command modules and LSP servers without asking; the card shows each whole (ADR 0031); its bash asks, its writes don't. **PiG** (ADR 0039) **runs every tool call without asking**; a folder's `.pig` loads only once trusted in PiG, `AGENTS.md`/`CLAUDE.md` regardless; the bridge trashes a session's file only for an id whose header it found. Both bridges read a write's old text from a regular file of at most 1 MB, no links (`internal/toolcall`).
- **Trust** reads `~/.claude.json`, never writes it ("Start anyway" goes to `trusted.json`); trust of the home folder or `/` covers that folder only, and `~/.claude` is never the home folder's own. It fails closed: it lists any string setting named like Claude's credential helpers (`…Helper`, `…AuthRefresh`, `…CredentialExport`), a skill's raw front matter when it has hooks, a `.mcp.json` it can't read.
- **Git** runs as you in a client's folder with `core.fsmonitor` off, `--no-ext-diff`/`--no-textconv`, `core.hooksPath=/dev/null`, signature checks off, `GIT_NO_LAZY_FETCH=1`, `--ignore-submodules=dirty`, and the panel's status without filter drivers (Changes and new worktrees still run them: git-crypt, lfs). Nushi writes into a repository only `.worktrees/` and `info/exclude`, never through a link, and renames a worktree's branch it made (`git branch -m`, the name checked by its rules and `git check-ref-format --branch`, never one on a remote); reads only regular files, 1 MB at most (64 MiB for Claude's settings and `.mcp.json`); refuses bases and commits starting with `-`; forces a worktree removal or `branch -D` only when asked after the app showed what's lost (the daemon checks again). Moving a chat writes a transcript copy (0600) into Claude's projects folder for the fork, removed after, never replacing one.
- **MCP**: Claude's config holds secrets in clear; the daemon masks them before they leave it. It runs `claude mcp add-json/remove/login/logout` (names checked, `--`), so a client can add a server Claude runs as you, as a prompt could. The switch writes only the two MCP lists of the project's `.claude/settings.local.json` (atomically, keeping its mode) and may add it to `.git/info/exclude`. A user or local server's switch runs `claude -p --bare` in the folder with two control requests on stdin (the name as JSON), which writes `~/.claude.json` itself; `--bare` runs none of the folder's hooks, helpers or servers.
- **Skills** (ADR 0051): skills' and plugins' text is its authors' (a plugin's a third party's): shown as plain text (control and bidi characters dropped), never Markdown or links, never sent to an agent. `claude plugin` runs only in Claude's config folder (ids checked, after `--`). Writes are one key each (`skillOverrides`, `disableBundledSkills`, `enabledPlugins`) in your `settings.json` (a link followed) or the project's local settings (links refused), replaced at once. Delete moves a folder to the Trash (`/usr/bin/trash`) only when it sits right in your skills folder or a project's `.claude/skills` that isn't a link (nor its `.claude`) and holds a `SKILL.md`; Open uses `open -t` (as text, whatever the file is). Other agents (ADR 0052): their settings are written only on a switch, one list each (Codex's `[[skills.config]]` path entries in `config.toml`, as text, the decoded result checked to be the original with only that change; PiG's `skills` list in yours or the folder's `.pig/settings.json` (there relative, `-skills/<folder>`, every other byte kept, else refused; a linked `.pig` refused); Ante's `exclude_skills`; omp's `disabledExtensions`, only in a file yaml.v3 writes back unchanged), links in a project refused, yours followed. Link for Claude makes a relative symlink in `.claude/skills` (never through a linked `.claude`, nothing replaced) only to a shared skill some agent lists. A path the app sends (Delete, Link) must be a skill Nushi listed, right in a listed root; a project's linked roots are never listed; a skill folder that is a link is listed as one and Delete moves the link. No agent runs to list skills. A project's skill is trashed, linked and its settings written through an `os.Root` of its repository (step 308), so a folder an agent swaps for a link between Nushi's check and its act can't lead outside; skill folders whose names have control or invisible characters are skipped. Claude's listing still runs `git rev-parse --show-toplevel` in the folder (now for every agent's view, through its shared skills).
- **What agents send**: a panic on it becomes a JSON-RPC error; a malformed form is refused. Their Markdown's local images come only from regular files of 20 MB at most, remote ones after a click; links open http(s) only. Background shells: the daemon reads only a regular `<task id>.output` in a `tasks` folder, no link, its last 64 KB. Finding a chat's session gone (ADR 0015) only reads Claude's project folder for the chat's folder (opens it, `lstat`s `<id>.jsonl`; ids with `/` or a leading `.` refused) and removes only Nushi's own record and an empty scratch folder of the chat's (`os.Remove`, which fails on a folder that has files). Listing sessions started elsewhere (ADR 0035) only reads (Claude's `sessions/*.json` and transcripts' first records, Codex's rollouts and lock files, omp's headers and locks via F_GETLK, Ante's `meta.json` and `lsof` on its `events.jsonl`).
- **The log** (ADR 0038): agents' stderr goes through a redaction pass for known secret shapes; a prompt or a key of another shape echoed there lands in `nushid.log` (0644 when the launcher's `>>` made it, 0600 when the daemon did; the folder is 0700). The client token is masked by value.
- **The helper** (ADR 0036): `start-daemon`, the launch agent's program, is a script sealed as a resource of the app's signature (launchd doesn't pin it to a hash) that only `open`s the helper. Start at login adds an item under Login Items.
- **Transcripts' copies** (ADR 0047): each chat's transcript as shown (prompts, the agent's text, tool calls' output and diffs, images) in `transcripts/<chat id>/` in the data folder (folders 0700, files 0600), readable by anything running as you, as Claude's own transcripts are. Never logged (counts, sizes and chat ids only; `TestNothingPrivateLogged` checks a copy written, merged and cleared), never sent to an agent; clients get it as they get transcripts (a paired phone too). Every path goes through an `os.Root` of the folder, named from a checked chat id or an image's SHA-256; a link planted there leads nowhere. Clearing removes the chat's folder; a crash's temporary files go at the next start. A rewind's fork may name an agent message id that came from the copy.
- **Remote access** (ADRs 0033, 0034; reviewed in milestone V): the Noise key is in `remote-key.json` (0600), readable by any process of yours. A paired phone is a full client (chats, permissions, terminals, MCP, adapters) but not the Mac's calls (SetRemote, StartPairing, ConfirmPairing, RevokeDevice); the remote API has no token check (the handshake authenticated the device). The Mac asks Allow or Deny for any pairing; the six-digit code is all that stops someone who saw the QR code within its 5 minutes. The PAC file is fetched directly and run by CFNetwork in osascript, asked only scheme://host:port/.
- **Jira** (ADRs 0042, 0043): the token is in the login keychain ("Nushi Jira"), readable by the build that stored it and by a later one after your OK (`security find-generic-password -w` gets the prompt too); any program of yours can delete it. It goes over HTTPS through the system proxy as Basic auth, to the site or Atlassian's gateway. An issue's text is rendered as escaped Markdown (fuzzed), people's names as plain text (control and bidi characters dropped; no avatar image fetched), links http/https/mailto, images only its attachments through the daemon. A chat's tools key (in its MCP server's environment and on Claude Code's command line, so in `ps`) grants that issue's four tools while the daemon runs; the agent's writes are its harness's to allow. What lists and issues showed last (issue text included) sits in `cache/jira/<site>.json` in the data folder (0600, its folder 0700), readable by anything running as you; dropped with the site, never logged.
- **GitHub** (ADRs 0045, 0046): a host's token is gh's (go-gh in the daemon, which may run `gh auth token`, the token on its stdout) or a pasted one in the keychain ("Nushi GitHub"); sent only in the `Authorization` header to its own host (never to a job log's link). A host must be github.com, gh's, or given a token before any token is read for it (go-gh gives `GH_ENTERPRISE_TOKEN` for any host). A `GH_TOKEN` in your shell reaches agents as it would a terminal; Nushi adds none. GitHub's text is rendered as GitHub renders it, parsed as a browser does, written back from what its sanitizer keeps; tested against GitHub's renderer and fuzzed. Addresses from GitHub leave the daemon only when http(s) (`webLink` checks again). Names that go into the inbox's searches (repositories, owners, hidden or picked, the folders' remotes') are checked against GitHub's characters first and a bad one refused (`InboxFilter.Check`), so none adds a qualifier of its own. In a message for an agent, GitHub's text sits between random marks, said to be data, outsiders marked. The API's failure line quotes GitHub's error message (it names what failed, never what was sent, so far). The inbox GitHub gave last sits in `cache/github/<host>.json` (0600). Keychain failures are logged with the call, its OSStatus and macOS's words, never the account or the secret; a daemon that can't be asked never prompts (an OK given then would be recorded for another program).
- **The phone's web app** (ADR 0054; reviewed by subagents in step 325): the device's X25519 key sits raw in IndexedDB with the pairing: script on the app's origin can take it and act as a paired device (code execution as you on the Mac) until revoked. Limits: the relay's CSP (`default-src 'none'`; scripts, images, fonts and connections only its own; `wasm-unsafe-eval` for CanvasKit; `unsafe-inline` styles, which the engine needs; Trusted Types required, Safari 26+), no third-party code, an origin used for nothing else (another service mounted on the same host would share IndexedDB), Revoke on the Mac. Whoever serves the app (the relay's operator, whoever takes the Pi, anyone with a certificate for its name) can serve code that takes the key: use it only from a relay you run; with `-web` the relay is trusted for code, not only a pipe. `-origin` is https except on this machine. The pairing link's secret is in the fragment, taken out of the address once read; it travels through the QR code (which iOS's Camera opens as a link in Safari: the fragment stays on the phone), the clipboard (Universal Clipboard: your other Apple devices) or AirDrop, single-use for 5 minutes, and the six-digit code still stands. Scan: the camera only from a tap, its frames read in the page or `qr_worker.js` (jsQR 1.4.0, vendored unchanged from the npm registry's tarball, sha512 checked; pure computation) and dropped, the stream stopped when the screen goes; the relay's Permissions-Policy allows the camera for its own origin only. **Cloudflare** (the owner's relay since 2026-10-27): it terminates TLS for `nushi.aaronfrase.com`, so it (and anyone with the owner's Cloudflare account) can serve altered app code that takes the device key, as the relay's host can; its Rocket Loader rewrote the page's script once (the CSP's Trusted Types refused its loader). Tailscale on the phone would keep TLS on the Pi. Static files have no bandwidth cap of their own (only the per-address connection caps and a write deadline).
- **Web Push** (ADR 0054): the VAPID private key in `vapid.json` (0600), never logged; subscriptions (endpoint and keys) in `devices.json` with their device, never sent to clients (the API says only on or off), removed by Revoke or a 404/410; pushes only to https on 443 at Apple's, Google's, Mozilla's or Microsoft's push services (a plain host name: no IP literal, zone or port), through the Mac's proxy, no redirects followed; a failure is logged without the endpoint, the push service's answer by status only. A payload is the title, the kind, the agent and the chat's id: nothing of the chat's. Only a device's own channel sets its subscription or view; only the Mac sends a test.
- **govulncheck** reports GO-2026-5932 with no fix (`golang.org/x/crypto/openpgp`, unmaintained): module-level only, since Nushi never imports `openpgp` (it needs x/crypto for autocert and Noise); `make lint` passes, and it stays until x/crypto drops the package.

## Working notes

- **ACP with acp-go**: to change the library and Nushi at once, `go work init . ../acp-go` (`go.work` is ignored; `make lint` builds golangci-lint into `bin/` because `go tool -modfile` refuses a workspace); before committing a version change, `GOWORK=off make check` against the tag in `go.mod`. A library fix is its own release there, then `go get github.com/afrase/acp-go@vX.Y.Z` here.
- **The fake agent in the app**: build `internal/acptest/fakeagent`, put a `node` that execs it and a `claude` (any script) first on `PATH`, fake Claude's setup (`<data>/agents/claude/node_modules/@agentclientprotocol/claude-agent-acp/package.json` = `{"version": "0.94.0", "bin": {"claude-agent-acp": "dist/index.js"}}`, as `app/test/remote_e2e_test.dart` does), and start a daemon with that `PATH` and a short `NUSHI_DATA`. Prompt words: `permission`, `question`, `think`, `pwd`, `many`, `plan`, `tool`, `run`, `stderr`, `garbage`, `wait` (until stopped); `FAKEAGENT_LOAD_DELAY` slows `session/load`.
- **Codex, Ante and omp by hand**: a dev daemon with `CODEX_HOME` (holding `docs/user/codex-config.md`'s config) or `ANTE_HOME` at a temp folder, `HOME` at one for omp (`~/.omp`), and `FIREWORKS_API_KEY` read from `fish -l -c` (real `HOME`) inside the launching script, never on a command line or in a file. Quit the dev app before stopping the dev daemon (an app that finds none starts its bundled one with the real `HOME`).
- **TUIs by hand**: a pty driver (Python's `pty`) answering the terminal's queries (cursor, device attributes, colours) and typing what's written to a FIFO runs Codex's and Ante's (`codex resume` too); a FIFO write blocks once the driver is gone. Set Codex's `check_for_update_on_startup = false` first (its prompt takes Enter and updates the global Codex). Claude's TUI stops at its trust prompt, and answering writes `~/.claude.json`: use `claude -p` (`--resume`). Headless: `codex exec`, `ante -p --permission-mode strict --session-save`, `omp -p`.
- **Terminals**: the shell is the login shell from `id -P`, never the daemon's `$SHELL`. fish 4 asks Primary Device Attributes at start and waits 10 s; the app answers queries in a replay only for a terminal it opened.
- **The window by hand** (only when the owner isn't at the screen): System Events' `click at` doesn't reach Flutter; Swift posting `CGEvent`s does (key codes, flags on every event, a pause after the focusing click). Screenshots are 2× points, current only while the window is in front. A phone by hand: decode the QR code from a screenshot (Vision's `VNDetectBarcodesRequest`) and pair from a Dart script on `packages/remote_transport`; a raw Connect call is a POST of `{}` (`content-type: application/json`) on its `makeRequest`.
- **The Dock and launchd**: `osascript -e 'tell application "System Events" to get name of every UI element of list 1 of application process "Dock"'` lists Dock items; `lsappinfo list` says why a quit app keeps one; `launchctl print gui/$(id -u)/com.nushihq.Nushi.daemon` shows the login item; `/usr/bin/log` (not fish's `log`) shows launchd's reasons.
- **The icon** ("the still lake"): `make icons` writes `app/macos/Runner/AppIcon.icon` (Icon Composer, Liquid Glass on macOS 26+), PNGs for older macOS and `docs/brand/`; `app/lib/logo.dart` draws the mark. `NSWorkspace.shared.icon(forFile:)` shows what macOS made of it; a deleted working folder fails actool until `pkill ibtoold`.
- **Slow diffs**: git runs with `GIT_OPTIONAL_LOCKS=0`, so a stale index stays stale (`git diff` ~0.16 s instead of ~0.02 s until a `git status`).
