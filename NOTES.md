## Nushi's parts

Nushi is for one user (the owner) for now. The app authenticates to the daemon with a client token (API version 95). The packaged app carries the daemon in a background-only helper app and starts it when none runs; Start at login is a launch agent.

Five agents, each run as the owner's own CLI with its own login, settings and history: **Claude** (`claude` through claude-agent-acp 0.94.0, which Settings › Agents › Set up installs into the data folder with `npm ci` from a pinned lockfile; or, with Settings › Agents' "Use Nushi's Go agent" on, through Nushi's own Go agent, `nushid claude-acp`, ADR 0066), **Codex** (`codex` through codex-acp 2.2.2, the same way), **Ante** and **PiG** (through bridges of Nushi's own inside `nushid`, `nushid ante-acp` and `nushid pig-acp`) and **oh-my-pi** (`omp --mode acp` under Bun). Chats belong to the agent: its history is the source of truth, and a chat resumes in a terminal (and a terminal's session opens in Nushi); Nushi keeps a read-only copy of each transcript as shown, for what the agent no longer replays (ADR 0047). The harness owns permissions: the agent's own mode is the only control, its prompts and questions (Claude's AskUserQuestion) are answerable cards, and Nushi never answers them. Nushi is unopinionated: options and warnings, few enforced flows.

A chat has a transcript (your messages as chapter bands, tool rows, subagents, background tasks, plans), a composer with a queue (into the running turn, or next) and Stop and send, side chats, rewind, a chat in its own worktree, a Changes view (a diff viewer with review comments sent to the agent), a preview of a file the agent wrote (Markdown, images, HTML and SVG in a web view, PDF, CSV as a table, Mermaid diagrams (also drawn in messages), code as highlighted source; from its tool row, the details panel's Artifacts widget (the palette's Artifacts…), the pane's name or ⌘P's Open file, or by the agent's own `show` tool on Claude and Codex (ADR 0068), beside the chat where subagents open, live as the agent rewrites it; full screen on the phone, with Artifacts in the chat's bar), terminals the daemon owns, the Context widget, and sleep (an idle chat's agent stops; the next message wakes it). Before an agent starts in a folder that brings code of its own (hooks, MCP servers, extensions), a trust card shows it. Settings is a view in the chat's place (⌘,), a nav of sections, Chat history's table of transcripts' copies among them. Its MCP servers section edits Claude's MCP config through `claude mcp` and turns servers off per project, and Ante's (yours only) in its settings under its lock; its Skills section lists each agent's skills (the shared `.agents/skills` with the agents that load each) and Claude's plugins, and turns them on and off the agent's own way. Jira (⌘J) and GitHub (⌘G) are views in the chat's place: lists, details, writes you ask for, and Start work into a worktree. Remote access connects the daemon to a relay for a phone over Noise; the phone is the Flutter app on the web, added to the Home Screen and served by the owner's relay, with Web Push from the daemon (ADR 0054). `nushid.log` is meant to be debugged from (ADR 0038).

The decisions are in `docs/adr/` (`docs/adr/README.md` is the index); the user docs (`docs/install.md`, `chats.md`, `agent-setup.md`, `mcp-and-skills.md`, `jira.md`, `github.md`, `remote.md`, `development.md`, linked from the README) say how to use each part. The README's screenshots (`docs/images/`) are drawn by `make screenshots` from made-up data (`app/test/screenshots/`).

## Install, releases, logs

- **Install**: `make install` packages a release app (`make package`: the app, the daemon in `Contents/Helpers/Nushi Daemon.app`, signed with the first "Apple Development" identity in the keychain (or `NUSHI_SIGN`; ad hoc when there is none, and then the keychain asks again after every install), checked by `tools/check-bundle.sh`), puts it in `~/Applications`, and copies it to `COPY_TO` from `local.mk` (not committed): the owner's iCloud Downloads, so the work Mac gets it. The running installed daemon keeps the old build until it restarts: restart it only when no chat's agent runs (stop it by its PID, then `open -n -g "$HOME/Applications/Nushi.app/Contents/Helpers/Nushi Daemon.app" --args -login` as the app does, and check `nushid started … api=<n>` in `nushid.log`); otherwise say so: an app of API 77 on asks it to restart itself once nothing runs (ADR 0056).
- **Releases** (ADR 0055): publishing a GitHub release (tag `vX.Y.Z` on `main`) runs `.github/workflows/release.yml` (about 5 minutes): the app (macOS), the relays and the web app (Linux) in parallel jobs, each `tools/release.sh X.Y.Z <part>` (try it here: with no part it writes all three into `dist/`), and the commit checked (a passing CI run on it, else CI's own workflow, called); then the files attached to the release, and the cask (`packaging/homebrew/nushi.rb`) pushed to `afrase/homebrew-tap` with the `HOMEBREW_TAP_TOKEN` secret, for the latest release only. `make package` stamps `NUSHI_VERSION` (else the newest tag's) and the commit count into the app, the helper and the daemon (`api.Release`, Ping's `version`), and builds for macOS 13 (`MACOS_MIN`). Never tag, publish or push to the tap unless the owner asks.
- **Debugging from the logs**: `nushid.log` in the data folder (Settings › Logs; `.1` and `.2` are older, 10 MB each), `app.log` beside it for what the app wrote while the daemon didn't answer; `NUSHI_LOG=debug` or the Settings switch for debug lines. One chat: `grep 'chat=<id>' nushid.log` (side chats name theirs); an agent's processes: `grep 'pid=<pid>'`; a recovered panic's stack: `printf '%b\n' "$(grep panicked nushid.log)"`. What each failure looks like: `docs/history/debugging-from-the-logs.md`.

## Lint exclusions

The whole rule (ADR 0040; AGENTS.md has it in brief). A report wrong for one line: `//nolint:<linter> // <why>` on it, or on the function's line when it covers the function (contextcheck's mark on a function that rightly starts its own context stops the report spreading to callers); nolintlint refuses one without both, or one that silences nothing. Exclude by path in `.golangci.yml`'s `exclusions.rules` only where a whole package or kind of file is what the linter reports on (tests' temp files for gosec, the proto int32s), with a comment why; `disable` a linter only when it doesn't fit the code at all, the reason on its line. No comment needed for `_ = json.Unmarshal(…)` on an agent's payload (best effort; what's missing stays zero) or `defer f.Close() //nolint:errcheck // read-only`. Dart: `// ignore: <rule>` below a comment saying why, `// ignore_for_file:` when the whole file is about it; a rule that doesn't fit goes `false` in `analysis_options.yaml` with the reason. govulncheck: a standard-library finding is fixed by the `go` line's patch version (`go.mod` and `tools/lint/go.mod`), a module's by `go get` of the fix; one with no fix goes under Security notes with its id.

**Transcripts' copies** (ADR 0047)
- [transcripts] On by default; off, nothing new is written but a rewind still cuts an existing copy and Delete removes it; turning it off asks Keep or Delete. Items are written as they settle (a message once another follows, a tool call once ended, a prompt once answered, a plan at the turn's end), each after the item before it; a crash loses what hadn't settled, which the agent's replay brings back. Records aren't fsynced (as the caches): a power loss may lose the last seconds. A file mostly of superseded records is written anew when read (past 1 MB).
- [transcripts] The merge lines up the copy and the replay by the agent's ids (messages and tool calls keep theirs in Claude's and Codex's replays; omp gives fresh ones), then by text, as their longest common run. Where they agree the copy's items stand (they have what no replay brings: prompts, questions, notices, subagents' steps); an item only the agent has is put in by its id, one without an id is dropped between agreed items (it may be the copy's, told otherwise, such as a command); a tool call the copy has running is the agent's. Before the replay's first agreed item: the copy alone, then "Compacted here" (Claude's replay starting with its summary: `claude.Compacted`), or a divider if the copy has a conversation there the agent lacks; after the last, when both go on, the agent's from there after a divider. Commands (`/…`) and a compaction's call count as the copy's own (Claude replays neither). Only Claude's and the fake agent's replays were tried by hand; Codex, Ante, omp and PiG go through the same merge untried.
- [transcripts] The marks aren't written to the copy; it then matches what the chat shows, so a divider shows on the reopen that finds the difference, not after. Only the last compaction is marked (Claude's replay says nothing of earlier ones; their calls stay). Side chats get no copy; a moved or rewound chat keeps its own (the same chat id). A user message's id in the copy is Nushi's (`item-N`), the agent's in a replay.
- [transcripts] Settings' cleanup goes by when a copy was last written, checked at start and hourly; Clear on a row asks nothing (Clear all, a picked batch and turning off ask once); a copy whose chat is gone lists as "A deleted chat". Clearing a gone chat's copy removes the chat unless its work keeps it.
- [settings] Chat history gets every copy in one answer (no paging: 5,000 list in about 0.15 s, the walk and a stat of each file; the app builds only the rows that show). Its folder, archived and read-only come from the app's chats, not the daemon's list. Sorting by agent or folder isn't offered; the bar counts and clears only the picked rows that show (a filter or search hides the others, still picked); the batch clear asks once. The "clear older than N days" field went: sort by last used and pick a range.

**Chats, turns and subagents**
- [U] A chat not opened since the daemon started counts as asleep; opening reopens it (its transcript comes from the agent). Sleep stops the agent as Archive does (a turn stopped, manual Sleep only; side chats end; a held queue waits); not for side chats. Auto-sleep checks each minute; any event is activity, opening or reading isn't. Waking restores model, effort and fast, but not after a daemon restart.
- [expired] A chat whose session its agent deleted (Claude Code's `cleanupPeriodDays`, 30 by default) is forgotten, not kept as a dead chat (the owner's call, ADR 0015's amendment): only Nushi's record goes (and an empty scratch folder); a worktree with uncommitted changes or commits, or a scratch folder with files, keeps the chat, marked, with Delete…; so does Nushi's copy of its transcript [transcripts], read-only, with Start a new chat here (the New chat dialog on its folder). Certain only: Claude's -32002 on `session/load` plus its readable project folder lacking the transcript, Codex's "no rollout found", PiG's -32002; listing the chats checks Claude's files alone at most hourly. Not covered: another `CLAUDE_CONFIG_DIR` whose project folder for the path exists (the check can't tell the configs apart), Ante and omp (their errors weren't looked at), a message typed into a chat that then goes (lost with it). The app's notice of removed chats lives in the daemon's memory until dismissed; the "30 days" in it is the app's text, not Claude's setting.
- [reopen fix] A failed reopen is retried only when the chat is shown or on Try again (it gives up after 2 minutes); a hidden chat whose agent became ready says "asleep" until shown. A removed worktree gets Move…, like a gone folder.
- [Q, R] Stopping the daemon (and Archive, Delete, Reload, Move) cancels turns, gives each agent 5 s, closes its input, kills it 5 s later; once stopping, no agent starts. Archive keeps queued messages held until you send or the next turn ends. Side chats end when no app has followed the daemon for 2 minutes. A message over about 30 MB is refused; one sent while a chat reopens, rewinds or moves waits in the queue.
- [Q, R] Send now stops only the turn running when it came; if that ends first, the message still goes next. Reload cancels a prompt or question Claude asked on its own. A message taken back keeps its mentions (and its subagent, as a chip; a replayed one can't). A message answered without words can't be rewound past. Stop (and a card) also ends a turn Claude started itself; Rewind waits for it; Move is refused meanwhile.
- [branch names] A plain worktree chat's branch is named after the chat once, between turns, when it has a title (ADR 0016's amendment): for Claude (`Dialect.NamesSessions`) its own title, which comes from a model call of its own and can follow a short first turn's end (then the rename happens when it comes, if no turn runs), waited for one turn at most (the waiting is in memory: a daemon restart may cost a turn); for the others the title at the first turn's end (Codex's is the first prompt). Never a later, better title. Older chats keep their two words (`Worktree.AutoName`). A refusal (pushed, upstream, the worktree off the branch, another worktree or chat on it) is for good; a git failure tries again after the next turn. Renamed with the chat locked, before the next queued message starts. The agent is told with the next prompt (ADR 0016's second amendment), a rename before the first prompt too, since Claude's system prompt has the branch from the session's start; an agent without that snapshot is told of a name it never saw. Rename branch… refuses a branch on a remote rather than renaming it locally with a warning.
- [unseen] A turn's end nobody saw (finished, or failed with an error; not stopped by the user, nor ended by sleep, archive or the agent quitting) marks the chat unseen (`ChatRecord.Done`, stored as `Unseen`, sent as `Chat.done`): a solid green dot, and "done" (then "idle" once seen), on the Mac and the phone. A chat's state in a word is `ChatState.phase`, worked out once and read by the dot, the header, the phone's row and the status bar: archived, needs you, working, in background (a turn ended while subagents or background commands it started run: `ChatStatus.background`, API 84; a slowly pulsing ring, not "idle", which reads as done), expired, couldn't start, done, asleep, new, idle, in that precedence (`phaseWord` says each the same on both). Seen is the daemon's: a client showing the chat (`SetDeviceView`, the phone's as before, the Mac's since API 76 from its socket: the selected chat while the window is focused or visible and nothing is in the chat's place, said again every 15 s against the 40 s lease) clears it, and a turn ending while one shows never sets it. A slept chat keeps it (the dot shows it over the moon); archiving clears it; rewind, move and fork leave it (whoever does them is looking); a side chat never has it; the end of the agent's own later work (after a background task) doesn't set it. The Mac's view never holds back a phone's push. An older daemon: the old dot (the check, then the ring) and no view told.
- [Q, R] Worktrees: a fresh chat moving out keeps its worktree while another chat or a terminal is in it; ignored files (`.env`, `node_modules`) count as work removing it loses, and Delete asks to force, naming how many, after closing the chat's terminals. A worktree chat can't start in a folder the repository doesn't track. A worktree whose base branch is gone counts from the commit it started from.
- [per chat] A worktree is chosen per chat and never remembered (the owner, 2026-10-27; ADR 0016's third amendment): every plain new chat starts in the folder itself, and the New worktree chip moves that chat only; an old `app.json`'s `worktrees` key is ignored.
- [switch] The Branch row is a menu (ADR 0016's amendment of 2026-10-28): in a repository's own folder it switches the folder's branch (`git switch`, local branches only, 500 listed; a new one from HEAD takes uncommitted changes along); in a worktree it lists the worktrees to move to, never switching inside one. Refused with uncommitted changes to tracked files (untracked files go along, as git takes them; no stash), while any chat in the checkout works (a side chat doesn't count), and asked once when other chats are there. A move into a worktree that was there keeps it as `Found`, never removed by Nushi; every move of a chat with messages tells the agent where it went.
- [bg fix] A Claude turn ends at its result while subagents it started run in the background (ADR 0044, read from `_claude/origin`; a steered message's cut-short result is skipped by counting steers; if either reading fails, the chat stays busy until the adapter answers). A running subagent has a Stop of its own (its row under the pointer, its pane, the Background tasks widget): its session is cancelled (the subagents RFD, ADR 0044's amendment), mid-turn too; a background command's, and a subagent's with no session known, asks Claude to `TaskStop` it, as a message ("Stop …, through Claude") that costs a short turn; Sleep/Reload stop them all and ask first. Move and Rewind are refused while one runs.
- [P] A message to a subagent goes to the main session as a prompt asking Claude to pass it on with SendMessage (`internal/claude/subagents.go`); the transcript shows only the message, but Claude's history (`claude --resume`) holds the wrapped prompt. A subagent with steps after its last report runs again.
- [stop] A subagent's end is what Claude's adapter says of its session (done, stopped, failed; an end it can't explain counts as stopped), live and on reopen, where a stop seen first keeps its word (a subagent stopped with the turn replays as failed); the replay's steps are dropped, the copy has them. `TaskStop`'s result, or its "is not running" error, ends the one it names. A Stop shows only once the adapter says so. Chats left showing a running subagent by an older daemon show it stopped once the daemon restarts (its elapsed time then runs to the restart) and the true end on reopen.
- [O, P, Q] The daemon counts a background subagent only if it saw it start, on its own clock (lost on a daemon restart). Background commands are followed through Claude's output file, polled each second, only when Claude's structured result names the task: "running" while the file has no end line and the agent runs, else "started". What ran on an agent that's gone shows as failed.
- [P, UI fixes] A finished subagent's pane opens at its prompt, a running one follows it; "Inherited" model and effort are the chat's now. Side panes each keep their width (`side`, `pane` or `subagent`, `details`); one that doesn't fit beside the transcript lies over it. The default model is "Default…" by name, "Other" is `<id>_custom` (Claude's).

**Daemon, logs and remote**
- [review A] A client that stops reading its events (a frozen app, a phone on a bad link) is dropped once 10,000 events or about 64 MB (text, diffs, images) wait for it: its stream ends with ResourceExhausted, and it subscribes again at its next ping and reloads what it shows, as after any reconnect (`events.MaxQueued`, `MaxBytes`). - [V] One pairing at a time; closing the QR dialog leaves it open until it expires; a phone that sent no readable name doesn't use it up. After a revoke the daemon waits at its old id for other devices, 30 days at most. A PAC file that fails leaves the static proxy settings for 30 s; the environment's proxy wins; a proxy password in the Keychain isn't read. At most 16 remote connections.

- **Stopping a background command** (ADR 0065): the daemon reads the command lines of the processes below a chat's agent (`kern.procargs2`, the user's own processes only; never logged) and sends SIGTERM, then SIGKILL, to one process group: the one whose leader is below the agent's process, is still the process found (its start time) and runs exactly the call's command, checked again just before the signal; the SIGKILL only while every process in the group started before the SIGTERM. An agent could start a process whose command line mimics another call's command: it then gets that group stopped, as it could stop it itself. The next prompt carries a fixed `[Nushi]` note naming the task's id.
- **Claude's transcripts in Go** (`claudeagent/sessions`, a port of the Python Agent SDK's helpers; `claudeacp` calls it to load, list, fork, delete and title sessions, and to tell a resume claude quit on from a session that is gone): reads Claude's transcripts in its config folder's `projects/`, every name from a session id that must be a UUID (no path in it) or an `agent-<id>.jsonl` found there; to find a session started in another worktree it runs `git -c core.fsmonitor=false worktree list --porcelain` in the session's folder (5 s at most), as the SDK does. `Fork` writes a new transcript (0600, its folder 0700 if new; `O_EXCL`, so never over another) beside the source or in a given folder's project folder; `Delete` removes `<id>.jsonl` and the `<id>/` folder beside it (subagents' transcripts), a link there removed, not followed.
- **Claude's requests in Go** (`claudeagent`'s control protocol; only `claudeacp` calls it): requests for credentials (`oauth_token_refresh`, `host_auth_token_refresh`, `remote_control_work_secret`) are always answered "unsupported", never passed to the caller's callback, and the environment that would invite them is never set. A permission request with no `CanUseTool` gets an error, never an allow; a user dialog gets no answer (none is declared); a request claude withdraws gets none either, whatever its callback returns. A hook callback runs only a function the caller registered in `initialize` (an unknown id gets an error); an MCP elicitation with no `OnElicitation` is declined, and an answer that isn't accept, decline or cancel is an error, never an accept.
- **Claude's ACP agent in Go** (`claudeacp`, ADR 0066; off by default): the daemon runs it only when Settings › Agents' "Use Nushi's Go agent" is on (`claudeGoAgent` in `settings.json`, which any client of the API can turn on, a paired phone included, as it can any setting; read each time a Claude chat's agent starts, so a running chat keeps the agent it started with until it next starts) or when `NUSHI_CLAUDE_ADAPTER=go` is in its own environment (a dev override that forces it whatever the setting says), as itself (`nushid claude-acp`, `os.Executable`), in the data folder, with the chat's environment (the login shell's, ADR 0048) and `CLAUDE_CODE_EXECUTABLE` naming the `claude` found on `PATH`, as for the adapter; its stderr goes to the log through the agents' redaction, claude's included (at INFO, a session's at most 20 lines at once then 2 a second, each cut at 1 KiB, the rest counted). It runs the user's `claude` once per session, in the session's folder (absolute and a folder, else refused), with the agent's environment plus `_meta.claudeCode.options.env`, the client's MCP servers (stdio ones are commands claude runs as you, as with claude-agent-acp) and settings, in the agent's own process group, so the daemon's kill of that group (an agent that overstays `stopGrace`) ends every claude, its stdio MCP servers and its hooks, as with the adapter (SIGTERM closes the sessions as stdin's end does), but not its Bash commands, background ones included: each leads a group of its own (docs/facts/claude.md) and outlives the kill, as under the adapter; it passes `--allow-dangerously-skip-permissions` (not as root without `IS_SANDBOX`) so the client may switch to bypass later, which claude's own settings can still forbid. It changes claude's mode, model and settings (effort, fast mode, main agent) only as the client sets them, an effort with `ultracode: true` when the session's settings turned ultracode on (else claude would turn it off). Every permission claude asks for goes to the client, and the agent never allows anything itself: no answer (withdrawn, the turn cancelled, an option it didn't offer) is a deny that stops the turn, and a request from work a cancel stopped is denied at once; "don't ask again" (claudeacp/always.go, worded per tool as claude-agent-acp words it) sends back the rules claude itself suggested, offered only where its words say no less than they allow (a file rule for any file only for a call in the session's folder, folder rules only when they reach one folder, named), or, as the adapter, a rule of its own kept in the project's local settings: a fetch's domain, a skill (or its prefix), or any use of a tool with no rules of its own (WebSearch, Agent…); none when an ask rule of the user's matched or claude said not to, and never one that would change the session's mode; leaving plan mode (ExitPlanMode) switches claude, for the session, to the mode the user picked from Auto (on a model that has it), Accept edits and Manual. AskUserQuestion's answers go back as the tool's input. An MCP server's form or page goes to the client only if it declares that kind, else it is declined; a page only when it is https, or http on a loopback host (localhost, 127.0.0.0/8, ::1), with a host and no user name in it (else declined and logged with the server's name), and both carry the server's name in `_meta.mcpServer`. It reads no settings or credentials itself. Of claude's transcripts (in `$CLAUDE_CONFIG_DIR`, else `~/.claude`) it reads a session's own, and its subagents', to replay a load to the client; the start and end of the folder's sessions (of every folder's, when the client names none) to list them; and the session's own for its title. It writes only a fork (the session's copy, into the request's folder's history) and deletes only on `session/delete`: that session's transcript and folder, after its claude has exited, wherever claude keeps them. A session id must be a UUID to name a file, so a request can't name a path. For the title, it reads the one claude keeps; when there is none it asks claude once a session to make one (`generate_session_title`, a model call of claude's, kept in the transcript) from the last 1,000 characters of the prompts and answers. It logs no prompt or text.
- **Recording claude for the parity tests** (`make claude-record`, a developer's tool; nothing in the daemon): it runs the `claude` named by `CLAUDE_TEE_REAL` (never one found by itself) under the pinned Node adapter, with none of the caller's environment but `PATH`: a throwaway `HOME`, `CLAUDE_CONFIG_DIR` and `TMPDIR`, a dummy `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL` at `fakeapi` and the CLI's nonessential traffic, telemetry, error reports and updates off, so no login, settings or account of the caller's takes part. `fakeapi` listens on loopback only, refuses a key shaped like a real one (`sk-ant-…`, never logged), and logs each call's path, model and answer, not its content. `claude-tee` writes the environment's names, never values, into a cassette, nor the values of any `env` or `headers` object in claude's arguments or frames (MCP servers' tokens, the settings' env), only their names (0600; the recorder copies the good ones into testdata); what claude and the adapter say is recorded as is, so a scenario's scripts must hold nothing secret. The adapter is set up in a cache folder with `internal/npm` as on Set up; the agent's process group is stopped at the end of each run, so no `claude` outlives it. A failed run's throwaway folder is kept in the temp folder for a look. A scenario's `kill` step stops a process group only below the agent the run started (`proctree`, as Nushi stops a background command), never one found elsewhere. The recordings keep claude's transcripts of the run (`history/`, from the throwaway config folder; never its `memory/`), which hold only what the scripts and the fake API said, and the run's throwaway paths.
- **What agents send**: a panic on it becomes a JSON-RPC error; a malformed form is refused. A line over 256 MB ends the agent (`agentproc.MaxRead`; the bridges likewise end a CLI that sends one), and a request to the API over 32 MB unzipped is refused before it is decoded (`api.MaxRequest`). Their Markdown's local images come only from regular files of 20 MB at most, remote ones after a click (a preview's Markdown: only the chat's files through `WatchChatFile`, remote ones as text); links open http(s) only. Background shells: the daemon reads only a regular `<task id>.output` in a `tasks` folder, no link, its last 64 KB. Finding a chat's session gone (ADR 0015) only reads Claude's project folder for the chat's folder (opens it, `lstat`s `<id>.jsonl`; ids with `/` or a leading `.` refused) and removes only Nushi's own record and an empty scratch folder of the chat's (`os.Remove`, which fails on a folder that has files). Listing sessions started elsewhere (ADR 0035) only reads (Claude's `sessions/*.json` and transcripts' first records, Codex's rollouts and lock files, omp's headers and locks via F_GETLK, Ante's `meta.json` and `lsof` on its `events.jsonl`).
- **The log** (ADR 0038): agents' stderr goes through a redaction pass for known secret shapes (`internal/secrets`, the ones tool calls' input loses) and values named like a secret (`NAME=value`, `"key": "value"`); a private key's lines after its BEGIN line are left out, to its END line (200 at most); a prompt or a key of another shape echoed there lands in `nushid.log` (0644 when the launcher's `>>` made it, 0600 when the daemon did; the folder is 0700). The client token is masked by value.
- **The helper** (ADR 0036): `start-daemon`, the launch agent's program, is a script sealed as a resource of the app's signature (launchd doesn't pin it to a hash) that only `open`s the helper. Start at login adds an item under Login Items.
- **The show tool** (ADR 0068): an agent can now open a file in the preview with no click, so on the Mac a page runs on the harness's ask alone. Nushi adds no allow rule and lists no annotations; Bypass permissions or "don't ask again" means pages open unasked. It takes only what a tool row's Preview could open (`filewatch.Allowed`, `filewatch.Artifact`, `filewatch.Check`: a regular file, links followed but not out of the folder), its path bounded (4096 bytes, no NUL), refused with fixed text because `tools.Service` logs a tool's error, and its answer carries nothing of the file. A show call never counts in `Wrote`. `Wrote` still counts any tool call's locations, reads and refused calls too. The path reaches the app in the `show` event and the row's input; both only ask `WatchChatFile`, which checks again, and the card and row mark control and bidi characters in it.
- **Previews of pages** (the owner: "we can trust what the agent writes and it's the user's responsibility", so no ADR, hardening later): on the Mac an agent's HTML, SVG or PDF runs in a WKWebView with its scripts and the network on, as a page opened in a browser would; only WebKit's free defaults hold: no script message handlers (nothing from the page reaches Nushi), file reads only inside the chat's folder or worktree holding it (else its own folder), and any navigation of the main frame away from the file opened in the default browser instead (http, https and file only, through the app that opens https, so a linked `.command` isn't run by Terminal; mailto by Mail). The daemon's watch still decides which files may show (the folders through `os.Root`, or `Wrote`); the web view then reads from disk itself, so a link inside the folder pointing out is WebKit's to refuse (its sandbox follows the resolved path). On the phone a page is written into a frame of `frame.html`, which the relay serves sandboxed (`sandbox allow-scripts`, as the iframe also is, so an origin of its own: no IndexedDB, no device key, no reach into the app) with a CSP of its own that lets scripts and the network run, framed only by the app (`frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`); the app's CSP gained `frame-src 'self'`. A `srcdoc` or `blob:` frame was tried first: WebKit gives it the app's CSP, so no inline script runs. The page can post messages to the app, which listens for none.
- **Transcripts' copies** (ADR 0047): each chat's transcript as shown (prompts, the agent's text, tool calls' output and diffs, images; since 2026-10-28 tool calls' raw input, an MCP tool's arguments too, and a raw output the content didn't show, 8 KB each at most; the input with what looks secret masked: every value under a key named like a secret (however deep; numbers and bools too, so `max_tokens` shows masked), and known token shapes anywhere, keys included (`internal/secrets`, as the log), as the row shows it; copies written before keep what they had; a tool call's title, the agent's own words and often its command, isn't masked) in `transcripts/<chat id>/` in the data folder (folders 0700, files 0600), readable by anything running as you, as Claude's own transcripts are. Never logged (counts, sizes and chat ids only; `TestNothingPrivateLogged` checks a copy written, merged and cleared), never sent to an agent; clients get it as they get transcripts (a paired phone too). Every path goes through an `os.Root` of the folder, named from a checked chat id or an image's SHA-256; a link planted there leads nowhere. Clearing removes the chat's folder; a crash's temporary files go at the next start. A rewind's fork may name an agent message id that came from the copy.
- **Drafts** (ADR 0062): what you're writing in a chat (text, mentioned files, reply cards with their quotes, images) sits in clear in `drafts.json` and `drafts/` (0600 in the 0700 data folder) until sent, or the chat is deleted or archived; the phone keeps text and cards in IndexedDB beside its key, readable by script on the app's origin.
- **The app's files**: `app.json`, `reviews.json` (review comments with the lines they quote), `context.json`, `drafts.json` and its images, and `pulls/` (pull requests as read) are each written whole through `writeWhole` (`file_mode_ffi.dart`), 0600, their folders 0700 (`privateDir`); the first three were 0644 before, in the 0700 data folder.
- **Remote access** (ADRs 0033, 0034; reviewed in milestone V): the Noise key is in `remote-key.json` (0600), readable by any process of yours. A paired phone is a full client (chats, permissions, terminals, MCP, adapters) but not the Mac's calls (SetRemote, StartPairing, ConfirmPairing, RevokeDevice); the remote API has no token check (the handshake authenticated the device). The Mac asks Allow or Deny for any pairing; the six-digit code is all that stops someone who saw the QR code within its 5 minutes. The PAC file is fetched directly and run by CFNetwork in osascript, asked only scheme://host:port/.
- **Jira** (ADRs 0042, 0043): the token is in the login keychain ("Nushi Jira"), readable by the build that stored it and by a later one after your OK (`security find-generic-password -w` gets the prompt too); any program of yours can delete it. It goes over HTTPS through the system proxy as Basic auth, to the site or Atlassian's gateway. An issue's text is rendered as escaped Markdown (fuzzed), people's names as plain text (control and bidi characters dropped; no avatar image fetched), links http/https/mailto, images only its attachments through the daemon. A chat's tools key (in its MCP server's environment and on Claude Code's command line, so in `ps`) grants that issue's four tools while the daemon runs; the agent's writes are its harness's to allow. What lists and issues showed last (issue text included) sits in `cache/jira/<site>.json` in the data folder (0600, its folder 0700), readable by anything running as you; dropped with the site, never logged.
- **GitHub** (ADRs 0045, 0046): a host's token is gh's (go-gh in the daemon, gh's config read again when a host isn't in it or has no token; else `gh auth token`, the token on its stdout, 10 s at most, in a process group of its own; gh having no token is believed for 30 s) or a pasted one in the keychain ("Nushi GitHub"); sent only in the `Authorization` header to its own host (never to a job log's link). A host must be github.com, gh's, or given a token before any token is read for it (go-gh gives `GH_ENTERPRISE_TOKEN` for any host). A `GH_TOKEN` in your shell reaches agents as it would a terminal; Nushi adds none. GitHub's text is rendered as GitHub renders it, parsed as a browser does, written back from what its sanitizer keeps; tested against GitHub's renderer and fuzzed. Addresses from GitHub leave the daemon only when http(s) (`webLink` checks again). Names that go into the inbox's searches (repositories, owners, hidden or picked, the folders' remotes') are checked against GitHub's characters first and a bad one refused (`InboxFilter.Check`), so none adds a qualifier of its own. In a message for an agent, GitHub's text sits between random marks, said to be data, outsiders marked. Send to agent quotes it in a reply card instead: every line of a quote goes to the agent behind `> ` (`withReplies`), so its text can't end the quote, and the card's own words say it's data. The API's failure line quotes GitHub's error message (it names what failed, never what was sent, so far). The inbox GitHub gave last sits in `cache/github/<host>.json` (0600). Keychain failures are logged with the call, its OSStatus and macOS's words, never the account or the secret; a daemon that can't be asked never prompts (an OK given then would be recorded for another program).
- **The phone's web app** (ADR 0054; reviewed by subagents on 2026-10-27): the device's X25519 key sits raw in IndexedDB with the pairing: script on the app's origin can take it and act as a paired device (code execution as you on the Mac) until revoked. Limits: the relay's CSP (`default-src 'none'`; scripts, images, fonts and connections only its own; `wasm-unsafe-eval` for CanvasKit; `unsafe-inline` styles, which the engine needs; Trusted Types required, Safari 26+), no third-party code, an origin used for nothing else (another service mounted on the same host would share IndexedDB), Revoke on the Mac. Whoever serves the app (the relay's operator, whoever takes the Pi, anyone with a certificate for its name) can serve code that takes the key: use it only from a relay you run; with `-web` the relay is trusted for code, not only a pipe. `-origin` is https except on this machine. The pairing link's secret is in the fragment, taken out of the address once read; it travels through the QR code (which iOS's Camera opens as a link in Safari: the fragment stays on the phone), the clipboard (Universal Clipboard: your other Apple devices) or AirDrop, single-use for 5 minutes, and the six-digit code still stands. Scan: the camera only from a tap, its frames read in the page or `qr_worker.js` (jsQR 1.4.0, vendored unchanged from the npm registry's tarball, sha512 checked; pure computation) and dropped, the stream stopped when the screen goes; the relay's Permissions-Policy allows the camera for its own origin only. **Cloudflare** (the owner's relay since 2026-10-27): it terminates TLS for `nushi.aaronfrase.com`, so it (and anyone with the owner's Cloudflare account) can serve altered app code that takes the device key, as the relay's host can; its Rocket Loader rewrote the page's script once (the CSP's Trusted Types refused its loader). Tailscale on the phone would keep TLS on the Pi. Static files have no bandwidth cap of their own (only the per-address connection caps and a write deadline).
- **Web Push** (ADR 0054): the VAPID private key in `vapid.json` (0600), never logged; subscriptions (endpoint and keys) in `devices.json` with their device, never sent to clients (the API says only on or off), removed by Revoke or a 404/410; pushes only to https on 443 at Apple's, Google's, Mozilla's or Microsoft's push services (a plain host name: no IP literal, zone or port), through the Mac's proxy, no redirects followed; a failure is logged without the endpoint, the push service's answer by status only. A payload is the title, the kind, the agent and the chat's id: nothing of the chat's. Only a device's own channel sets its subscription or view; only the Mac sends a test.
- **Pull requests kept**: each pull request a chat's tab or widget read last (its text, comments, threads, checks' summaries) sits in clear in `pulls/` in the app's data folder (0600 in a 0700 folder), readable by anything running as you, as `cache/github/` is; the 50 newest, never logged, named from the host, repository and number when those are only GitHub's characters.
- **Clean-up after a pull request** (ADR 0063): `RemoveChatWorktree` forces (`git worktree remove --force`) only when the request says so, which the app sends only after its dialog named the uncommitted files; it removes ignored files too (said in the dialog); never mid-turn or under another chat that isn't archived. `DeleteChatBranch` runs `branch -D` only with no worktree holding the branch, and with commits its base lacks only when forced (after a merge GitHub reports). `DeleteGitHubBranch` deletes `refs/heads/<head>` on the pull request's head repository only for a merged or closed pull request, only while that ref is at the pull request's head commit, never the default branch; `RestoreGitHubBranch` makes it again at that commit. `RerunGitHubChecks` re-runs the failed jobs of the runs a pull request's failed checks belong to. - **The update check** (ADR 0061): the daemon asks `api.github.com` for the latest release of `afrase/nushi` every 2 hours (GitHub sees the Mac's address, nothing else: no token, no header of the user's), through the system proxy; the tag must parse as a version, and the link the app opens is built from it, not taken from the answer. - **govulncheck** reports GO-2026-5932 with no fix (`golang.org/x/crypto/openpgp`, unmaintained): module-level only, since Nushi never imports `openpgp` (it needs x/crypto for autocert and Noise); `make lint` passes, and it stays until x/crypto drops the package.
