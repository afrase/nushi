**GitHub** (ADRs 0045, 0046)
- [AF] A view in the chat's place (⌘G), as Jira's; one host at a time, the first that works unless picked. The inbox is three searches (review requested of me by name, or of my teams too when picked [AF fix: only me by default, remembered in `app.json`], mine, assigned issues), 50 each; "my folders' repositories" is `repo:` qualifiers (six at most, then filtered in the daemon). Details replace the list.
- [AF] A pasted token beats gh's login for its host until removed; gh's login can't be removed from Nushi (`gh auth logout`).
- [PR redesign, 2026-10-29] To do is what GitHub itself structures: failing checks, each reviewer whose latest review requests changes (one item, the whole review on Send; a reviewer asked again isn't one), review threads not resolved (outdated ones kept, marked). Findings parsed from a review bot's Markdown are opt-in (Settings › GitHub › Findings from review bots, off; the owner: "really cool but it only works for our setup"): the bots' logins (`github-actions`) and the headings that start them ("Key findings, Must address"), kept in `app.json`. Only each bot's newest message (review or comment, whichever came last) counts, never merged with earlier ones; one with no findings section means none. Under the nearest heading that matches: one finding per list item or paragraph; a list whose items end in `;` is one sentence (with the paragraph leading into it with a colon); a paragraph after a list is the reviewer's note; a leading `path:line:` or backticked path is the title; "None" is none; a shape not read cleanly (a clause left, a list after the note) gives none, and the message stays in Activity. A message on an older commit than the head still gives its findings, its group saying so ("comment /review"). A bot's comment has no commit, so it's never "older". If bots start posting structured review comments (threads, or a check's annotations), read those instead. Send in the Pull request tab says what went in a toast ("Added to the chat's box: CI / rubocop", "Added 4 to the chat's box; 2 were there already", with Go to chat), and a To do row whose card waits in the box shows "In the box ✓" (Send off) until the card is taken out or sent; that's remembered in memory per pull request and item, by the card's quote and request (a check's log read again can differ, and then the row offers Send). The bar under the tab counts the cards waiting (the Changes view's, over it, says the same). The PR widget's Fix checks and Address put cards in the box shown beside them, with no toast. [2026-10-29] The tab and the widget show the pull request read last at once (`pull_cache.dart`: in memory, and each in `pulls/` in the app's data folder, the daemon's protobuf as it sent it, its file's time when it was read; the 50 newest), with "Updated 2m ago · refreshing" until GitHub answers (then gone; a failed ask keeps it, "Updated 2m ago"); asked again behind it as the polls already do; with none kept, a skeleton of the page. Measured (2026-10-29): an open waited for GetGitHubPull, which always asks GitHub (the daemon keeps no pull request), 0.76–1.14 s for the test repository's small PR (8 reads), before anything but "Loading…" showed; now the kept one reads from disk in 0.7–4 ms (38 KB) and the tab's first frame has it, 150–410 ms from the tap in a debug widget test (a release build's frame is less; not measured, no clicks into the app). The PR widget's reviewer rows show who was asked and who approved or asked for changes; GitHub doesn't say which reviewers branch protection requires, so a code owner asked (`asCodeOwner`) is the nearest thing.
- [cards] The inbox's three searches are cards as Jira's statuses: their order and which are collapsed are one choice for every host (`app.json`). A row's repository is on a line under its title (both layouts in `docs/history/github-rows/`); Start work shows on hover and on the selected row, and in the right-click menu. Review required (only asked for) shows nothing; comments show only where no thread is unresolved.
- [cards] The filters go into the searches: "Last 90 days" at first (30 days, a year, any time; one choice for every host), counted in UTC days; each card counts what it leaves out with three `first: 0` searches (the query's cost stays 1) and "Show" widens that card until Nushi quits, the span or the host changes. Hidden repositories and owners (`-repo:`, `-user:`; 50 in the search, the rest left out by the daemon, taking places of the 50) and "Only owners…" (`user:`, ten at most) are per host; "My folders' repositories" and "Only owners…" exclude each other. The menu lists the owners and repositories the inbox has and those hidden, so one never seen can't be hidden from it (only from a row). A repository both asked for and hidden is neither (GitHub drops `repo:` given the same `-repo:` and searches everyone's).
- [cache] The inbox GitHub gave last is kept per host and filter (`cache/github/<host>.json`) and shown while GitHub is asked; dropped when a pasted token is added or removed, not when gh's login switches account (the old account's inbox shows until GitHub answers).
- [AF] Polls are quiet and stop below 200 left in their bucket; the user's own asks go until it's spent. The daemon keeps the inbox 20 s, states 30 s.
- [AF] A review's inline comments live in the app while it runs (no pending review on GitHub until sent); a review sent while mine is pending on GitHub joins it.
- [AF] Start work on a pull request needs a clone of its repository (a remote whose URL is it); its branch is checked out tracking it (a taken name gets `-2`, pushed with `git push <remote> HEAD:<branch>`); a fork's head is `pr-<n>-<branch>`, tracking nothing.
- [AF] Fix checks carries five failed checks at most, each a reply card with its job log's failing part (`failingPart`, 8 KB) [2026-10-29: cards, as Send to agent; the daemon's `GetGitHubPrompt` text is no longer asked for by the app, kept for older apps]. Images in GitHub's text are links, never fetched (camo needs its signature).

- [S] A chat keeps its agent for good; nothing is stored for the agent a new chat starts with. A chat whose agent the daemon doesn't know can't be opened, renamed or deleted. A failed start shows in the error dialog; no chat is made.
- [W] Every way to start a chat opens one dialog, the newest chat's agent picked (archived count; else the daemon's first). Digits start an agent at once; ⌘N starts with no folder. An agent whose start failed in this run of the app is dimmed with why and not picked, but can still start (the app keeps this, not the daemon). A sidebar row: status, the agent's mark (one color, the row's secondary text), title.

Signed in or not shows for Claude only (`codex login status` says "Not logged in" when a provider key is all it needs; the others have no such command).
- [Z] Update and Remove put the agent's awake chats to sleep (a turn stopped) rather than refusing; a chat woken in between runs the old adapter until it sleeps. The adapters stay pinned at claude-agent-acp 0.94.0 and codex-acp 2.2.2; Update shows once the pins move. npm reads your npm settings (registry, proxy); hashes must still match. Agents are found again each time Settings › Agents or the dialog opens (about 0.4 s). A paired phone can set up and remove adapters. `sandbox-exec` is deprecated but works on macOS 27; finding and setting up rely on it.
- [S] Codex's Delete archives (`session/delete`; no `codex delete`), so side chats and throwaway forks pile up in `archived_sessions`. After a Rewind Codex titles the chat after the next message (Claude keeps its title), and Nushi drops what came after the agent's last text in that turn, which Codex's fork keeps.
- [T] Ante's options are Allow, "Allow for this session" and Deny (not Ante's "always", which writes a rule); a denial sends Ante nothing. An Ante fork needs Ante idle; a rewind forks after the turn holding the agent's last message, as Codex's. Ante's Delete removes its session folder; omp's leaves omp's history (no op for it), and says so. **Transcripts' copies** (ADR 0047)
- [transcripts] On by default; off, nothing new is written but a rewind still cuts an existing copy and Delete removes it; turning it off asks Keep or Delete. Items are written as they settle (a message once another follows, a tool call once ended, a prompt once answered, a plan at the turn's end), each after the item before it; a crash loses what hadn't settled, which the agent's replay brings back. Records aren't fsynced (as the caches): a power loss may lose the last seconds. A file mostly of superseded records is written anew when read (past 1 MB).
- [transcripts] The merge lines up the copy and the replay by the agent's ids (messages and tool calls keep theirs in Claude's and Codex's replays; omp gives fresh ones), then by text, as their longest common run. Where they agree the copy's items stand (they have what no replay brings: prompts, questions, notices, subagents' steps); an item only the agent has is put in by its id, one without an id is dropped between agreed items (it may be the copy's, told otherwise, such as a command); a tool call the copy has running is the agent's. Before the replay's first agreed item: the copy alone, then "Compacted here" (Claude's replay starting with its summary: `claude.Compacted`), or a divider if the copy has a conversation there the agent lacks; after the last, when both go on, the agent's from there after a divider. Commands (`/…`) and a compaction's call count as the copy's own (Claude replays neither). Only Claude's and the fake agent's replays were tried by hand; Codex, Ante, omp and PiG go through the same merge untried.
- [transcripts] The marks aren't written to the copy; it then matches what the chat shows, so a divider shows on the reopen that finds the difference, not after. Only the last compaction is marked (Claude's replay says nothing of earlier ones; their calls stay). Side chats get no copy; a moved or rewound chat keeps its own (the same chat id). A user message's id in the copy is Nushi's (`item-N`), the agent's in a replay.
- [transcripts] Settings' cleanup goes by when a copy was last written, checked at start and hourly; Clear on a row asks nothing (Clear all, a picked batch and turning off ask once); a copy whose chat is gone lists as "A deleted chat". Clearing a gone chat's copy removes the chat unless its work keeps it.
- [settings] Chat history gets every copy in one answer (no paging: 5,000 list in about 0.15 s, the walk and a stat of each file; the app builds only the rows that show). Its folder, archived and read-only come from the app's chats, not the daemon's list. Sorting by agent or folder isn't offered; the bar counts and clears only the picked rows that show (a filter or search hides the others, still picked); the batch clear asks once. The "clear older than N days" field went: sort by last used and pick a range.

**Chats, turns and subagents**
- [U] A chat not opened since the daemon started counts as asleep; opening reopens it (its transcript comes from the agent). Sleep stops the agent as Archive does (a turn stopped, manual Sleep only; side chats end; a held queue waits); not for side chats. Auto-sleep checks each minute; any event is activity, opening or reading isn't. Waking restores model, effort and fast, but not after a daemon restart.
- [expired] A chat whose session its agent deleted (Claude Code's `cleanupPeriodDays`, 30 by default) is forgotten, not kept as a dead chat (the owner's call, ADR 0015's amendment): only Nushi's record goes (and an empty scratch folder); a worktree with uncommitted changes or commits, or a scratch folder with files, keeps the chat, marked, with Delete…; so does Nushi's copy of its transcript [transcripts], read-only, with Start a new chat here (the New chat dialog on its folder). Certain only: Claude's -32002 on `session/load` plus its readable project folder lacking the transcript, Codex's "no rollout found", PiG's -32002; listing the chats checks Claude's files alone at most hourly. Not covered: another `CLAUDE_CONFIG_DIR` whose project folder for the path exists (the check can't tell the configs apart), Ante and omp (their errors weren't looked at), a message typed into a chat that then goes (lost with it). The app's notice of removed chats lives in the daemon's memory until dismissed; the "30 days" in it is the app's text, not Claude's setting.
- [reopen fix] A failed reopen is retried only when the chat is shown or on Try again (it gives up after 2 minutes); a hidden chat whose agent became ready says "asleep" until shown. A removed worktree gets Move…, like a gone folder.
- [Q, R] Stopping the daemon (and Archive, Delete, Reload, Move) cancels turns, gives each agent 5 s, closes its input, kills it 5 s later; once stopping, no agent starts. Archive keeps queued messages held until you send or the next turn ends. Side chats end when no app has followed the daemon for 2 minutes. A message over about 30 MB is refused; one sent while a chat reopens, rewinds or moves waits in the queue.
- [Q, R] Send now stops only the turn running when it came; if that ends first, the message still goes next. Reload cancels a prompt or question Claude asked on its own. A message taken back keeps its mentions (and its subagent, as a chip; a replayed one can't). A message answered without words can't be rewound past. Stop (and a card) also ends a turn Claude started itself; Rewind waits for it; Move is refused meanwhile.
- [branch names] A plain worktree chat's branch is named after the chat once, between turns, when it has a title (ADR 0016's amendment): for Claude (`Dialect.NamesSessions`) its own title, which comes from a model call of its own and can follow a short first turn's end (then the rename happens when it comes, if no turn runs), waited for one turn at most (the waiting is in memory: a daemon restart may cost a turn); for the others the title at the first turn's end (Codex's is the first prompt). Never a later, better title. Older chats keep their two words (`Worktree.AutoName`). A refusal (pushed, upstream, the worktree off the branch, another worktree or chat on it) is for good; a git failure tries again after the next turn. Renamed with the chat locked, before the next queued message starts. The agent is told with the next prompt (ADR 0016's second amendment), a rename before the first prompt too, since Claude's system prompt has the branch from the session's start; an agent without that snapshot is told of a name it never saw. Rename branch… refuses a branch on a remote rather than renaming it locally with a warning.
- [unseen] A turn's end nobody saw (finished, or failed with an error; not stopped by the user, nor ended by sleep, archive or the agent quitting) marks the chat unseen (`ChatRecord.Done`, stored as `Unseen`, sent as `Chat.done`): a solid green dot, and "done" (then "idle" once seen), on the Mac and the phone. A chat's state in a word is `ChatState.phase`, worked out once and read by the dot, the header, the phone's row and the status bar: archived, needs you, working, in background (a turn ended while subagents or background commands it started run: `ChatStatus.background`, API 84; a slowly pulsing ring, not "idle", which reads as done), expired, couldn't start, done, asleep, new, idle, in that precedence (`phaseWord` says each the same on both). Seen is the daemon's: a client showing the chat (`SetDeviceView`, the phone's as before, the Mac's since API 76 from its socket: the selected chat while the window is focused or visible and nothing is in the chat's place, said again every 15 s against the 40 s lease) clears it, and a turn ending while one shows never sets it. A slept chat keeps it (the dot shows it over the moon); archiving clears it; rewind, move and fork leave it (whoever does them is looking); a side chat never has it; the end of the agent's own later work (after a background task) doesn't set it. The Mac's view never holds back a phone's push. An older daemon: the old dot (the check, then the ring) and no view told.
- [Q, R] Worktrees: a fresh chat moving out keeps its worktree while another chat or a terminal is in it; ignored files (`.env`, `node_modules`) count as work removing it loses, and Delete asks to force, naming how many, after closing the chat's terminals. A worktree chat can't start in a folder the repository doesn't track. A worktree whose base branch is gone counts from the commit it started from.
- [per chat] A worktree is chosen per chat and never remembered (the owner, 2026-10-27; ADR 0016's third amendment): every plain new chat starts in the folder itself, and the New worktree chip moves that chat only; an old `app.json`'s `worktrees` key is ignored.
- [switch] The Branch row is a menu (ADR 0016's amendment of 2026-10-28): in a repository's own folder it switches the folder's branch (`git switch`, local branches only, 500 listed; a new one from HEAD takes uncommitted changes along); in a worktree it lists the worktrees to move to, never switching inside one. Refused with uncommitted changes to tracked files (untracked files go along, as git takes them; no stash), while any chat in the checkout works (a side chat doesn't count), and asked once when other chats are there. A move into a worktree that was there keeps it as `Found`, never removed by Nushi; every move of a chat with messages tells the agent where it went.
- [bg fix] A Claude turn ends at its result while subagents it started run in the background (ADR 0044, read from `_claude/origin`; a steered message's cut-short result is skipped by counting steers; if either reading fails, the chat stays busy until the adapter answers). A running subagent has a Stop of its own (its row under the pointer, its pane, the Background tasks widget): its session is cancelled (the subagents RFD, ADR 0044's amendment), mid-turn too; a background command's, and a subagent's with no session known, asks Claude to `TaskStop` it, as a message ("Stop …, through Claude") that costs a short turn; Sleep/Reload stop them all and ask first. Move and Rewind are refused while one runs.
- [P] A message to a subagent goes to the main session as a prompt asking Claude to pass it on with SendMessage (`internal/claude/subagents.go`); the transcript shows only the message, but Claude's history (`claude --resume`) holds the wrapped prompt. A subagent with steps after its last report runs again.
- [stop] A subagent's end is what Claude's adapter says of its session (done, stopped, failed; an end it can't explain counts as stopped), live and on reopen, where a stop seen first keeps its word (a subagent stopped with the turn replays as failed); the replay's steps are dropped, the copy has them. `TaskStop`'s result, or its "is not running" error, ends the one it names. A Stop shows only once the adapter says so. Chats left showing a running subagent by an older daemon show it stopped once the daemon restarts (its elapsed time then runs to the restart) and the true end on reopen.
- [O, P, Q] The daemon counts a background subagent only if it saw it start, on its own clock (lost on a daemon restart). Background commands are followed through Claude's output file, polled each second, only when Claude's structured result names the task: "running" while the file has no end line and the agent runs, else "started". What ran on an agent that's gone shows as failed.
- [P, UI fixes] A finished subagent's pane opens at its prompt, a running one follows it; "Inherited" model and effort are the chat's now. Side panes each keep their width (`side`, `pane` or `subagent`, `details`); one that doesn't fit beside the transcript lies over it. The default model is "Default…" by name, "Other" is `<id>_custom` (Claude's).

**The UI, review and diffs**
- [R] Help text only where the screen can't say it (what a destructive action loses, why something is disabled, warnings, errors); empty states are a few words.
- [R] Review comments go as reply cards (the UX review's "three ways"): the Changes view's Send to agent (n) puts each unsent comment in the chat's box (the quote: its file, lines and code; the reply: the comment) and marks it sent; a card taken out of the box without a message carrying it is unsent again. Unsent comments are counted in the header's Changes tab and over the Chat tab's box (Send to agent, Show). Every group of cards in a message is led by one line saying whose the quoted text is and where it's from (`Reply.from`, after `<!-- from -->`; the coordinator's case: Claude took the owner's own comments for a reviewer's and answered as the PR's author): "My review comments on your changes:"; "Review comments from @octo on PR owner/repo#N (GitHub), my pull request:" (or "@author's pull request"; nothing when the host's user isn't known; mine when gh's login, or the pasted token's user, is its author); "A comment from @x …"; "Failed checks on PR …" (the check's name is in the quote: what GitHub names stays out of the lead, which is one line). The daemon's Fix checks and Address comments text (older apps') starts the same way, its reviewers' logins left in the data. Left of the review's idea: a comment as a card while it's written (one store for both), and GitHub's threads in the same queue. Review comments are the app's (`reviews.json`): they don't follow a chat to another Mac.
- Diffs: a side over 10,000 lines isn't diffed, over 20,000 characters is diffed in an isolate, over 200,000 isn't highlighted (a message's code block over 20,000 characters shows plain: it's highlighted on the UI thread); the daemon skips files over 1 MB a side; Changes stops after 32 MB of text in a view; a nested repository or submodule shows as not shown.
- [findings] Claude's `/code-review` reports through its ReportFindings tool because Nushi sets `CLAUDE_CODE_REPORT_FINDINGS` for every Claude session (host options' `env`); the terminal resuming the chat sees the tool call. Text findings are recognised only as a fenced JSON block, else a bare array starting a line, of objects with `file`, `line` and `summary`. A finding's path is taken as relative to the chat's folder, though Claude's schema says relative to the repository: a chat in a subfolder misses files outside it, and an absolute path in the worktree but outside the chat's folder isn't opened. A finding's line goes to the new side; a file not among the changes shows as both sides of an unchanged diff.
