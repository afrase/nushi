# AGENTS.md

How to work in Nushi's code, for every agent (Claude Code reads it through `CLAUDE.md`). Plans are [GitHub issues](https://github.com/afrase/nushi/issues), decisions to revisit in [`docs/roadmap.md`](docs/roadmap.md), security notes in [`docs/security.md`](docs/security.md), dependencies, releases and working notes in [`docs/development.md`](docs/development.md).

## Architecture

Nushi is an agentic development environment for macOS and Linux: coding agents (Claude, Codex, Ante, Pi, PiG, oh-my-pi, OpenCode) run as chats.

- **The daemon**, `nushid` (Go, `cmd/nushid`; it runs on Linux too, ADR 0101), runs each agent as the user's own CLI over the Agent Client Protocol (`github.com/afrase/acp-go`), keeps chats, worktrees and terminals, and outlives the app.
- **The app** (Flutter, `app/`) is the window. It talks to the daemon over Connect RPC on a Unix socket with a client token; the API is `proto/nushi/v1/nushi.proto`.
- **The phone** is the same Flutter app built for the web (`app/lib/phone_main.dart`, `app/lib/phone/`). It reaches the daemon through **the relay** (`cmd/nushi-relay`, `relay/`), which pairs the two over a Noise channel (`noiseconn/`) and serves the web app; the daemon sends it Web Push.
- **Principles**: Chats belong to the agent: its history is the source of truth, and a chat resumes in a terminal (and a terminal's session opens in Nushi); Nushi keeps a read-only copy of each transcript as shown, for what the agent no longer replays (ADR 0047). The harness owns permissions: the agent's own mode is the only control, its prompts and questions (Claude's AskUserQuestion) are answerable cards, and Nushi never answers them. Nushi is unopinionated: options and warnings, few enforced flows.
- **Layering**: features (`internal/features/<name>`) declare the interfaces they need, in their own package; `cmd/nushid/main.go` builds the concrete packages and wires them in at startup. An agent is a concrete `Harness` type in its own package, behind the small interfaces of `features/chats/harness.go`, which it meets without importing chats (ADR 0077). Packages are named for what they are (`store`, `git`, `githubapi`, `keychain`): no `adapters/`, `lib/`, `ports/` or `utils` folders. Generic code (the relay, Noise, the Dart packages) lives outside `internal/`. The same at the native edge (ADR 0097): in the app, each native capability is an interface declared beside its user, in a file named for it (`speller.dart`, `alerts.dart`, `web_views.dart`…), each platform's implementation in `<capability>_macos.dart` or `<capability>_linux.dart` (ADR 0104), the only files that may hold a platform channel or `dart:ffi` (`webview_flutter_wkwebview` only the Mac's, `dbus` only Linux's), named by no file but the same platform's and `main.dart` (`tools/native-edge` checks); `native.dart`'s `Native` holds one of each, set once in `main.dart` (`linuxNative()` on Linux, `windowsNative()` on Windows, else `macosNative()`), and a test puts a fake in its place. In the daemon, macOS-only code (cgo, darwin's sysctl, the Mac's commands) is in `foo_darwin.go` behind the package's API, Linux's in `foo_linux.go` (no cgo; ADR 0101), what macOS and Linux share (Unix's calls) in `foo_unix.go` (`//go:build unix`) and Windows's in `foo_windows.go` (no cgo; ADR 0124), and a `foo_other.go` for the rest that builds and answers `errors.ErrUnsupported` or a safe empty result (`make lint-linux` lints for Linux without cgo, golangci-lint type-checking and vetting; `make lint-windows` builds, vets and lints for Windows).

## Build, run, check

- **Tools**: Go (the `go` line in `go.mod`) and Flutter on `PATH`; buf, golangci-lint, govulncheck and the Dart protoc plugins come pinned (`make gen-tools`). The daemon builds with cgo on the Mac (Xcode's command-line tools), without it on Linux.
- **`make check`** before every push: the lint, every test (the app's suite once, beside the rest) and `flutter build macos` (`linux` on Linux; build only), all run even after a failure; its output is short, a line per step, then each failure's tests and reasons and its full log's path, and the verdict last, so don't pipe it. `make lint` needs the network (govulncheck), and includes `make lint-linux` (every Go package linted for Linux without cgo: golangci-lint type-checks and vets) and `make lint-windows` (built, vetted and linted for Windows) and `tools/native-edge` (in `make lint-dart`). CI runs the same parts as parallel jobs (`.github/workflows/ci.yml`).
- **A dev daemon beside the installed Nushi**: `NUSHI_DATA=/tmp/nd1 make run` builds `bin/nushid`, starts it on that folder unless one runs there, then `flutter run`s the app; `NUSHI_DATA=/tmp/nd1 make stop`. Keep the path short (the socket's path has a length limit). Without `NUSHI_DATA` both use the owner's real data. On Linux `make run` is the same (`flutter run -d linux`; `make stop` needs psmisc's `fuser`), and `make package-linux` builds the package a release's tarball holds. Driving its API without the app: `docs/development.md`'s Working notes.
- **`make gen`** after editing `proto/`; the generated code is committed and CI checks it is current.
- **`make golden-diff`**: each golden changed against `BASE=<ref>` (default `HEAD`; `TO=<ref>` instead of the working tree): size, changed box and pixel count, identical boxes grouped, outliers listed. `ROWS=0-44` fails on a change outside those rows; a changed size always fails.
- **Others**: `make lines` (hand-written line counts), `make relay`, `make web` (the phone's app), `make icons`, `make adapters` (an adapter's lockfile), `make claude-record` (the Claude parity recordings: `internal/features/chats/testdata/claude-parity/README.md`), `make screenshots` (the README's images, not part of `make check`), `make gallery` (every shared control in every state, a sheet per group, in `app/build/gallery`), `make package-linux` (on Linux). `make install` and releases: [`docs/development.md`](docs/development.md).

## Common changes

- **An API call**: add the rpc and its messages to `proto/nushi/v1/nushi.proto` (additive only, ADR 0004: new fields and calls, never a changed meaning), `make gen`, write the handler in `internal/api/<area>.go` against an interface the feature satisfies, and call it from the `daemon_*.dart` part it belongs to. Bump `api.Version` in `internal/api/api.go` and `apiVersion` in `app/lib/daemon.dart` together (`remote_e2e_test` fails when they differ). A call only the Mac may make goes in `macOnly` in `api.go`. Teach `FakeDaemon` (`app/test/fake_daemon.dart`) its answer when tests need it.
- **A daemon setting**: a field in `Settings` in the proto (`optional`, so SetSettings leaves it when not given), its key in the `settings` struct of `internal/store/settings.go` (`settings.json`), carried through `GetSettings`/`SetSettings`; its row in the matching `app/lib/settings_*.dart` page.
- **An app preference**: a `Pref` in `app/lib/settings.dart` from one of its makers (`_plain`, `_set`, `_list`, `_places`, `_byChat`) or its own read (one that never throws on a wrong type), and a line in the file's opening comment; it saves itself. Every pref goes in `allPrefs` (a test counts them), which only tests read (the wrong-type test goes through it); one kept by chat also goes in `chatPrefs`, so a deleted chat is forgotten there (a test checks the two agree). Tests start each with the prefs as at launch (`resetAppSettings` in `flutter_test_config.dart`).
- **An agent kind**: its package in `internal/<agent>` (CLI, page, a `Harness` type: `Info`, `Start` and the methods of each interface in `features/chats/harness.go` it can meet, and a `Local` around it for what reads its files on the Mac), its trust (`internal/<agent>trust`) and skills (`internal/<agent>skills`), its row in `internal/knownagents` (`Harness`, `Local`, its `agents.Agent`, skills, trust, MCP) and its lines in `capabilities.go` and its test, which main and the e2e tests build from (main runs `Local`, the e2e tests `Harness`); a fake in `internal/acptest`, its mark in `app/lib/agent_mark.dart`, `readyAgents()` in `fake_daemon.dart`, and its behaviour in `docs/facts/<agent>.md`.
- **A view**: a widget file in `app/lib/`, built from `controls.dart` and the theme's tokens (no raw colors, corner radii or ad hoc buttons); if it takes the chat's place, a `Place` (`place.dart`; `Daemon.go` and `back`) and a branch in `main.dart`'s main area, and an `Act` in `app_actions.dart` for its key and menu item. Widget tests, component goldens in both themes, and renders at full size (below).

## Code conventions

- **Go**: plain functions and small interfaces declared by their user; errors wrapped with `%w` and context, returned as `connect.NewError` with a fitting code at the API; `log/slog` with key-value attributes (never a token, a prompt or a user's text); contexts passed down, processes started under one (`procgroup`); files written whole (`atomicfile`).
- **Ports are rewrites**: code taken from another language (claude-agent-acp's JS, the Python SDK, a vendor's CLI) is written as idiomatic Go, not translated line by line: typed structs over `map[string]any` (except truly open JSON such as `_meta`), small types with methods over closure chains, errors as values, `switch` where it reads better than tables of funcs, no getters, option bags or utils packages. Keep the behaviour, not the source's shape.
- **UI**: read [`docs/design.md`](docs/design.md) before any UI work: the tokens, the shared components, the patterns and the owner's rules; update it in the same commit when a UI rule changes. `tools/design-check` (in `make lint-dart`) and `make gallery` hold it.
- **Dart**: `very_good_analysis`; state in `ValueNotifier`s and the `Daemon` `ChangeNotifier`; colors only from `theme/tokens.dart`, corners only from `NushiTheme`'s radius tokens (`tag`, `control`, `card`, `panel`, `pill`, `inner`; ADR 0110, `corners_test.dart` checks), surfaces told apart by fill (`window`, `base` a pane, `raised` a card, `lifted`, `codeBlock` code's sunk surface), a hairline (`line`) only as a divider and never a colored stripe down a side (ADR 0111), controls only from `controls.dart`; one file per view or part.
- **Comments** are plain sentences that say what a thing is and why, not what the next line does; they name the ADR or `docs/facts` page behind a choice (a commit's short sha only when a pointer to the change itself is needed; never a step number). Types, functions and settings carry a doc comment saying so (lint requires them only in `noiseconn` and `relay`, which could be published).
- **Words**: [`docs/glossary.md`](docs/glossary.md) names Nushi's parts and ideas for the UI, the code and the docs (the details panel is made of widgets, a side pane isn't a side chat). A new user-facing term goes there first, and everything uses its word; an old word goes under its Synonyms, and code that still says it under Renames to do.
- **Size tripwires**: about 500 changed lines a commit (tests included, generated code not) and about 400 lines a source file. Crossing one is allowed: say what pushed it in the commit's body, and split a file along its seams when it grows past. `make lines` counts the hand-written lines when you want to look.
- **Lint exclusions** (ADR 0040): a report wrong for one line takes `//nolint:<linter> // <why>` on it (or on the function's line), a Dart one `// ignore: <rule>` under a comment saying why; a path exclusion in `.golangci.yml` or a rule off in `analysis_options.yaml` only with the reason beside it. The whole rule: `docs/development.md`'s Lint exclusions.
- **Docs**: a change people see updates its page of the guide (`docs/wiki/`) in the same commit, in its plain style (one or two sentences of what and why, then tasks as short steps with the app's exact labels, details last); the reference pages (`docs/chats.md` and the rest) as before. An ADR for a decision someone might undo (`docs/adr/`, a page at most, one line in its README), never restated elsewhere; a vendor's behaviour in `docs/facts/`; a security-sensitive change in `docs/security.md`, a new dependency under `docs/development.md`'s Dependencies; a plan as a [GitHub issue](https://github.com/afrase/nushi/issues) with its area and size labels, an open decision in [`docs/roadmap.md`](docs/roadmap.md), nowhere else. A gap is checked against the code before it's written down, the commit that ships a plan's work closes its issue (`Closes #N`), and a decision's entry goes in the same commit as its work.

## Testing

- **Fakes, never the real thing**: Go features are tested against fakes of their interfaces (`internal/features/chats/fake_test.go`; chats' one real-git test is `TestRelatedRefusesAForgedList`, what git lists from a gitdir an agent rewrote), the API end to end against the fake agent (`internal/acptest`, `internal/e2e`), HTTP clients against recorded `testdata/`. The app's tests use `FakeDaemon` (`app/test/fake_daemon.dart`: chats, agents, recorded requests, `answer` for the rest; `fake_shells.dart` adds a chat's terminals); call `loadFonts` in `setUpAll` for goldens.
- **The app's test helpers** are `app/test/harness.dart`'s: `viewport` (the window's size, pixel ratio and brightness, put back after the test), `themed` (a widget on its own in a plain app of the theme), `startPhone` (a paired phone on a fake daemon, started), `closeView` and `endPhone` (the app gone and its timers ended), `pairedRecord` (a paired phone's record), `untilReal` (a poll on the real clock for an isolate's work, never a fixed wait), `narrowing` (the window narrowed as a point at a time would check it: every 8th width, then every width where the widget tree changes, walked again from the start), `render` (a PNG to look at, below), `withRealShadows` (shadows as the app draws them, for a picture that's looked at), `expectTextInside` (no text past the window's edge), `onMac` and `macAndLinux` (a test's platforms), `frames` (a count of frames for what never settles), `cmdKey` (a key with ⌘ held), `clipboardCopies` (what the app copied, in order), `viewItems` (the View menu's items) and `msAgo` (a time before `fixtureNow`, as the daemon sends it); `readSaved()` reads `app.json`. A test passes in any order (CI shuffles each file's): what one leaves that the next could see (a top-level value, a file in the test's data folder) is put back for every test in `flutter_test_config.dart`'s `startAfresh`, not by the test after it, and a tap that misses its widget fails the test. The app's `clock` (`app/lib/clock.dart`) stands at `fixtureNow` in every test: what shows an age or a time reads it, not `DateTime.now()`, and a test's data counts from `fixtureNow`.
- **Go's test helpers** are `internal/testcheck`'s: `NoErr`, `JSON` (a value marshalled, or the test fails), `Write` (0600, folders 0700), `Eventually` (every 10 ms, 5 s at most), `Wait` (`Eventually`, failing the test with what it waited for), `Git` (without the owner's git config), `PutBranch` (a worktree on a branch git can't make), `Fifo` and `Main` (a TestMain with HOME and XDG_CONFIG_HOME temp folders and no global or system git config); a package keeps at most a wrapper of one, on `Wait` (chats' `eventually`, under the chat's lock, and `idle`; e2e's `until`). A chats test makes its service with `newService` (`fake_test.go`), whose work ends with the test; its agent is a `model.HarnessInfo`, a plain ACP agent, or `testHarness`, Claude's, and it opts into a capability by embedding that capability's fake. Tests never run a `Local`, but for `internal/e2e`'s Claude kinds, which read Claude's transcripts (search) and workflows' files with `claudehistory.Local` in the test daemon's own Claude config folder: those readers look at files only, not this machine's processes.
- **Temp data only**: Go tests use `t.TempDir()`; an app test process makes its own data folder (`nushi-test-…` in the temp folder, even with `NUSHI_DATA` set) and deletes it when its tests end.
- **Tests** (`make check` runs them all): `make test-go`, Go with `-race` and `-timeout 3m` (CI adds `GOTESTFLAGS=-shuffle=on`; a failure's log has the seed for `-shuffle=<seed>`), `make test-packages`, each Dart package, `make test-web`, the web app in Chrome (skipped without one), the app (`make test-app SET=macos SHARD=1/3` runs the first of three shards of the files with goldens, `SET=linux` the rest, split by `app/test/timings.tsv`, slowest first; `make test-timings RUN=<id>` rewrites the table from a CI run's app shards; `FLUTTER_TEST_FLAGS=--concurrency 3`; CI adds `--test-randomize-ordering-seed=random`, each file's tests in a random order, and a failure's log has the seed to pass in its place), and the Mac window's placement maths (`make test-window`: swiftc, no window). CI runs `make test-go` on Linux too; how to run it on a Linux machine: `docs/development.md`'s CI.
- **Goldens**: `app/test/goldens`, macOS only (on Linux about a third differ by 1–4%); CI compares them in its macOS shards, which run only the files with goldens (`tools/test-shards`), so a file's other tests run on Linux in CI and on the Mac in `make check`. Commit component goldens (a card, a row, a menu, a dialog, a pane on its own) in both themes; a full-window golden only for the main views `docs/development.md`'s Goldens and renders lists, with the sidebar hidden (the sidebar has its own goldens). `cd app && flutter test --update-goldens test/<file>` rewrites them. Before committing, run `make golden-diff`: every change must be inside the area you meant to change. Open every changed window golden, one in each group of identical changes plus every outlier, and say in the commit or report how many you opened.
- **UI is looked at, full size**: render every view you build or change at real sizes (Mac: ~1700 and ~720 wide; phone: 390×844, 430×932, landscape) with `render` in its test and `make renders TEST=test/<file>_test.dart` (PNGs in `app/build/renders`, never committed), and read the PNGs; assert key positions (a bar's trailing buttons at its edge, nothing clipped). In a `Row`, never a `Flexible` beside a `Spacer` (it takes half the free width): put the flexible part in an `Expanded` row of its own (`github_wide_test.dart`).
- **Live tests** run only with their variables set: `NUSHI_GITHUB_LIVE` (the throwaway repository `afrase/nushi-gh-test`), `NUSHI_JIRA_TEST_SITE`/`_EMAIL`/`_TOKEN`, `NUSHI_KEYCHAIN_TEST`.

## Rules

- **Commits**: one change a commit on `main`. The subject is short (72 characters at most) and says what changed; the body says why. No step numbers (retired 2026-10-29), no row in `docs/history/` (a frozen archive) and no line counts.
- **Pushing**: work in your own git worktree and commit by path; `make check`, rebase on `origin/main`, `git push origin HEAD:main`. Never force-push or rewrite pushed history.
- **Commit messages**: a `Co-Authored-By` line is fine; never a `Claude-Session:` trailer or a session URL, in commits, PR titles or PR bodies.
- **The owner's data and credentials**: never touch the real data folder (`~/Library/Application Support/Nushi`) from a test or a dev run; never use the owner's credentials in tests (fakes instead) unless a task's prompt allows it; never print, log or store a token; never erase or set the owner's fish variables (`env -u` keeps one out of a child).
- **No synthetic input**: never send clicks, keystrokes or mouse events to a running app, the installed Nushi or a dev build, idle or not. Test through the daemon's API, widget tests and goldens.
- **Security-sensitive changes** (what reads, writes, runs or sends on the user's behalf) get their entry in [`docs/security.md`](docs/security.md) in the same commit.
- **Stop what you start** (dev daemons, apps, simulators, relays) before you report, and remove its temp folders.
